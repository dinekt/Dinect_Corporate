## 注目技術と実践ベストプラクティス

### 長文脈AIを証拠マニフェストと引用検証で運用する

#### 目的

長い文書、コードベース、動画を一度に入力できても、複数箇所から条件を集める質問では、情報の取り違えや根拠の欠落が起こり得ます。Google Cloudの長文脈ガイドも、単一情報の検索評価と複数情報を同時に探す場合では精度が同じとは限らないと説明しています。入力を増やすこと自体を目的にせず、各資料へ安定したIDとハッシュを付け、回答を主張・出典ID・根拠箇所へ分解して機械検査できるようにすることで、長文脈の利便性と検証可能性を両立します。

#### 対象・前提

複数の公開規約やリリースノートの比較、大規模コードベースの変更調査、長時間の会議・動画から複数条件を抽出する用途に適します。利用するモデルが対象データ量を収められるコンテキスト長を持ち、文書単位またはチャンク単位の出典IDを回答へ返せることが前提です。以下は特定モデルの導入実績ではなく、Python 3.11以降の標準ライブラリで入力マニフェストと回答中の引用を検査する一般化した構成例です。

#### 手順

最初に、文書本文だけでなく、出典ID、タイトル、取得日、SHA-256を含むマニフェストを作ります。次の例では、公開サービスの規約とリリースノートを模した合成文書を使い、実在する企業や契約の事実として扱いません。

```python
import hashlib
import json

documents = [
    {
        "source_id": "terms-v3",
        "title": "公開サービス規約 v3（仮想例）",
        "retrieved": "2026-11-10",
        "text": "標準プランの監査ログ保持期間は30日です。"
    },
    {
        "source_id": "release-2026-11",
        "title": "2026年11月リリースノート（仮想例）",
        "retrieved": "2026-11-10",
        "text": "新プランでは監査ログを90日保持できます。既存プランは30日のままです。"
    }
]

for document in documents:
    document["sha256"] = hashlib.sha256(
        document["text"].encode("utf-8")
    ).hexdigest()

context = json.dumps(documents, ensure_ascii=False, indent=2)
question = "監査ログ保持期間の変更対象と例外を、根拠付きで説明してください。"
prompt = (
    "以下の資料だけを根拠に回答してください。回答はclaim、source_id、"
    "evidenceを持つJSON配列にしてください。\n\n"
    + context
    + "\n\n質問: "
    + question
)

# モデル出力を模した仮想例。実際のAPI呼び出し結果ではありません。
answer = [
    {
        "claim": "新プランの監査ログ保持期間は90日です。",
        "source_id": "release-2026-11",
        "evidence": "新プランでは監査ログを90日保持できます。"
    },
    {
        "claim": "既存プランは30日のままです。",
        "source_id": "release-2026-11",
        "evidence": "既存プランは30日のままです。"
    }
]

sources = {document["source_id"]: document for document in documents}
errors = []
for number, item in enumerate(answer, start=1):
    if set(item) != {"claim", "source_id", "evidence"}:
        errors.append(f"claim {number}: invalid fields")
        continue
    source = sources.get(item["source_id"])
    if source is None:
        errors.append(f"claim {number}: unknown source")
    elif item["evidence"] not in source["text"]:
        errors.append(f"claim {number}: evidence mismatch")

if errors:
    raise SystemExit("FAIL: " + "; ".join(errors))
print(f"PASS: {len(answer)} claims verified across {len(sources)} sources")
```

長文入力は先に配置し、質問と出力条件を末尾へ置きます。これはGoogleとAnthropicの公式ガイドに共通する推奨で、モデルが質問に必要な箇所へ注意を向けやすくするためです。回答生成後は、根拠文字列が元文書に存在することを機械検査し、その後に人または別の評価処理で「根拠が主張を本当に支持するか」を確認します。繰り返し同じ資料へ質問する場合はコンテキストキャッシュを検討できますが、キャッシュキーと保存範囲は利用者の権限境界に合わせます。

#### 確認方法

上記コードはPython 3.11で実行確認済みで、`PASS: 2 claims verified across 2 sources`を得ました。モデルAPIによる長文脈推論、コンテキストキャッシュ、回答の意味的妥当性評価は未実行です。本番では、正答が1文にある質問だけでなく、複数文書を横断する質問、矛盾する版、欠落資料、未知の出典ID、本文にない引用を含む評価セットを用意し、主張単位の正答率、引用一致率、根拠不足時の保留率、待ち時間、入力コストを測定します。

#### 注意点

根拠文字列の存在確認だけでは、引用が主張を論理的に支持することや、重要な例外を網羅したことまでは保証できません。文書の重複、版の混在、古い規約、OCR誤りがあると、長いコンテキストでも誤った根拠を選ぶため、取得日、版、ハッシュを保存し、最新版の選定を別工程で行います。大量入力は初回応答の遅延と費用を増やし、キャッシュは再利用効率を高める一方で、利用者をまたいだ再利用が情報漏えいにつながる可能性があります。個人情報や機密情報を投入する場合は、モデル提供者の保存条件、処理地域、削除方法、キャッシュの分離を確認し、必要最小限の文書だけを対象にします。

**出典**: [Google Cloud — Long context](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/long-context) / [Anthropic — Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) / [Anthropic — Citations](https://platform.claude.com/docs/en/build-with-claude/citations)

## まとめ

- 長文脈へ資料をまとめて入れる前に、出典ID、取得日、版、ハッシュを持つマニフェストを作成します。
- 回答を主張・出典ID・根拠箇所へ分解し、引用一致を機械検査した後で意味的な支持関係を確認します。
- 同じ資料を反復利用する場合だけキャッシュを検討し、利用者の権限境界と同じ単位で分離します。
