### 1. ChatGPT Health が Epic EHR と連携 — 3億2,500万人の患者記録をAIで横断参照

OpenAI が **ChatGPT Health** と電子医療記録（EHR）大手 **Epic** の統合を正式に開放した。3億2,500万人超の患者データを管理する Epic のカルテと接続し、臨床医が予約メモ・検査結果・処方薬・専門医文書をChatGPTへ取り込んで質問できるようになる。接続は **読み取り専用** で、BAA（Business Associate Agreement）を締結した組織に対して HIPAA 準拠のアクセスが提供される。加えてバイオメディカル研究データベース・臨床試験情報・メディケアデータなど9つの公的医療データソースも追加された。医師27の臨床ユースケース（受診前レビュー・薬剤レビュー・引き継ぎサマリー等）で実施した評価では4,363件中99.1%が「安全」と評価されており、医療AIの商用展開における安全性の基準点となる可能性がある。大規模 EHR との接続は「院内 AI」の実装コストを大幅に下げ、中規模医療機関のAI活用にも道を開く転換点とみる向きが多い。

### 2. McKinsey「State of AI 2026」— 大企業の40%がエージェントAIをスケール展開、32%がSaaSを自社構築に切り替え

McKinsey が発表した **「State of AI in 2026」** 調査が、エンタープライズAI普及の実態を明確に示している。大企業における1つ以上の業務でのエージェントスケール展開は2025年の27%から **40%** に増加。さらに注目されるのは、32%の組織が「アジェンティックコーディングツールで内部構築できるため、少なくとも1つのソフトウェア製品または機能を購入しなかった」と回答した点だ。これは既存 SaaS ベンダーにとって構造的な脅威を意味し、エンタープライズソフトウェア市場全体の再編を示唆する。AWS も同日、エージェントワークフローのライフサイクル管理・ヒューマンインザループ・creator-processor パターンを組み込んだ **Quick Automate** のネイティブケース管理機能を発表しており、AIエージェント基盤を巡るクラウド各社の競争がさらに加速している。

### 3. 韓国、ソブリンAIに9,190億ドル投資計画 — 2035年までに18.4GWのデータセンター容量を目指す

韓国政府が発表したソブリンAIプログラムが、国家規模の産業戦略として世界的注目を集めている。2029年までに **8.4GW**、2035年までに **18.4GW** のデータセンター容量を確保し、総投資額は **9,190億ドル**（約135兆円）に達する計画だ。自国AI基盤を持つことで、米中間のAI技術デカップリングの影響を受けにくくする狙いがある。「AIジオポリティクス」の観点では、EUが AI Act の段階的緩和を模索する一方、米国は任意基準（voluntary standards）を維持、APACでは日本・オーストラリア・韓国が明示的にイノベーション優先の規制スタンスをとっている。技術覇権が経済安全保障と直結する時代に、インフラとしてのAIへの国家投資競争は今後も激化する見通しだ。

## 新技術・新リリース

### JDK 27 — ポスト量子TLS・G1デフォルト化・構造化並行処理がセットで9月15日リリースへ

Java の次期メジャーリリース **JDK 27** が9月15日のGA（一般提供）を目指して最終段階に入った。今回の目玉は大きく3つある。

1. **ポスト量子ハイブリッド鍵交換**：TLS 1.3 に量子コンピュータ耐性のハイブリッド鍵交換（ML-KEM + ECDH）を追加。「量子脅威」を見越した長期的なセキュリティ強化。
2. **G1 GC のデフォルト化**：SerialGC に代わり G1（Garbage-First）がすべての環境でデフォルトGCになる。スループットとレイテンシのバランスが改善。
3. **構造化並行処理（Structured Concurrency）の正式プレビュー継続**：スレッド管理の安全性と可読性を向上させる API が着実に成熟。

また Go 言語では **Go 1.27.1** パッチリリース（9月1日）が cgo・コンパイラ・ランタイムの修正を含む形で提供されている。

```java
// JDK 27: 構造化並行処理 (Structured Concurrency) — preview
import java.util.concurrent.StructuredTaskScope;

void fetchAndProcess() throws Exception {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        var userTask    = scope.fork(() -> fetchUser());
        var orderTask   = scope.fork(() -> fetchOrders());

        scope.join();           // 両タスク完了またはいずれかが失敗するまで待機
        scope.throwIfFailed();  // 例外を伝播

        process(userTask.get(), orderTask.get());
    }
}
// 親スレッドのライフサイクルに子タスクを束ねることで
// スレッドリークやキャンセル漏れを防ぐ構造的アプローチ
```

ポスト量子TLSの採用は「いつか来る量子コンピュータ」への予防的対応であり、長期運用する金融・公共系 Java アプリケーションでは早めの検証が推奨される。


本日特に注目すべきは **CVE-2026-59822（BerriAI LiteLLM 認証バイパス）**だ。LiteLLM は OpenAI・Anthropic・Azure OpenAI などの LLM API を統一インターフェースで扱うプロキシとして、エンタープライズのAIエージェント基盤に広く組み込まれている。認証バイパスが悪用されると、AIゲートウェイを経由したバックエンドモデルへの不正リクエストや API キーの窃取が可能となり、従来のWebアプリ脆弱性と異なる「AIサプライチェーン攻撃」の性格を帯びる。**CVE-2026-82329（JFrog Artifactory）**もCI/CDパイプラインの上流に位置するリポジトリへの侵入口となる点で影響が広く、パッケージの改ざん・悪意あるビルド成果物の挿入リスクがある。**CVE-2026-48710（Starlette HTTP Smuggling）**は FastAPI ベースのマイクロサービスを持つ組織が影響を受ける可能性があり、リバースプロキシ構成の見直しが求められる。CISA の連邦機関向け対応期限は **9月9日** だが、一般組織も同等の優先度での対処が推奨される。
