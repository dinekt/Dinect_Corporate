### 1. Plugin4Shell — AI コーディングエージェント 4 製品を直撃したゼロクリック RCE、2 製品は未修正

セキュリティ企業 AIR Security が「Plugin4Shell」と命名したゼロクリック RCE 脆弱性が、Claude Code・OpenAI Codex・GitHub Copilot・Google Gemini CLI の 4 大 AI コーディングエージェント全てに影響することが明らかになった。AIR は 2026 年 5 月に脆弱性を発見し、翌 6 月に各ベンダーへ報告済みだ。本脆弱性は各エージェントが依存するプラグインマーケットプレイスの SHA ピンニング機構を破ることで、悪意あるプラグインアップデートがユーザーの操作なしに任意コードを実行できる仕組みになっている。Anthropic は Claude Code v2.1.179 で、OpenAI は Codex v0.146.0 で修正済みだが、**GitHub は Copilot を未修正のまま**であり、Google は「Gemini CLI は既に非推奨」として修正を行わず Antigravity への移行を推奨している。エージェントが持つ企業ネットワークへのアクセス権を丸ごと奪えるため、AI 開発を行う組織は対応バージョンへの即時アップデートが求められる。

### 2. TypeSafe AI が "Jev" をリリース — ChatGPT 共同発明者が作った "System One" モデルは LLM の 40〜200 倍速

ChatGPT 共同発明者でもある Diogo Almeida が創業した TypeSafe AI が、テキストを一切生成しない全く新しいクラスの AI モデル「Jev」を 9 月 15 日に早期アクセスで公開した。従来の大規模言語モデル（LLM）が自己回帰的にトークンを生成する「System 2 型」だとすると、Jev は「System 1 型」— 並列サンプラーにより全出力を 1 クエリで確率として返す決定モデルだ。**GPT-5.6 Tera クラスの精度を維持しつつ、レイテンシは 40〜200 倍改善、コストは 40〜400 倍削減**できるとされる。応答形式はテキストではなく「Yes/No の確率」「定義済みオプションの選択」「スコア」など型付きの決定値であり、ソフトウェアロジックへの組み込みに特化している。訓練には独自手法 RLCD（Reinforcement Learning for Calibrated Decisions）を採用しており、ハルシネーションを構造的に排除した設計が注目を集めている。

## 新技術・新リリース

### TypeSafe Jev — System One モデルをソフトウェアに組み込む

Jev は LLM のようにテキストを返さず、型付きの決定値を返す。以下は SDK を用いた基本的な利用パターンだ。

```python
# TypeSafe Jev SDK — System One モデルによる型付き決定
from typesafe import Jev

client = Jev(api_key="...")

# 1. 二値分類: Yes/No を確率で返す
result = client.decide(
    model="jev-1",
    question="Is this email spam?",
    context="Subject: You won $1,000,000! Click here now.",
)
# result.yes_probability => 0.97, result.no_probability => 0.03

# 2. 多クラス分類: 定義済みオプションから選択
result = client.classify(
    model="jev-1",
    question="What is the sentiment of this review?",
    options=["positive", "neutral", "negative"],
    context="The product arrived on time and works perfectly.",
)
# result.choice => "positive", result.confidence => 0.94

# 3. スコアリング: 0〜100 のスコアを返す
result = client.score(
    model="jev-1",
    question="How relevant is this document to the query?",
    scale=(0, 100),
    query="quantum computing breakthroughs 2026",
    document="NIST finalized post-quantum cryptography standards...",
)
# result.score => 82
```

```python
# 従来の LLM との比較 (レイテンシ・コスト)
# GPT-5.6 Terra: ~800ms/query, ~$0.012/1k tokens
# Jev-1:          ~12ms/query,  ~$0.00004/1k tokens (約66倍速、約300倍安)
#
# ユースケース: リアルタイム判定、高頻度フィルタリング、
#              ルールエンジンの LLM 化、ログ異常検知 など
```

従来の LLM がテキスト生成ベースで「推論しながら答える」のに対し、System One モデルは「判断を直接出力する」設計であり、バックエンドの判定ロジックや ML パイプラインへの差し込みに適している。プロダクションでの意思決定層に LLM を使用しているシステムでは、コストと遅延の大幅改善が見込める。

### Plugin4Shell 詳報 — AI エージェントのサプライチェーンが初めて大規模攻撃ベクタに

```text
===== Plugin4Shell 対応チェックリスト: 2026-09-18 =====

【影響製品と対応状況】
  Claude Code    → v2.1.179 で修正済み ✓  即時アップデートを
  OpenAI Codex   → v0.146.0 で修正済み ✓  即時アップデートを
  GitHub Copilot → 未修正 ✗            → プラグイン機能を無効化することを推奨
  Google Gemini CLI → 修正なし (非推奨) → Antigravity への移行を推奨

【脆弱性の仕組み】
  攻撃対象  : プラグインマーケットプレイスの SHA ピンニング機構
  攻撃手法  : 悪意あるプラグインアップデートを正規チャネルで配布
  攻撃条件  : ユーザーのクリック不要 (0-click) — 自動更新で発火
  影響範囲  : エージェントが持つ全アクセス権を攻撃者が取得可能

【推奨アクション】
  1. 修正済みバージョンへの即時アップデート
  2. Copilot ユーザー: プラグインマーケットプレイスを無効化

  4. エージェントのアクセスログを遡って不審な動作を確認
```

Plugin4Shell は AI コーディングエージェント向けエコシステムで初めて確認された大規模サプライチェーン脆弱性だ。Cymulate の分析によれば、SHA ピンニング破壊と組み合わせたプロンプトインジェクションにより、エージェントが信頼するプラグインを介して任意コードを挿入できる。エージェントは開発者の認証情報・コードベース・内部 API へのアクセスを持つことが多く、侵害された場合の被害は従来のツール侵害より広範になりやすい。AIR Security のレポートは「AI エージェントの普及が攻撃対象面を根本的に拡大している」と警告しており、組織はエージェントのパーミッション設計（最小権限の原則）を今すぐ見直すべき段階にある。
