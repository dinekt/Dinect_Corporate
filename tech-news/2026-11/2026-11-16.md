## 注目技術と実践ベストプラクティス

### OCR結果をページ完全性ゲートで検証してからAIへ渡す

#### 目的

PDFやスキャン画像をAIへ直接渡すだけでは、文字認識が途中で打ち切られたページ、欠落した図、ページ順の乱れを回答モデルが補完し、もっともらしい誤答を作る可能性がある。そこで、OCRと意味理解を分離し、ページ数、インデックス、終了理由、空ページを機械検査した後にだけ抽出結果をAIへ渡す。DeepSeekのOCR APIはページ単位の未加工テキストと`finish_reason`を返すため、この境界を実装しやすい。帳票、点検報告書、契約書など、ページ欠落が業務判断へ影響する文書で特に有効である。

#### 対象・前提

対象は、PDF、Word、PowerPointまたは画像から文字を取り出し、その結果を検索、項目抽出、要約へ利用する処理である。2026年11月16日時点のDeepSeek OCR APIは`POST https://api.deepseek.com/v1/tools/ocr`で提供され、1ファイル100MiB、1,000ページ、処理全体180秒、アカウント当たり同時15件が上限で、成功した認識ページ1,000枚当たり0.225米ドルと案内されている。OCR APIのファイルはFiles APIへ保存されず、チャットモデルにも渡されない。図表の理解が必要ならFiles APIの`rich_layout_recognition`を別途選ぶが、図の検出は保証されず、画像トークンとコンテキストを消費するため、文字中心の文書は`text_recognition`を優先する。

#### 手順

一般化した構成例として、全4ページの設備点検報告書を処理する。受領時にファイルのハッシュ、想定ページ数、文書種別をマニフェストへ保存し、OCRへ`purpose=text_recognition`で送る。返却JSONはそのまま回答モデルへ渡さず、次のPython 3.11以降の標準ライブラリだけを使うゲートで検査する。

```python
import json
from pathlib import Path

EXPECTED_PAGES = 4
response = json.loads(Path("ocr_response.json").read_text(encoding="utf-8"))

if "error" in response:
    raise SystemExit(f"ocr_error: {response['error'].get('code', 'unknown')}")

pages = response.get("pages", [])
reasons = [page.get("finish_reason") for page in pages]
indices = [page.get("index") for page in pages]

checks = {
    "declared_page_count": response.get("page_count") == len(pages),
    "expected_page_count": len(pages) == EXPECTED_PAGES,
    "contiguous_indices": indices == list(range(EXPECTED_PAGES)),
    "complete_pages": all(reason == "stop" for reason in reasons),
    "nonempty_pages": all(page.get("text", "").strip() for page in pages),
}

failed = [name for name, passed in checks.items() if not passed]
if failed:
    raise SystemExit("reject: " + ",".join(failed))

validated = {
    "ocr_id": response["id"],
    "pages": [{"page": p["index"] + 1, "text": p["text"]} for p in pages],
}
print(json.dumps(validated, ensure_ascii=False))
```

入力例で4ページ目の`finish_reason`が`length`なら、結果は`reject: complete_pages`となり、その文書は再処理または手動確認へ送る。全ページが`stop`で、ページ番号が0から3まで連続し、本文が空でなければ、検証済みJSONだけを次の項目抽出や要約へ渡す。OCRが返す座標付き特殊トークンは、原文位置を追跡する用途では保持し、表示用の正規化コピーと根拠確認用の未加工結果を分けて保存する。

#### 確認方法

期待される結果は、正常な4ページの合成レスポンスだけが通過し、`length`を含むレスポンス、欠番、空本文、APIエラーがそれぞれ拒否されることである。上記の検証ロジックは、個人情報を含まない合成JSONフィクスチャで実行し、正常系1件と異常系4件の分岐を確認する。DeepSeek OCR APIへの実ファイル送信、認識精度、処理時間、料金はこの調査環境では実測していない。本番導入前には、実際の帳票から機密情報を除いた評価用文書を用意し、文字誤り率だけでなく、必須項目の抽出率、ページ欠落、表の行列対応、手動差し戻し率を文書種別ごとに測る。

#### 注意点

HTTP 200でも本文がエラーオブジェクトになる場合があるため、ステータスコードだけで成功と判定しない。`finish_reason=length`は不完全なページを意味し、空白ページが正当な文書では`nonempty_pages`を一律条件にせず、マニフェスト側で許容ページを指定する。切断しても受信済みファイルの認識は継続し、完了すれば課金されるため、クライアント側の再試行にはリクエストIDやファイルハッシュを使って重複処理を防ぐ。また、OCR文字列は命令ではなく未信頼データとして扱い、後段のプロンプトでは文書内の指示に従わず抽出契約だけを実行するよう境界を設ける。
