### 2. MikroTrick — MikroTik RouterOS の SSH 認証バイパス＋特権昇格ゼロデイが積極悪用、インターネット露出12万台超

MikroTik RouterOS に存在する2件の脆弱性が **"MikroTrick"** と命名され、攻撃者が9月2日頃から連鎖利用して世界中のルーターを乗っ取っていることが確認された。CERT.pl が報告した **CVE-2026-67276**（SSH 認証バイパス、CVSS 9.2）はユーザー名と RSA 公開鍵のモジュラスを知っていれば正規の秘密鍵なしにログインできる検証不備で、**CVE-2026-86060**（SSH 特権昇格）を組み合わせると完全な管理者権限を奪取できる。Shadowserver Foundation が9月5日に行ったスキャンでは、SSH がインターネットに公開された MikroTik 機器が **12万台超**に上ることが判明しており、攻撃者はハイジャック後に "ops" という名のアカウントを作成し長期潜伏を狙っていると報告されている。MikroTik は対応パッチを既に公開しており、Security Affairs は「ルーターに SSH ユーザー名 "-2" が存在する場合はすでに侵害されている可能性が高い」と警告している。ルーターは企業ネットワークの入口に位置するため、侵害後は内部トラフィックの盗聴・再ルーティング・中間者攻撃が容易になる点でリスクが高い。機器担当者は直ちに最新ファームウェアへ更新し、SSH の WAN 側公開を無効化することが強く推奨される。

## 新技術・新リリース

### iOS 27 × Gemini Siri — Apple Intelligence 新 API と Swift での連携パターン

iOS 27 では Siri のバックエンドが Gemini に切り替わり、デバイス上推論（on-device）とクラウド推論の透過的な切り替えが可能になった。Apple は App Intents フレームワークと組み合わせた新しい **Apple Intelligence API** を開発者向けに公開予定で、以下のような実装パターンが期待される。

```swift
// iOS 27 / Swift 7 — Apple Intelligence API (WWDC 2026 Developer Preview)
import AppIntents
import AppleIntelligence  // iOS 27 新フレームワーク

// ---- 1. App Intent で自然言語アクションを定義 ----
struct SummarizeDocumentIntent: AppIntent {
    static let title: LocalizedStringResource = "書類を要約する"

    @Parameter(title: "書類テキスト")
    var documentText: String

    func perform() async throws -> some IntentResult & ReturnsValue<String> {
        // Apple Intelligence がデバイス上推論かクラウドかを自動選択
        let request = AITextRequest(
            prompt: "以下の書類を3点で要約してください:\n\(documentText)",
            model: .auto,            // デバイス優先、不可なら Gemini クラウドへ
            maxOutputTokens: 256
        )

        let response = try await AISession.shared.perform(request)
        return .result(value: response.text)
    }
}

// ---- 2. SwiftUI から Apple Intelligence を直接呼び出す ----
struct DocumentView: View {
    @State private var summary = ""
    let document: String

    var body: some View {
        VStack(alignment: .leading, spacing: 12) {
            Text(document).font(.body)

            Button("要約する") {
                Task {
                    let intent = SummarizeDocumentIntent()
                    intent.documentText = document
                    let result = try? await intent.perform()
                    summary = result?.value ?? ""
                }
            }

            if !summary.isEmpty {
                GroupBox("AI 要約") { Text(summary).font(.caption) }
            }
        }
        .padding()
    }
}

// ---- 3. プライバシー設定の確認（iOS 27 新規）----
// ユーザーがクラウド推論を無効化しているかチェックする
let privacyPolicy = AISession.shared.privacyPolicy
if privacyPolicy.cloudInferenceEnabled {
    print("クラウド（Gemini）推論: 有効")
} else {
    // on-device のみ利用可能 — モデルの能力が制限される
    print("オンデバイス推論のみ: モデルは制限あり")
}

// ---- 4. Structured Output — JSON スキーマ指定 ----
// iOS 27 の AITextRequest は Codable スキーマを受け取り構造化レスポンスを返せる
struct TaskList: Codable {
    let tasks: [String]
    let priority: String
}

let structuredRequest = AIStructuredRequest<TaskList>(
    prompt: "プロジェクト計画書から TODO を抽出してください:\n\(document)",
    schema: TaskList.self
)
let taskList = try await AISession.shared.perform(structuredRequest)
print(taskList.tasks)  // => ["設計書作成", "API テスト", ...]
```

App Intents を経由することで Siri から自然言語でアプリ機能を呼び出せるようになる点は従来と同様だが、iOS 27 では **デバイス上推論とクラウド推論の透過切り替え**、および **Structured Output（Codable スキーマ指定による JSON 応答）** が加わった点が特に注目される。ユーザーが「設定」→「Apple Intelligence」でクラウド推論を無効化した場合、アプリは `privacyPolicy.cloudInferenceEnabled` を確認してオンデバイス専用のフォールバック UX を提供できる。Xcode 18 での正式 API 公開は iPhone Duo・iPhone 18 Pro の出荷と同期して10月下旬が見込まれている。

## セキュリティ

### MikroTrick 緊急対応 & Android 9月アップデート 180件 — ルーターと Android デバイスの即時確認手順

```bash
# === MikroTrick 緊急チェックリスト ===
# CVE-2026-67276 (SSH auth bypass, CVSS 9.2) / CVE-2026-86060 (SSH privilege escalation)
# 攻撃者は侵害後に "ops" または "-2" という SSH ユーザーを作成する

# ---- Step 1: RouterOS バージョン確認 (MikroTik SSH/Winbox から) ----
# /system resource print
# パッチ済みバージョン: RouterOS 7.17.2 以上 (2026-09 パッチ)

# ---- Step 2: 不審な SSH ユーザーの検出 ----
# RouterOS CLI:
/user print
# "ops" や "-2" というユーザーが存在する場合は侵害済みの可能性が高い

# ---- Step 3: WAN 側 SSH の無効化（推奨） ----
# /ip firewall filter add chain=input protocol=tcp dst-port=22 \
#   in-interface=<WAN_INTERFACE> action=drop comment="Block SSH from WAN"

# ---- Step 4: ファームウェア更新 ----
/system package update check-for-updates
/system package update download
# ダウンロード後、再起動してアップデートを適用
/system reboot

# ---- Step 5: ログで侵入痕跡を確認 ----
/log print where topics~"ssh"
# 不審な IP からの認証試行や、"-2"/"ops" ユーザーの作成ログを探す

# ==============================================================
# === Android 9月セキュリティアップデート — 重要 CVE 一覧 ===
# ==============================================================
# 180 件修正、うち Critical RCE が複数 (2026-09-01 / 2026-09-05 パッチレベル)
#
# 特に注意すべき Critical 脆弱性:
# - CVE-2026-28662: Wi-Fi メモリ破損 → ユーザー操作なし・特権不要で RCE
#   影響: Android 14, 15, 16, 16 QPR2, 17
# - CVE-2026-49882 / CVE-2026-49884 / CVE-2026-49919 / CVE-2026-49921:
#   System コンポーネントの Critical RCE（特権・操作なしで悪用可能）
#
# ---- Android パッチレベル確認 (adb) ----
adb shell getprop ro.build.version.security_patch
# 出力例: 2026-09-05 ← 両フェーズのパッチが揃っている
# 2026-09-05 未満の場合は即時アップデートを推奨

# ---- Qualcomm / MediaTek チップセット端末は特に要注意 ----
# 2026-09-05 パッチには Qualcomm / Unisoc / MediaTek コンポーネント修正が含まれる
adb shell getprop ro.board.platform
# Qualcomm (sm8*) / MediaTek (mt*) 端末は 2026-09-05 パッチレベルまで確認すること

# ---- エンタープライズ向け: Intune で Android コンプライアンスポリシー設定 ----
# デバイスコンプライアンスポリシー > Android Enterprise >
#   "最小セキュリティパッチ日" を "2026-09-05" に設定
# 非準拠端末は自動的に条件付きアクセスで遮断される
```

MikroTrick は SSH ポートがインターネットに公開されているだけで認証バイパスが成立するため、露出した12万台超の機器は今この瞬間も攻撃対象になっている。ルーターを乗っ取られた場合、VPN トラフィックを含む全通信の傍受・DNS リダイレクト・内部ネットワークへのピボットが可能となるため影響は甚大だ。まず WAN 側 SSH を閉じ、次にファームウェアを更新し、最後にログで既存侵害痕跡を確認するという順序で対応すること。Android 側はCVE-2026-28662（Wi-Fi 越しのユーザー操作なし RCE）が特に危険度が高く、2026-09-05 パッチレベルへの更新が最優先となる。Google Pixel 端末は OTA が既に配信中で、一般の Android 端末はメーカーのスケジュールに従って数週間以内に展開される見込みだ。
