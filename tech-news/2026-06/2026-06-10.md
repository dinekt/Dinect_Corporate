### Google DeepMind TurboQuant — KV キャッシュ圧縮で LLM 推論メモリを大幅削減（ICLR 2026 発表）

ICLR 2026 で Google DeepMind が発表した **TurboQuant** は、トランスフォーマー推論の最大ボトルネックである **KV キャッシュ**のメモリ使用量を大幅に削減する二段階アルゴリズムだ。① **PolarQuant**（ベクトル回転）でクエリ・キーテンソルの分布を均一化し、② **Quantized Johnson-Lindenstrauss 圧縮**でその後の量子化精度損失を最小化する組み合わせにより、長いコンテキストでの KV キャッシュのメモリオーバーヘッドを劇的に圧縮できる。GPT-5.4 の 100 万トークンコンテキストが注目される中、長文推論をコスト効率よく実現するインフラ技術として vLLM や TensorRT-LLM への統合実装も近い見込みだ。

```python
# TurboQuant — KV キャッシュ圧縮の二段階処理（教育目的サンプル）
import torch

def polar_quant_rotate(keys: torch.Tensor, queries: torch.Tensor):
    """
    PolarQuant: QR 分解で生成した回転行列で KV の分布を均一化し量子化精度を向上
    keys/queries: [batch, heads, seq_len, head_dim]
    """
    random_matrix = torch.randn(keys.shape[-1], keys.shape[-1], device=keys.device)
    rotation, _ = torch.linalg.qr(random_matrix)
    return keys @ rotation, queries @ rotation


def jl_compress(tensor: torch.Tensor, target_dim: int) -> torch.Tensor:
    """
    Quantized Johnson-Lindenstrauss: 距離関係を保ちながら次元削減
    """
    original_dim = tensor.shape[-1]
    scale = (original_dim / target_dim) ** 0.5
    proj = torch.randn(original_dim, target_dim, device=tensor.device) * scale
    return tensor @ proj


class TurboQuantKVCache:
    """KV キャッシュに TurboQuant 圧縮を適用するラッパー"""

    def __init__(self, head_dim: int, compressed_dim: int):
        self.compressed_dim = compressed_dim  # head_dim の 1/4 程度が推奨

    def compress(self, keys: torch.Tensor, values: torch.Tensor):
        # Step 1: PolarQuant 回転
        rotated_k, _ = polar_quant_rotate(keys, keys)
        # Step 2: JL 圧縮で次元削減（メモリ削減）
        compressed_k = jl_compress(rotated_k, self.compressed_dim)
        # values は INT8 量子化（精度優先）
        scale = values.abs().max(dim=-1, keepdim=True).values
        quantized_v = (values / scale).to(torch.int8)
        return compressed_k, (quantized_v, scale)
```

### npm サプライチェーン攻撃（CVE-2026-48027 / CVE-2026-45321）— 影響確認と緊急対応チェックリスト

今回の Nx Console・TanStack 同時攻撃は、**信頼された npm 名前空間を悪用した認証情報窃取**という典型的なサプライチェーン攻撃パターンだ。CI/CD パイプラインで `npm install` を自動実行する環境では、マルウェアが実行されていても気づきにくく、**パッケージ更新だけでなく全認証情報のローテーションが必須**となる。

```bash
# --- CVE-2026-48027 / CVE-2026-45321 緊急確認チェックリスト ---

# 1. 脆弱なバージョンがインストールされているか確認
npm audit --json | jq '.vulnerabilities | to_entries[] |
    select(.key | test("nx-console|tanstack")) | {pkg: .key, severity: .value.severity}'

# 2. package-lock.json から推移的依存も含めてバージョンを確認
# (直接依存していない場合も乗っ取られたバージョンが入る可能性がある)
cat package-lock.json | jq '
    .. | objects | select(.name? | test("@nrwl/nx-console|@tanstack")) |
    {name: .name, version: .version}'

# 3. 自動修正を適用（安全なバージョンへのアップグレード）
npm audit fix

# 4. 侵害の痕跡確認 — 実行中 Node プロセスによる不審なアウトバウンド通信
# Linux / macOS
ss -tnp | grep node
# macOS
sudo lsof -i -n -P | grep -E "node|npm" | grep ESTABLISHED

# Windows (PowerShell)
$nodePids = (Get-Process node, npm -ErrorAction SilentlyContinue).Id
Get-NetTCPConnection -State Established |
    Where-Object { $_.OwningProcess -in $nodePids } |
    Select-Object LocalAddress, RemoteAddress, RemotePort

# 5. 侵害が疑われる場合の認証情報ローテーション優先順位
# - .env / CI 環境変数のシークレット (AWS_ACCESS_KEY, API_KEY 等) → 即時失効・再発行
# - SSH 鍵ペア (~/.ssh/) → 即時削除・再生成・authorized_keys 更新
# - ~/.npmrc の publish トークン → npm token revoke <token>
# - Git ホスティングサービスのアクセストークン / Deploy key
echo "[!] Credentials rotation required for any environment where affected packages ran"
```

**優先度: 高**。NVD（nvd.nist.gov）で各 CVE の影響バージョン範囲を確認し、脆弱なバージョンが実行された形跡があれば、パッケージ更新と並行して**全シークレットの即時ローテーション**を実施すること。
