### 3. Python 3.15 Beta 1 リリース — JIT 性能が 8〜13% 向上、遅延インポート（PEP 810）が feature freeze 通過

5/11 に Python 3.15 が Feature Freeze を迎え、**Beta 1** が公開された。今サイクル最大のハイライトは **JIT コンパイラの大幅改善**で、新しいトレーシングフロントエンド・レジスタアロケーション・参照カウント除去最適化により、プラットフォームとワークロードに応じて **8〜13% の幾何平均性能向上**（α7 時点では 3〜4% だったが大幅に伸長）を達成した。**PEP 810（明示的遅延インポート）**も正式採用され、実際にモジュールを使う時点まで `import` の処理を先延ばしにすることでスタートアップ時間を最大 50〜70% 削減できる。加えて **PEP 686**（`open()` のデフォルトエンコーディングを UTF-8 に統一）も本バージョンに含まれ、Python 2 以来続いてきたロケール依存の落とし穴がついて解消される見込みだ。一方、CPython への Rust 統合（Rust for CPython）は 3.15 ではなく **3.16 が目標**に変更されたと Python Insider が報告している。リリース本番は 2026 年 10 月を予定している。

### Python 3.15 Beta 1 — 主要新機能チートシート

Feature Freeze が確定した Python 3.15 の主要変更点をコードで確認する。

```python
# PEP 810: 明示的遅延インポート（lazy imports）
# 従来: モジュール読み込み時に即 import が実行される
import heavy_library  # 起動時に全コードを評価

# 3.15 新構文: lazy キーワードで遅延評価
lazy import heavy_library  # 実際に使われるまで実行されない

# 環境変数でも制御可能（コード変更不要）
# PYTHONLAZYIMPORTS=1 python myapp.py

# PEP 686: UTF-8 がデフォルトエンコーディングに
# 3.14 以前: ロケール依存（Windows では cp932 など）
with open("data.txt") as f:  # 3.15 では常に UTF-8
    content = f.read()

# 3.14 以前の移植性確保コードが不要になる:
# with open("data.txt", encoding="utf-8") as f:  # 明示が不要に

# comprehension でのアンパック拡張（3.15 新機能）
pairs = [(1, "a"), (2, "b"), (3, "c")]
keys, values = zip(*pairs)

# リスト内包表記での * アンパック（3.15）
merged = [*list_a, *(x * 2 for x in list_b)]

# JIT を有効化して性能を計測（環境変数）
# PYTHON_JIT=1 python -m timeit "sum(range(10**6))"
```

### Google Managed Agents（Gemini API）— シングル API コールでエージェント起動

Google I/O 2026 で発表された Gemini API の Managed Agents を試すための最小実装例。

```python
import google.generativeai as genai

# Gemini API クライアント初期化
genai.configure(api_key="YOUR_API_KEY")

# Managed Agent を Interactions API 経由で起動
# モデル: gemini-3.5-flash（デフォルト）
# 隔離 Linux サンドボックス内でツール使用・コード実行が完結
response = genai.managed_agents.create(
    model="gemini-3.5-flash",
    system_instruction="You are a data analysis agent.",
    tools=["code_execution", "file_read"],  # 組み込みツールを指定
)

session = response.start_session()

# イベント送信（SSE ストリーミング）
for event in session.send("analyze the uploaded CSV and return summary stats"):
    if event.type == "text":
        print(event.content)
    elif event.type == "tool_call":
        print(f"Tool used: {event.tool_name}")

# AGENTS.md でエージェント定義をバージョン管理
# echo "# Agent: data-analyst\nmodel: gemini-3.5-flash\ntools: [code_execution]" > AGENTS.md
```

### Microsoft Defender CVE-2026-41091 / CVE-2026-45498 — 野放し悪用中、CISA が 6/3 期限でパッチ適用を義務化

本日（5/21）Help Net Security・The Hacker News・BleepingComputer が一斉報道した Microsoft Defender の 2 件のゼロデイが、CISA の **Known Exploited Vulnerabilities (KEV)** カタログに追加された。米連邦文民機関（FCEB）は **2026-06-03 までにパッチ適用またはシステム停止**が義務付けられる。

| CVE | 別名 | 種別 | CVSS | 影響コンポーネント |
|---|---|---|---|---|
| CVE-2026-41091 | UnDefend | 権限昇格（SYSTEM 取得） | 7.8 | Microsoft Malware Protection Engine v1.26030.3008 以前 |
| CVE-2026-45498 | RedSun | サービス拒否（Defender 無効化） | 4.0 | Microsoft Defender Antimalware Platform |

CVE-2026-41091 は Malware Protection Engine がファイルアクセス前にシンボリックリンクを不適切に解決する欠陥で、ローカル低権限ユーザーが **SYSTEM 権限**を取得できる。CVE-2026-45498 は Defender を意図的にクラッシュ・無効化できる DoS で、単独では軽微だが CVE-2026-41091 と組み合わせて「防衛機能を無効化してから権限昇格」する攻撃チェーンとして悪用される懸念がある。

```powershell
# Microsoft Defender エンジンバージョンを確認（要修正バージョン: 1.1.26040.8 以降）
Get-MpComputerStatus | Select-Object AMEngineVersion, AntivirusEnabled, RealTimeProtectionEnabled

# 修正済みエンジンバージョンの確認
# AMEngineVersion が 1.1.26040.8 以上であれば CVE-2026-41091/45584 は修正済み
# AntivirusPlatformVersion が 4.18.26040.7 以上であれば CVE-2026-45498 は修正済み

# 強制アップデート（エンジン定義を即時更新）
Update-MpSignature -UpdateSource MicrosoftUpdateServer

# Windows Update 経由でプラットフォームも更新
Install-WindowsUpdate -KBArticleID "KB5058415" -AcceptAll -AutoReboot

# Defender が正常動作しているか確認
Get-MpThreatDetection | Select-Object -Last 5 ActionSuccess, ThreatName
```

### Linux CVE-2026-46333 — 非特権ローカルユーザーが root 実行可能、Debian / Fedora / Ubuntu のデフォルト構成に影響

カーネルの権限管理不備（CVSS 5.5）として追跡される **CVE-2026-46333** は、Debian・Fedora・Ubuntu のデフォルトインストールで非特権ローカルユーザーが機密ファイルの読み出しと root としての任意コマンド実行を行える脆弱性だ。CVSS スコアは 5.5 と中程度だが、デフォルト構成で再現可能なため実際の影響範囲は広い。各ディストリビューションはカーネルアップデートをリリース済みで、更新適用が最優先となる。

```bash
# 影響カーネルバージョンの確認
uname -r

# 各ディストリビューションでの対処
# --- Debian / Ubuntu ---
sudo apt update && sudo apt full-upgrade -y
sudo reboot  # カーネル入れ替えに必要

# --- Fedora ---
sudo dnf update kernel -y
sudo reboot

# 更新後に修正済みカーネルを確認
uname -r  # 修正済みバージョンに変わっていることを確認

# audit ログで不審な権限昇格の痕跡を確認
sudo ausearch -m avc,user_avc -ts today | grep -i "root\|privilege"
```
