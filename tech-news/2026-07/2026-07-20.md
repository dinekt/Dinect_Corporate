### 1. Moonshot AI が Kimi K3 をリリース — 2.8兆パラメータ、史上最大のオープンウェイトモデル

中国の Moonshot AI が7月16日、**Kimi K3** をリリースした。2.8兆パラメータのMoE（Mixture of Experts）構造を採用した、これまでに公開されたなかで最大のオープンウェイトモデルである。ネイティブマルチモーダル（視覚理解）と最大100万トークンのコンテキストウィンドウを備え、実運用タスクを44職種・9産業で評価するベンチマーク **GDPval-AA v2** では1,687点（3位）を記録、Claude Opus 4.8（1,600点）を上回った。とりわけ **Frontend Code Arena**（フロントエンド実装能力）では Claude Fable 5（1,631点）・GPT-5.6 Sol（1,618点）を抑えて**1位（1,679点）**を獲得している。さらに SpreadsheetBench 2・BrowseComp・Automation Bench など実務自動化系ベンチマークで8分野中4分野を制した。全パラメータの公開は7月27日を予定しており、公開後はオープンモデルプロバイダーを通じたセルフホスティングも可能となる。これは米国の輸出規制によって高性能チップへのアクセスが制限されているなかでの成果であり、「算力（compute）制約下でのオープンソース競争力」という新たな可能性を示した。

### 2. Microsoft 7月 Patch Tuesday — 史上最多 622 CVE、うち3件はゼロデイ野外悪用済み

Microsoft が7月の月次セキュリティ更新を公開し、**622件の脆弱性（CVE）** を一括修正した。これは過去最大規模のPatch Tuesdayであり、6月（約198件）の3倍超、5月の5倍近い件数にのぼる。57件が「Critical」評価で、うち48件はリモートコード実行（RCE）、7件は権限昇格（EoP）。特に注目すべき脆弱性は2件で、**CVE-2026-56155**（Active Directory Federation Services における権限昇格、Important）と **CVE-2026-56164**（Microsoft SharePoint Server における認証バイパス、Moderate）がすでに野外で悪用されている。CISA は6月中旬からSharePoint の複数CVE（CVE-2026-32201・CVE-2026-45659・CVE-2026-56164・CVE-2026-58644）の積極的な悪用事例を把握しており、オンプレミス SharePoint Server を運用する組織への早急なパッチ適用を求めている。さらに Windows DHCP Server に影響する CVE-2026-50370・CVE-2026-50518（ヒープバッファオーバーフロー、いずれも Critical/RCE）は隣接ネットワーク・外部ネットワーク双方からの無認証攻撃を許す可能性がある。年間累計でも2026年は前年比でCVE発行数が急増しており、パッチサイクルの圧縮が運用チームの恒常的課題となっている。

### 3. Apple Intelligence が中国市場で承認 — Alibaba Qwen 統合、AI地政学の新章へ

中国の国家インターネット情報弁公室（CAC）が、Apple の生成AIサービス **Apple Intelligence** の中国展開を承認した。iOS・iPadOS・macOS・visionOS に Alibaba の **Qwen** モデルを統合する形で提供される。この承認は、外資系AIサービスに対して厳格な国内データ管理と提携先承認を求める中国の規制枠組みのもとで下されたもので、Appleが自社AIを「国産モデル統合」という形式で現地化した点が注目される。同時期に開催された **WAIC 2026**（上海、7/17-20・本日閉幕）でも、中国政府はAI標準のグローバルな多極化を主張し、「米国主導ではなく包括的なガバナンス」を訴えた。これに対し Satya Nadella（Microsoft CEO）は同週、「企業はAIモデルプロバイダーに依存しすぎるべきでなく、大規模モデルのアウトプットを使った蒸留（distillation）によって独自モデルを構築する権利がある」と公言し、AI産業の垂直統合リスクを警告している。AI覇権をめぐる米・中・欧の三極間の政策・外交摩擦は、Kimi K3 のオープンウェイト公開、Apple Intelligence のローカライズ、そして WAIC での外交発信と、まさに今週の出来事に凝縮された形となった。

## 新技術・新リリース

### Kimi K3: オープンウェイト最大モデルを試す

Kimi K3 の全パラメータ（2.8T MoE）公開は7月27日予定だが、現在は Kimi 公式 API と一部オープンモデルプロバイダー経由で利用できる。MoE 構造のため、推論時に活性化されるパラメータは全体の一部に限られ、ハードウェア要件は総パラメータ数ほど高くはならない。

```python
# Kimi K3 API 呼び出し例（OpenAI互換エンドポイント）
import openai

client = openai.OpenAI(
    api_key="YOUR_KIMI_API_KEY",
    base_url="https://api.moonshot.ai/v1",
)

response = client.chat.completions.create(
    model="kimi-k3",
    messages=[
        {
            "role": "user",
            "content": "以下のReactコンポーネントをTypeScriptで書き直してください:\n..."
        }
    ],
    max_tokens=4096,
)

print(response.choices[0].message.content)
```

```python
# マルチモーダル利用例（画像 + テキスト）
import base64

with open("screenshot.png", "rb") as f:
    image_data = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model="kimi-k3",
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/png;base64,{image_data}"
                    }
                },
                {
                    "type": "text",
                    "text": "このUIのHTMLとCSSを実装してください"
                }
            ]
        }
    ],
)
```

フロントエンド実装ベンチマーク（Frontend Code Arena）でトップを記録していることもあり、UIコンポーネント生成・HTML/CSS実装タスクでの活用が特に期待される。1Mトークンのコンテキストウィンドウを活かした長大なコードベース全体への質問も有効なユースケースだ。
