### 3. TypeScript 6.0 正式リリース — JSベース最後のメジャー版、Go製 TS 7.0 へのブリッジ

Microsoftが2026年3月23日に**TypeScript 6.0**を正式リリースした。本バージョンは、現在Goで書き直しが進行中の**TypeScript 7.0**への移行前における、JavaScriptベースコンパイラの最後のメジャーリリースと位置づけられている。パフォーマンス面では、増分ビルドが**40〜60%高速化**し、大規模コードベースでのコンパイル時メモリ消費が**約25%削減**された。言語仕様面ではStage 3デコレーターのメタデータ対応が強化され、依存性注入・バリデーション・シリアライズライブラリがランタイムで型情報にアクセスできるようになった。また`using`宣言（Disposableリソースの自動クリーンアップ）が正式サポートされ、C#の`using`ステートメントやPythonのコンテキストマネージャに相当する構文が利用可能となった。デフォルト設定の変更として`strict`が`true`に、`module`が`esnext`に、`target`が`ES2025`に変更されており、新規プロジェクトは設定なしでモダンな設定が適用される。TypeScript 7.0はGoで実装されており、ネイティブ実行速度と共有メモリマルチスレッドによる大幅な高速化が見込まれ、年内リリースが予定されている。

### TypeScript 6.0 — `using` 宣言とデコレーターメタデータの実践

TypeScript 6.0で導入された主要機能を実際のコードで確認する。

```typescript
// --- using 宣言: Disposable リソースの自動クリーンアップ ---
// TS 6.0から using キーワードがネイティブサポート
// スコープ離脱時に [Symbol.dispose]() が自動呼び出される

class DbConnection implements Disposable {
  private connected = true;

  query(sql: string): string[] {
    if (!this.connected) throw new Error("Connection closed");
    console.log(`Executing: ${sql}`);
    return ["row1", "row2"];
  }

  [Symbol.dispose]() {
    this.connected = false;
    console.log("Connection closed automatically");
  }
}

function fetchUsers() {
  using db = new DbConnection(); // スコープ離脱時に自動クローズ
  return db.query("SELECT * FROM users");
  // ← ここで db[Symbol.dispose]() が呼ばれる。try/finally 不要
}


// --- Stage 3 デコレーター + メタデータ: 実行時型情報の活用 ---
// TS 6.0 で decoratorMetadata が安定化、DI フレームワーク等で活用可能

function Injectable(target: DecoratorContext) {
  // メタデータを付与することでコンテナが型情報を参照可能
  target.metadata["injectable"] = true;
}

function Validate(min: number, max: number) {
  return function (target: unknown, context: ClassFieldDecoratorContext) {
    return function (this: unknown, value: number) {
      if (value < min || value > max) {
        throw new RangeError(
          `${String(context.name)} must be between ${min} and ${max}`
        );
      }
      return value;
    };
  };
}

@Injectable
class UserService {
  @Validate(1, 120)
  age: number = 0;

  getUser(id: number): string {
    return `User #${id}`;
  }
}


// --- strict デフォルト化の影響確認 ---
// TS 6.0 から tsconfig.json で strict 未指定でも true が既定値
// 既存プロジェクトでは明示的に strict: false が必要になる場合がある

// tsconfig.json (TS 6.0 以降のデフォルト相当)
// {
//   "compilerOptions": {
//     "strict": true,       // 新デフォルト
//     "module": "esnext",   // 新デフォルト
//     "target": "ES2025"    // 新デフォルト
//   }
// }
```

TypeScript 7.0（Go製）はネイティブコンパイル速度と共有メモリマルチスレッドにより、現在のJS実装比でさらに大幅な高速化が見込まれる。6.0は既存コードベースの7.0移行準備のためのブリッジリリースと捉えると、`strict`デフォルト化等の破壊的変更も早期に対処しておくことが移行コスト削減につながる。

### SharePoint RCE CVE-2026-45659 が CISA KEV に追加 — 認証済みユーザーによる任意コード実行、7/4 パッチ期限

```bash
# === SharePoint CVE-2026-45659 対応チェックリスト ===
# CVSS: 8.8 | CWE-502: Deserialization of Untrusted Data
# 影響: SharePoint Server SE / 2019 / Enterprise 2016
# CISA KEV 追加日: 2026-07-01 | 連邦機関パッチ期限: 2026-07-04

# ---- [1] 影響バージョン確認 ----
# SharePoint Server Subscription Edition (SE)
# SharePoint Server 2019
# SharePoint Server Enterprise 2016

# PowerShell でバージョン確認
# (SharePoint 管理シェルで実行)
# (Get-SPFarm).BuildVersion

# ---- [2] パッチ適用確認 ----
# 2026年5月の月例パッチ（Microsoft のリリースノートに当初未掲載）
# 2026-05-27 に修正アドバイザリが追記されたため、
# 5月パッチ適用済みでも SharePoint 更新が漏れている可能性がある

# Windows Update 履歴確認 (PowerShell)
Get-HotFix | Where-Object { $_.InstalledOn -ge "2026-05-01" } `
  | Select-Object HotFixID, InstalledOn `
  | Sort-Object InstalledOn -Descending

# ---- [3] 侵害痕跡 (IoC) の確認 ----
# 悪用後に確認されたツール: Velociraptor, Cloudflare Tunnels,
# Zoho Assist, SSH via VS Code（永続化・横移動に使用）

# SharePoint の ULS ログで不審なデシリアライズエラーを確認
# ログパス例: C:\Program Files\Common Files\Microsoft Shared\
#              Web Server Extensions\16\LOGS\

# Site Member 以上の権限があれば認証済みユーザーが悪用可能なため
# 外部公開 SharePoint だけでなく社内 SharePoint も対象

echo "CVE-2026-45659: Patch immediately — active exploitation confirmed"
echo "Attack vector: Authenticated (Site Member+), no admin privilege needed"
echo "Post-exploit: Velociraptor / Cloudflare Tunnels observed in the wild"
```

**CVE-2026-45659**はSharePoint Serverのデシリアライゼーション処理における信頼されていないデータの不適切な取り扱いに起因するRCEで、攻撃者はSharePointのサイトメンバー以上の権限さえあれば管理者権限なしに任意コードをSharePointサービスのコンテキストで実行できる。MicrosoftはCVSSスコア9.8の深刻度を「悪用の可能性は低い」と当初評価していたが、CISAが7月1日にKEV（既知の悪用済み脆弱性カタログ）へ追加し、実際の悪用が確認された。悪用後の侵害では永続化ツール（Velociraptor、Cloudflare Tunnels、Zoho Assist）や横移動手法（VSCode経由SSH）が観測されており、単なるRCEにとどまらず高度な侵入活動の足がかりとして機能している。MicrosoftがリリースノートにこのCVEを当初掲載していなかった経緯から、5月パッチ適用済み組織でもSharePoint更新が漏れているケースがあるため、パッチ適用状況の再確認が推奨される。合わせて、**SimpleHelp**（リモートサポートツール）のOIDC認証フローにおける署名検証なし認証バイパス脆弱性も7月2日が対応期限として設定されており注意が必要だ。
