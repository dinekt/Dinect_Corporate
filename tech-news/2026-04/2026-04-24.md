### 1. Google Cloud Next 2026 最終日 — Gemini 3.1 Flash-Lite GA・TPU v8 二系統・A2A プロトコル拡大

Google Cloud Next 2026（4月22〜24日、ラスベガス）が最終日を迎え、AI インフラとエージェント関連の主要発表が出揃った。

**主な発表内容:**

- **TPU v8 二系統体制**: トレーニング最適化の「Sunfish」（Broadcom設計、TSMC 2nm対応予定）と推論最適化の「Zebrafish」（MediaTek設計、エージェント展開向け）を発表。TPU 8t は最大 9,600 TPU をスケールアウトし、2ペタバイトの共有高帯域メモリをサポートする。
- **Gemini 3.1 Flash-Lite 一般提供開始**: Vertex AI 上で GA。前世代（Gemini 2.5 系）は 2026 年 10 月に退役予定で、3.x 系への移行が公式に加速。
- **A2A プロトコル拡大**: マルチエージェントオーケストレーション規格「Agent-to-Agent (A2A)」の対応パートナーを 50 社以上に拡大。Agent Development Kit (ADK) 2.0 も更新。
- **Vertex AI Agent Builder 2.0**: 成果ベース（アウトカム課金）の新価格モデルを導入。
- **数字**: Google Cloud の AI モデルが毎分 160 億トークンを処理（前四半期比で 60% 増）。Google 社内では新規コードの 75% が AI 生成（前年秋は 50%）。セキュリティ運用センターでの脅威対応時間が 90% 以上削減。

**開発者への影響:**
A2A プロトコルの標準化が進むことで、複数の AI エージェントを組み合わせたワークフロー構築がプロプライエタリな API ではなく共通規格ベースに移行しつつある。Vertex AI Agent Builder の成果ベース課金は、エンタープライズ向け SaaS にとってコスト設計の参考事例となる。DeepSeek・Anthropic との三角競争が明確になり、Google Cloud はインフラ（TPU）＋エージェント基盤（ADK + A2A）＋モデル（Gemini 3.x）を垂直統合する戦略を鮮明にした。

### 2. Anthropic の評価額がセカンダリー市場で 1 兆ドル到達 — OpenAI（8,800 億ドル）を上回り業界首位

2026 年 4 月 23 日、Forge Global などのセカンダリー市場で Anthropic の株式が取引された結果、同社の暗示的評価額が約 1 兆ドルに達した。OpenAI の同市場評価額（8,800 億ドル）を超え、プライベート AI 企業として世界最高評価を記録した。

**数字で見る急成長:**
- 年次収益（ARR）: 2025 年末の 90 億ドル → 2026 年 3 月時点で 300 億ドル（1 四半期で +233%）
- 評価額: セカンダリー市場で 1 兆ドル（ただし IPO 目標は 4,000〜5,000 億ドル）
- IPO 予定: 2026 年 10 月、ゴールドマンサックス・JPモルガンが主幹事

**背景と注意点:**
収益成長の主な牽引役はコーディングツール（Claude Code / Claude API）への強い需要。一方、セカンダリー市場の評価は「株式供給不足 × 参加への不安（FOMO）」によって過熱している側面があり、2021 年以前のセカンダリー評価が後に 60〜70% 下落した事例と比較する声もある。実際の IPO 評価額はセカンダリー評価の半分以下（4,000〜5,000 億ドル）が想定されており、乖離は大きい。

**開発者・事業者への影響:**
Claude API の長期的な事業継続性に対する市場の信認が高まっている。ただし Amazon-AWS との深い提携（4 月 22 日報告済）の構造上、Anthropic が AWS 以外でのインフラ構成を柔軟に変える余地は狭まっている。コーディング分野での ARR 急成長は、AI コーディングツール市場が「試用段階」から「業務必須ツール」へ完全に移行したことを示す定量的な証拠といえる。

### 3. OpenAI が「Privacy Filter」をオープンソースで公開 — ローカル実行可能な PII 検出・マスキングモデル

2026 年 4 月 22 日、OpenAI が個人情報（PII）をテキストから自動検出・編集するモデル「Privacy Filter」を Apache 2.0 ライセンスで公開した。Hugging Face（`openai/privacy-filter`）および GitHub（`openai/privacy-filter`）で取得可能。

**技術仕様:**
- パラメータ数: 15 億（アクティブ 5,000 万）の双方向トークン分類器
- コンテキスト窓: 128,000 トークン
- 対象 PII カテゴリ: 個人氏名・連絡先（メール、電話、住所）、口座番号（銀行・クレジットカード）、日付・URL の 8 カテゴリ
- ベンチマーク: PII-Masking-300k データセットで 96% スコア
- 動作: ローカル実行対応（データが外部サーバーに送信されない）

**通常の LLM との差異:**
一般的な LLM が左から右への自己回帰生成を行うのに対し、Privacy Filter は双方向分類器（BERT 系アーキテクチャ）を採用。前後文脈を同時に参照するため、「Alice」が文学的キャラクターか実在の個人かを文脈から判別するといった精度が実現できる。

**開発者への実用手順:**
```bash
pip install transformers
python -c "
from transformers import pipeline
pii_filter = pipeline('token-classification', model='openai/privacy-filter')
result = pii_filter('田中太郎（090-XXXX-XXXX）が申請しました。')
print(result)
"
```

**開発者・事業者への影響:**
AI に入力するテキストから PII を事前に取り除くユースケース（RAG パイプライン、カスタマーサポートログの学習前処理、文書デジタイゼーションでの個人情報除去）で即座に実用できる。文書処理（IDP）や日本語 SaaS を扱う事業者にとっては、GDPR・個人情報保護法対応の前処理コストを大幅に下げる選択肢となる。ローカル実行可能な点が、クラウド送信を避けたい金融・医療・法務系顧客向けプロダクトに特に有効。
