### 2. Langflow CVE-2026-5027（CVSS 8.8）が未パッチ状態で積極悪用中 — 約7,000インスタンスが認証なしRCEリスクに

オープンソースのAI開発プラットフォームLangflowに存在するパストラバーサル脆弱性CVE-2026-5027（CVSS 8.8）が、6月8日にVulnCheckの既知悪用脆弱性（KEV）リストに追加された。問題は`POST /api/v2/files`エンドポイントの`filename`パラメータにおけるサニタイズ不足で、攻撃者はパストラバーサル文字列（`../`）によりファイルシステム上の任意の場所へファイルを書き込める。LangflowはデフォルトでUnauthenticated Auto-Loginが有効なため、認証なしでエンドポイントへ到達でき、実質的に未認証のリモートコード実行（RCE）となる。インターネット上に公開されている約7,000インスタンスが危険にさらされており、北米への集中が最も高い。3月27日にTenable社が公開開示していたにもかかわらず未パッチのバージョンが多く流通しており、AI開発ツール自体がサプライチェーン攻撃の新たな入口として標的化される事態を示している。

### 3. EU AI Act 高リスクAI 8月2日コンプライアンス期限が迫る — 米欧規制アプローチ対立深まる中、Google I/O 2026でGemini Omni・3.5 Flash発表

EUのAI規制法（EU AI Act）の高リスクAIシステム規制が**2026年8月2日**を期限とし、EU域外企業にも適用される。欧州は権利・リスクベースの規制モデルを推進する一方、米国は自主的な基準を優先しており、この規制アプローチの乖離がグローバルAI市場の分断を加速させるとの懸念が広まっている。技術面では、Google I/O 2026（5月19〜20日開催）で発表された**Gemini Omni**（動画・音声・テキスト横断のマルチモーダル生成・編集）と**Gemini 3.5 Flash**（フラッグシップ級の精度をFlash速度で実現、エージェンティックタスクとコーディングベンチマークでGemini 3.1 Proを上回る）が引き続き開発者コミュニティの注目を集めている。さらに、Gemini for Scienceでは30以上のライフサイエンスデータベースとエージェンティックプラットフォームの連携が可能になるなど、科学研究の加速に向けた取り組みも強化された。規制の不確実性が高まる中でも、AI機能そのものの進化は止まっておらず、企業はコンプライアンス対応と技術採用の両立を迫られている。

## 新技術・新リリース

### Visual Studio 2026 June Update（v18.7.0） — MCP Server 信頼検証・GitHub Copilot 深化統合でIDE刷新

2026年6月9日リリースのVisual Studio 2026 v18.7.0は、Microsoftが「初のインテリジェント開発環境（IDE）」と位置付ける大型アップデートだ。最大の注目点は**MCP Server 信頼検証**の追加で、Copilot ChatからMCPサーバーへ接続する際に信頼バリデーションを実施し、悪意あるサーバーへの意図せぬ接続を防ぐ仕組みが標準化された。加えて、編集内容の影響が及ぶコード上の離れた箇所の変更候補を自動提案する**長距離次編集提案（Long-distance Next Edit Suggestions）**、IDE内でのGitHub PRレビュー・承認、Copilot月次クレジット使用量の追跡とアラート機能も搭載された。

```json
// Visual Studio 2026 — MCP Server 設定例（.vscode/mcp.json 互換フォーマット）
// 信頼バリデーションを "strict" にすることでリモート接続のリスクを軽減する
{
  "mcp": {
    "servers": {
      "local-filesystem": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "."],
        "trust": {
          "validation": "strict",
          "allowedOrigins": ["localhost", "127.0.0.1"],
          "requireSignature": false
        }
      },
      "remote-api-tool": {
        "url": "https://your-mcp-server.example.com/mcp",
        "trust": {
          "validation": "strict",
          "requireSignature": true
        }
      }
    }
  }
}
```

ローカルMCPサーバーは`allowedOrigins`で接続元を明示的に制限し、リモートサーバーは`requireSignature: true`で署名検証を必須化するのが現時点の推奨構成だ。MCPの普及に伴い悪意あるサーバーへの誘導攻撃が現実的なリスクになりつつあり、信頼検証の標準組み込みは開発ツール側のセキュリティ強化として評価される動きとなっている。

### Langflow CVE-2026-5027 ＋ Microsoft Defender CVE-2026-41091 — AIツールがサプライチェーン攻撃の入口に

```bash
# === Langflow CVE-2026-5027 対応チェックリスト ===

# 1. 影響バージョンを確認
pip show langflow | grep Version
#    Langflow 1.4.0 以前が対象（修正済みバージョンへの即時アップグレードを推奨）

# 2. インターネット公開状態を確認・遮断（最優先）
#    約 7,000 インスタンスが公開状態（Shodan/Censys 調査より）
#    公開している場合はファイアウォールで即時遮断すること

# 3. 暫定緩和策（パッチ適用前の nginx リバースプロキシ設定例）
#    /api/v2/files エンドポイントへの外部アクセスをブロック
#
#    location /api/v2/files {
#        deny all;
#        return 403;
#    }

# 4. パッチ適用（最も確実な対応）
pip install --upgrade langflow

# 5. 侵害調査（3月27日の公開開示日以降を起点に確認）
#    - 不審なファイルがシステムディレクトリに書き込まれていないか
find /tmp /var/lib/langflow /etc -name "*.py" -o -name "*.sh" \
  | xargs ls -la 2>/dev/null | grep "Jun\|May"

echo "[PRIORITY: HIGH] CVE-2026-5027 — unauthenticated RCE, isolate from internet immediately"
echo "VulnCheck KEV: Added 2026-06-08 | CVSS 8.8"
```

Langflowの問題はAI開発ツール自体が攻撃対象となる「AIサプライチェーンリスク」の典型例であり、開発環境のセキュリティ評価が不可欠な時代に入ったことを示している。また**Microsoft Defender CVE-2026-41091**（権限昇格、PoC「RoguePlanet」公開済み・積極悪用中）は6月 Patch Tuesday（2026年6月9日）の月例パッチで修正されており、未適用のWindows環境は速やかな更新が必要だ。
