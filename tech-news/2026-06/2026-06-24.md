### 1. Reflection AI × SpaceX Colossus 2が総額$6.3B計算資源契約を締結 — NvidiaがAI新興勢力に両方向で関与、Grok AIの将来にも影

### 2. 「Squidbleed」(CVE-2026-47729)と「FortiBleed」が同時警戒 — 29年間潜伏したプロキシ脆弱性と8.6万台のFortinet機器侵害が並走

セキュリティコミュニティが2つの「Bleed系」インシデントへの対応に追われている。一つ目は**Squidbleed（CVE-2026-47729）**。1997年1月のコミットに起源を持つ**Squid Proxyの29年間未発見のヒープオーバーリード**脆弱性であり、FTPパーサーがバッファ境界を超えて読み出すことで別ユーザーの未クリア済みHTTPリクエストデータが漏洩する仕組みだ。Heartbleedとの類比から命名され、Calif Security Researchが**Claude Mythos Previewとの協働**によって三十年越しのFTP解析コードを解析し発見したと報告されている（The Register、2026年6月23日）。共有プロキシ環境（企業ネットワーク・学校・公衆Wi-Fi）が最も高リスクで、Squid 7.6（2026年6月リリース）および8系列のパッチで修正済みだ。二つ目は**FortiBleed**。2026年2月から継続するFortinet FortiGate/SSL VPN機器への組織的攻撃キャンペーンであり、194カ国の**86,644台**の機器から認証情報が流出・検証済みのデータベースが構築されたとSOCRadarが公表している。ロシア語話者の脅威アクターが関与していると指摘されており、まだパッチ未適用のFortiGateが広く残存していることを示唆する。

**出典**: [The Register: Mythos discovers Squidbleed](https://www.theregister.com/security/2026/06/23/mythos-discovers-squidbleed-a-memory-leak-thats-gone-undetected-since-clinton-era/5260367) / [SecurityWeek: Squidbleed](https://www.securityweek.com/decades-old-squid-proxy-flaw-squidbleed-can-expose-user-data/) / [SOCRadar: FortiBleed](https://socradar.io/blog/fortibleed-fortinet-firewalls-compromised/) / [The Hacker News: Squidbleed](https://thehackernews.com/2026/06/29-year-old-squid-proxy-bug-squidbleed.html)

### 3. EUが「EUROPA」コンソーシアムを選定 — EU全24言語対応オープンソースフロンティアAIの構築へ、AI Act透明性ルールも8月に迫る

欧州委員会は6月19日、**Frontier AI Grand Challenge**の勝者としてイタリア新興企業**Domyn**率いる**EUROPAコンソーシアム**を選定した（Fraunhofer-Gesellschaft等が参加）。欧州連合の全24公用語に対応する**400億パラメータ超**のオープンソースフロンティアAIモデルを、EuroHPCの計算資源を活用して構築する計画で、完成したモデルは公的機関・研究機関・企業に広く開放される。製造業・医療・自律システムなどのAI応用分野での欧州産業力強化を狙った取り組みで、米中AI二極体制への対抗軸として位置づけられている。タイミングとしても重要なのは、**EU AI Actの透明性ルール（Transparency Obligations）が2026年8月に施行**される点であり、汎用AIシステムへの説明義務・著作権規制が実効性を持ち始める転換期に差し掛かっている。米国側では白鍵が連邦レベルでAI監督の集約を志向する一方で、カリフォルニア・コロラド州が独自のAI規制で連邦政府と対立する展開が続いており、グローバルなAIガバナンスの多極化が加速している。

### FFmpeg「PixelSmash」(CVE-2026-8461) 詳細と対策 & OpenAI Daybreak GPT-5.5-Cyber公開

**FFmpeg PixelSmash（CVE-2026-8461）**は、MagicYUVデコーダー内のスライス高さ計算に起因するヒープ境界外書き込みであり、CVSS **8.8（High）**に評価されている。AVI・MKV・MOV形式の細工された動画ファイルを開くだけでコード実行が可能になり得るため、Jellyfin・Kodi・Emby・Nextcloud・PhotoPrism・OBS Studioなどを含む**FFmpegを組み込んでいる広範なアプリケーションが影響を受ける**。RCE成立にはASLRの無効化またはバイパスが条件となるが、DoSは無条件で発生する。JFrogが6月17日に修正版FFmpeg **8.1.2**のリリースと同時に技術詳細を公開している。

```bash
# PixelSmash 影響確認・対処スクリプト

# === 1. インストール済みFFmpegバージョン確認 ===
ffmpeg -version 2>&1 | head -1
# "ffmpeg version 8.1.2" 未満であれば要更新

# === 2. パッケージマネージャー経由の更新 ===
# Ubuntu/Debian
sudo apt update && sudo apt upgrade ffmpeg

# macOS (Homebrew)
brew upgrade ffmpeg

# === 3. 動画サーバー (Jellyfin例) の再起動 ===
# FFmpeg更新後はサービス再起動が必要
sudo systemctl restart jellyfin

# === 4. バージョン再確認 ===
ffmpeg -version 2>&1 | grep "ffmpeg version"
# "ffmpeg version 8.1.2" 以上であれば対処完了

# === 5. 信頼できないソースからの動画をFFmpegで処理する場合の一時措置 ===
# ASLRが有効であることを確認 (Linux)
cat /proc/sys/kernel/randomize_va_space
# 2 であれば完全なASLR有効（推奨状態）
```

また、OpenAIは**Daybreak**イニシアティブの一環として**GPT-5.5-Cyber**の改良版を信頼済みディフェンダー（セキュリティ研究者・防衛機関）向けに限定公開した。ソフトウェア脆弱性の発見とパッチ作成を支援する用途に特化した「これまでで最強のモデル」と自称しており、Anthropicがオープンソースコードを対象に展開しているModel for Good系の取り組みと並んで、AIを防御側のアシスタントとして活用する流れが加速している。

**出典**: [JFrog: PixelSmash CVE-2026-8461](https://jfrog.com/blog/pixelsmash-critical-ffmpeg-vulnerability-turns-media-files-into-weapons/) / [SecurityWeek: FFmpeg PixelSmash](https://www.securityweek.com/ffmpeg-pixelsmash-flaw-allows-rce-on-video-players-media-servers-nas-appliances/) / [BleepingComputer: FFmpeg fixes PixelSmash](https://www.bleepingcomputer.com/news/security/ffmpeg-fixes-pixelsmash-flaw-in-widely-used-video-decoder/)

### Squidbleed緊急対応ガイド & FortiBleed確認フロー（2026-06-24）

```bash
# ============================================================
# 2026-06-24 セキュリティ緊急チェックリスト
# ============================================================

# ---- [1] Squidbleed (CVE-2026-47729) — Squid Proxy ヒープオーバーリード ----
# 影響: Squid 7.5以前 / 8系列の一部（FTPパーサー、デフォルト設定で発動）
# リスク: 共有プロキシ環境で別ユーザーのHTTPリクエスト内容が読み取られる

# Squidバージョン確認
squid -v 2>&1 | head -2

# 修正済みバージョン: 7.6 以上 または 8.x パッチ済み
# Ubuntu/Debian
sudo apt update && sudo apt install --only-upgrade squid

# 緩和策: FTPプロキシ機能を使用しない場合は無効化
# /etc/squid/squid.conf に追記:
#   ftp_list_width 0
#   acl FTP proto FTP
#   http_access deny FTP
sudo systemctl reload squid

# ---- [2] FortiBleed — Fortinet FortiGate / SSL VPN 認証情報流出確認 ----
# 影響: CVSSスコア未発番の進行中キャンペーン（2026年2月〜）
# 規模: 194カ国 86,644台の機器で認証情報が検証済みリストに掲載

# FortiOSバージョン確認 (CLIから)
# get system status | grep "Version"
# 最新のFortiOS 7.6パッチを適用しているかを確認

# 侵害確認: SOCRadar / BitSight から提供されているIOCリストとの照合
# https://www.bitsight.com/blog/security-alert-fortibleed-fortinet-vpn-credentials-firewall-exposed

# 優先対応手順:
# 1. FortiGate管理者パスワードの即時ローテーション
# 2. SSL VPN接続ログのアノマリ確認（異常な送信元IP・時間外接続）
# 3. FortiOSを最新にアップデート
# 4. MFA（多要素認証）が未設定の場合は即時有効化

# ---- [3] FFmpeg PixelSmash (CVE-2026-8461 / CVSS 8.8) ----
# 影響: FFmpeg 8.1.1以前を組み込むすべてのアプリ
# 対処: FFmpeg 8.1.2へ更新（詳細は「新技術・新リリース」セクション参照）

echo "=== 本日の優先対応サマリー ==="
echo "Squidbleed CVE-2026-47729 : Squid Proxy ヒープオーバーリード → 7.6以上へ更新"
echo "FortiBleed キャンペーン   : 86,644台侵害確認済み → パスワードローテーション＋MFA"
echo "PixelSmash CVE-2026-8461  : FFmpeg CVSS 8.8 → 8.1.2へ更新"
```

**Squidbleed**の技術的特徴として注目すべきは、脆弱性の根本がFTPプロトコル実装の境界チェック欠如であり、ほとんどの組織がFTPプロキシを積極利用していない中でもデフォルト設定でFTPパーサーが有効になっているケースが多いことだ。AIモデルが三十年間見過ごされてきたコードのバグを発見したという事実は、AIを用いたコードセキュリティ解析の実用性を示す好例として業界に広く引用されることになるだろう。**FortiBleed**については、単発の脆弱性悪用ではなく「長期間・組織的な認証情報収集キャンペーン」という性質を持つため、影響範囲の特定と認証情報のローテーションが緊急対応の核心となる。
