### 2. Microsoft、Exchange Server 緊急パッチ配布 — CVE-2026-42897（CVSS 9.8）OWA 経由の認証前 RCE がすでに実環境悪用中

6 月 9 日、Microsoft は Exchange Server の **Patch Tuesday** 外緊急アップデートを配布し、**CVE-2026-42897**（CVSS **9.8**・Critical）を修正した。この脆弱性は Outlook Web Access（OWA）コンポーネントに存在する**認証前リモートコード実行（pre-auth RCE）**で、攻撃者は細工した電子メール 1 通を送り付けるだけでサーバー上でコードを実行できる。影響対象は Exchange Server 2016・2019・Subscription Edition（オンプレミスのみ。Exchange Online は非影響）で、攻撃の複雑度は**低（Low）**と評価されており、認証不要・利用者操作不要という極めて悪用しやすい条件が揃っている。CISA は同日 CVE-2026-42897 を**既知悪用脆弱性（KEV）カタログ**へ追加し、連邦機関に対して **7 月 1 日**までのパッチ適用を義務付けた。OWA をインターネットへ直接公開しているサーバーは即時の更新が必要で、パッチ適用前の暫定緩和策として URL 書き換えルール（所要 5 分以内）が提供されている。Exchange 2016/2019 は Extended Security Update（ESU）プログラムへの登録がパッチ受領の条件となるため、未登録組織は即時の ESU 申請も求められる。

6 月 2 日にトランプ大統領が署名した大統領令「**Promoting Advanced Artificial Intelligence Innovation and Security**」の全容が各所で分析され、AI 規制の国際競争が一段と鮮明になってきた。同令は米国の AI 主導権確立を柱に据えつつ、①民間・連邦機関横断の**AI サイバーセキュリティクリアリングハウス**設置、②フロンティアモデルへの政府早期アクセスを含む**自発的審査フレームワーク**整備、③**強制ライセンス制度の明示的禁止**という 3 点を規定する。「規制よりイノベーション」という姿勢は欧州と対照的で、EU の AI 法（AI Act）では**高リスク AI への義務**が 8 月 2 日から順次発効する。米国内でも**コロラド州消費者 AI 保護法**が 6 月 30 日に施行予定（全米初の包括的州法）であり、議会では**Great American AI Act**（269 ページ）の審議が続く。「連邦法で州法を 3 年間停止」という条項を巡っては各州が反発しており、米国内の AI 規制の断片化が深刻化しつつある。グローバルに展開する企業にとっては米国・EU・州レベルの三重基準への対応が避けられない状況だ。

### Claude Foundation Models — Apple プラットフォーム向け Swift パッケージで型安全 AI 統合が実現

Fable 5 / Mythos 5 のリリースと同日、Anthropic は Apple の **Foundation Models フレームワーク**をサポートする新しい **Swift パッケージ**を公開した。iOS/macOS アプリから Claude を呼び出す際に、型付き Swift の出力をそのまま Claude へ渡してマルチステップ推論・コード生成・Web 検索・コード実行・SwiftUI でのストリーミングレスポンスをシームレスに扱えるようになる。SwiftUI の Observation フレームワークとの統合も提供されており、`@Observable` なビューモデルにストリーミングレスポンスを直接バインドできる設計となっている。

```swift
// Claude Foundation Models Swift パッケージ利用例（教育目的サンプル）
import ClaudeAI
import Foundation

// 型安全なレスポンス定義
struct AnalysisResult: Codable {
    let summary: String
    let keyPoints: [String]
    let confidence: Double
}

// Claude Fable 5 へのマルチステップ推論リクエスト
@Observable
class DocumentAnalyzer {
    var result: AnalysisResult?
    var isStreaming = false

    private let client = ClaudeClient(model: .fable5)

    func analyze(document: String) async throws {
        isStreaming = true
        defer { isStreaming = false }

        // 型付き出力の指定
        result = try await client.generate(
            prompt: "次のドキュメントを分析し、要約・要点・信頼度を返してください:\n\(document)",
            responseType: AnalysisResult.self,
            options: .init(
                maxTokens: 2048,
                contextPolicy: .ephemeral  // クエリはリクエスト後に破棄
            )
        )
    }
}

// SwiftUI ビューでのバインド
struct AnalysisView: View {
    @State private var analyzer = DocumentAnalyzer()

    var body: some View {
        Group {
            if analyzer.isStreaming {
                ProgressView("分析中...")
            } else if let result = analyzer.result {
                VStack(alignment: .leading, spacing: 12) {
                    Text(result.summary).font(.body)
                    ForEach(result.keyPoints, id: \.self) { point in
                        Label(point, systemImage: "checkmark.circle")
                    }
                    Text("信頼度: \(Int(result.confidence * 100))%")
                        .foregroundStyle(.secondary)
                }
            }
        }
        .task { try? await analyzer.analyze(document: sampleDocument) }
    }
}
```

Apple プラットフォームで Claude を直接組み込んだアプリ開発のハードルが大幅に下がり、WWDC 2026 で発表された Apple Intelligence Extensions との共存という形で iOS 27 エコシステムへの Claude 統合が加速しそうだ。

### CVE-2026-42897 — Exchange OWA 認証前 RCE・CVSS 9.8・CISA KEV 登録、パッチ適用と URL 書き換え緩和策を急げ

**CVE-2026-42897** の深刻さは CVSS スコア 9.8 という数字に加え、「**認証不要・メール 1 通で即座に RCE**」という攻撃経路のシンプルさにある。OWA をインターネットに公開している組織では、攻撃者が公開 IP を探索してメールを送るだけで侵害が完了する。過去の Exchange RCE（ProxyLogon 等）は公表から 24〜48 時間以内に大規模スキャンが始まった前例があり、今回も同様のタイムラインを想定すべきだ。パッチが最優先だが、適用までの時間を稼ぐ URL 書き換え緩和策（5 分で適用可能）を先行させることが推奨されている。

```powershell
# --- CVE-2026-42897 緊急対応チェックリスト ---

# 1. 影響バージョンの確認
Get-ExchangeDiagnosticInfo -Server $env:COMPUTERNAME -Process EdgeTransport `
    -Component ResourceThrottling -Settings LoggingLevel

# 現行の CU / SU バージョンを確認
Get-Command Exsetup.exe | ForEach-Object { $_.FileVersionInfo }

# 2. OWA がインターネット公開されているか確認
#    IIS バインディングを確認（443 が外部 IP に bind されていないか）
Import-Module WebAdministration
Get-WebBinding -Name "Default Web Site" | Select-Object bindingInformation

# 3. URL 書き換えルール（緩和策）の適用 — パッチ適用まで先行して実施
#    Microsoft 公式 OWA Mitigation Script を使用
# https://aka.ms/CVE-2026-42897-OWA-Mitigation
.\OWA-Mitigation.ps1 -Apply

# 4. ESU 登録状況の確認（Exchange 2016/2019 の場合）
#    未登録の場合はパッチを受け取れないため即時申請
# https://learn.microsoft.com/exchange/new-features/extended-security-updates

# 5. 侵害インジケーター（IoC）の確認
#    OWA アクセスログで不審なリクエストパターンを検索
Get-EventLog -LogName Application -Source MSExchange* -Newest 500 |
    Where-Object { $_.EntryType -eq "Error" } |
    Select-Object TimeGenerated, Message |
    Format-List

# 6. パッチ適用後の検証
Test-OwaConnectivity -MailboxServer $env:COMPUTERNAME
```

**優先度**: 最高。CISA KEV 登録・連邦機関パッチ期限 2026-07-01。OWA をインターネット公開している Exchange オンプレミス環境は本日中の対応が必須。
