### Python 3.15.0b4 最終ベータ到着・PEP 836がJITの6ヶ月クロックに応答

Python 3.15の最終予定ベータ（b4）が**7月18日にクラクフから出荷**され、b3以来約298件のバグ修正・ビルド改善・ドキュメント修正が含まれる。最大の焦点はJITの行方だ。CPython Steering Councilが6月に「JITには標準PEPプロセスが必要」として6ヶ月のクロックをスタートさせたのに対し、Savannah Ostrowski・Brandt Bucher・Ken Jinが**PEP 836「JIT Go Brrr」**で応答した。PEP 836はPython 3.17時点で「JIT＋フリースレッディング有効時に幾何平均20%以上の高速化」という定量目標を設定し、ツーリング対応・プラットフォームサポート・長期メンテナンス担当の明確化を約束している。現在JITはまだ「実験的」でデフォルト無効だが、承認されれば3.17以降の正式機能になる道が開ける。

```bash
# Python 3.15b4 で JIT を明示的に有効化してベンチマーク比較
python3.15 --enable-jit -c "
import timeit

def fib(n):
    if n < 2:
        return n
    return fib(n-1) + fib(n-2)

t = timeit.timeit(lambda: fib(30), number=10)
print(f'JIT enabled  — fib(30) x10: {t:.4f}s')
"

python3.15 -c "
import timeit

def fib(n):
    if n < 2:
        return n
    return fib(n-1) + fib(n-2)

t = timeit.timeit(lambda: fib(30), number=10)
print(f'JIT disabled — fib(30) x10: {t:.4f}s')
"
```

```python
# PEP 836 が 3.17 で目指すターゲット（概念確認スクリプト）
import sys

jit_on = getattr(sys, '_jit_enabled', lambda: False)()
gil_off = not getattr(sys.flags, 'gil_enabled', True)

print(f"JIT enabled:      {jit_on}")
print(f"Free threading:   {gil_off}")
# 目標: 両方 True の状態で幾何平均 +20% speedup (vs 3.17 without JIT + free-threading)
```

### SimpleHelp CVE-2026-48558（CVSS 10.0）——OIDC署名検証欠落でMSPサプライチェーン攻撃が継続

リモートモニタリング・管理（RMM）ツールの**SimpleHelp**に発見された**CVE-2026-48558**（CVSS 10.0・満点）の悪用が7月に入っても継続している。根本原因はOpenID Connect（OIDC）トークンの署名を検証しない実装上の欠陥（CWE-347）だ。OIDCグループ認証が有効な環境では、未認証の攻撃者が任意のIDクレームを含む偽造トークンを送信するだけで、多要素認証を迂回して技術者（Technician）レベルの特権セッションを取得できる。CISAは6月29日に本脆弱性をKEV（既知悪用済み脆弱性カタログ）へ追加し修復期限を7月2日と設定したが、パッチ未適用のサーバーが依然残存しており、**Djinn Stealer**マルウェアの配送に悪用されている。MSP（マネージドサービスプロバイダー）経由でダウンストリームの顧客環境まで侵害が連鎖するサプライチェーン攻撃のベクターとして機能している点が特に深刻だ。

```text
=== CVE-2026-48558 SimpleHelp 対応チェックリスト ===

[影響条件]
  SimpleHelp 5.x (< 5.5.16) かつ OIDC グループ認証を有効化している場合
  SimpleHelp 6.x (< 6.0 RC2)

[攻撃の流れ]
  1. 攻撃者が署名なし偽造 OIDC トークンを送信
  2. SimpleHelp サーバーが署名検証をスキップして受理
  3. 任意の Technician アカウントとしてセッション確立
  4. リモートアクセス・ファイル転送・管理操作が可能に
  5. Djinn Stealer を展開 → クレデンシャル窃取・横展開

[修復手順]
  1. SimpleHelp 5.5.16 または 6.0 RC2 以上へアップグレード（最優先）
  2. CISA KEV 登録済み（2026-06-29）— 7/2 期限を超過している場合は即時対応
  3. OIDC 経由の不審なセッション確立ログを精査
  4. 管理対象エンドポイントで Djinn Stealer の痕跡をスキャン
  5. MSP 経由で管理する顧客環境まで影響範囲を拡大して確認
```

Microsoft 7月Patch Tuesdayで修正されたCVE-2026-57092（VMSwitch CVSS 9.9）とあわせ、今月は「RMMツールを踏み台にしたサプライチェーン攻撃」「低権限からVM境界を越えた特権昇格」という2つのパターンが実際の攻撃で観測されており、インフラ管理ツール自体のパッチ管理・監査体制の見直しが急務となっている。
