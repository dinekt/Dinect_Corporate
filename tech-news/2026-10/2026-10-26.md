### 全二重音声エージェントの割り込みを時系列ログで受け入れ試験する

#### 目的

全二重音声エージェントでは、人とAIが同時に話せるだけでなく、短い相づちを会話継続として扱い、本当の割り込みではAIの発話を素早く止める必要がある。音声の自然さだけを試聴しても、誤停止、割り込み無視、停止後の音声残りは見落としやすい。そこで、ユーザー発話開始、割り込み判定、AI音声停止を時系列イベントとして記録し、会話パターンごとの合否を再現可能にする。

#### 対象・前提

対象は、コールセンター、受付、音声アシスタントなど、AIの発話中にも利用者の音声を受け付けるシステムである。以下はPython 3.12標準ライブラリだけを使う一般化した構成例で、実際の音声認識やDessaは呼び出さず、収集済みイベントを検査する。実装側には音声区間検出、再生停止機構、単調増加時計、セッションID付きログが必要である。停止時間の基準は製品、ネットワーク、業務リスクに応じて事前に決め、ここでは構成例として250ミリ秒を採用する。

#### 手順

まず、AIの発話中にユーザーが短く「はい」と相づちを打つケースと、「待って、違います」と訂正するケースを用意する。各ケースで`user_speech_start`、音響判定の`classified`、再生停止の`assistant_stop`を同じ時刻基準で記録する。相づちは基準時間内に停止しないこと、本当の割り込みは基準時間内に停止することを別の条件として検査する。実環境では背景雑音、複数話者、通信遅延、言語、声量を変えた録音を評価セットへ加える。

以下の最小例は、相づちでは発話が継続し、割り込みではユーザーの発話開始から180ミリ秒で停止したログを検査する。

```python
MAX_STOP_MS = 250

sessions = {
    "backchannel": [
        (0, "assistant_start", None),
        (800, "user_speech_start", None),
        (880, "classified", "backchannel"),
        (2000, "assistant_stop", None),
    ],
    "barge_in": [
        (0, "assistant_start", None),
        (1000, "user_speech_start", None),
        (1070, "classified", "interruption"),
        (1180, "assistant_stop", None),
    ],
}

def evaluate(events):
    by_name = {name: ms for ms, name, _ in events}
    kind = next(value for _, name, value in events if name == "classified")
    start = by_name["user_speech_start"]
    stop = by_name["assistant_stop"]
    latency = stop - start
    if kind == "backchannel":
        return "PASS continued" if latency > MAX_STOP_MS else "FAIL false_stop"
    return (
        f"PASS stop_latency_ms={latency}"
        if 0 <= latency <= MAX_STOP_MS
        else f"FAIL stop_latency_ms={latency}"
    )

for session_id, events in sessions.items():
    print(session_id, evaluate(events))
```

期待する出力は`backchannel PASS continued`と`barge_in PASS stop_latency_ms=180`である。製品ログへ適用するときは、判定前に停止した、停止イベントがない、イベント時刻が逆転した、といった欠損も失敗にし、音声録音への参照IDを残して人が再確認できるようにする。

#### 確認方法

上のコードは標準Python 3.12で実行し、記載した2行の出力になることを確認する。Dessa、LiveKit、実在する通話環境では未実行であり、180ミリ秒は製品性能の測定値ではなく構成例の入力である。本番では、真の割り込みを正しく止めた割合、相づちを誤って止めた割合、停止遅延の中央値と上位パーセンタイル、停止後に再生された音声長を測る。LiveKitの公式資料も、相づちと真の割り込みを分け、割り込み判定遅延をメトリクスとして取得する構成を示している。

#### 注意点

音声区間検出だけで止めると、咳、環境音、短い相づちで誤停止しやすい一方、意味判定を待ちすぎると訂正を無視したように感じられる。緊急通報、医療、金融、本人確認では音声エージェントだけで完結させず、人への切り替えと明示的な再確認を設ける。録音や声質は個人情報になり得るため、収集目的、同意、保存期間、アクセス権、削除手順を定め、評価ログには必要最小限の参照情報だけを残す。全二重処理は入力と出力を常時扱うため計算・通信コストが増え、ローカル実行でも端末性能、発熱、消費電力、モデル更新方法が適用限界になる。

## まとめ

- 全二重音声は自然さだけでなく、相づちの誤停止率と真の割り込み停止時間を分けて評価する。
- ユーザー発話、判定、再生停止を同じ時刻基準で記録し、録音参照とともに再現可能にする。
- 高リスク業務では人への切り替えを用意し、録音の同意・保存・削除を先に設計する。
