### 2. EU AI Act デジタルオムニバス、本日の最終三者協議で高リスク義務の実施期限が決定へ

EU の AI 法（AI Act）高リスク AI システム義務の 2026 年 8 月 2 日実施期限を延期するか否かが、本日（4 月 28 日）の政治的三者協議（トライローグ）で決まる見通しとなった。欧州委員会が 2025 年 12 月に提案した「デジタルオムニバス」パッケージでは、付属書 III（スタンドアロン型高リスク AI）の期限を 2027 年 12 月 2 日、付属書 I（規制対象製品への組み込み AI）の期限を 2028 年 8 月 2 日に延期する案が盛り込まれており、欧州議会・EU 理事会の双方がこの延期方向に収束している。最大の焦点は、EU 製品安全規制の適用を受ける組み込み AI システムを AI 法のスコープから除外するかどうかで、産業界は強く支持する一方、理事会側は慎重な姿勢を崩していない。米国はライト規制路線を維持しており、EU と米国の「AI 規制の大西洋分断」が深まりつつある中、今日の協議結果は日本・ASEAN 諸国など EU の規制モデルを参照する地域の政策立案にも影響を与える。

### 3. LMDeploy CVE-2026-33626 — AI インフラを狙う SSRF、公開後 13 時間未満で実環境悪用

オープンソースの LLM デプロイツールキット「LMDeploy」（バージョン 0.12.0 以前）に高深刻度の SSRF 脆弱性 CVE-2026-33626（CVSS 7.5）が発見され、GitHub への開示から 12 時間 31 分後にはハニーポット環境への攻撃が確認された。`lmdeploy/vl/utils.py` 内の `load_image()` 関数がプライベート IP アドレスの検証なしに任意の URL を取得するため、攻撃者はモデルサーバー背後のクラウドメタデータサービス（AWS IMDS）・内部 Redis/MySQL・管理インターフェースに到達できる。実際の攻撃では 8 分間のセッションで内部ネットワークポートスキャン・AWS IMDS アクセス・OOB DNS 外部通信が確認されており、AI インフラが公開と同時に標的になる速度は従来の OSS 脆弱性を大きく上回っている。マルチモーダル LLM の普及で画像ローダーが汎用 HTTP プロキシとして悪用される新しい攻撃ベクターとして注目されており、ビジョン言語モデルを運用するすべての環境での早急な対応が求められる。

**出典**: [The Hacker News — LMDeploy CVE-2026-33626 Flaw Exploited Within 13 Hours of Disclosure](https://thehackernews.com/2026/04/lmdeploy-cve-2026-33626-flaw-exploited.html) / [Vulert — LMDeploy CVE-2026-33626 SSRF Exposes AI Infrastructure](https://vulert.com/blog/lmdeploy-cve-2026-33626-ssrf/)

## 新技術・新リリース

### Rust 1.83 — async closures が安定版へ、非同期コードの人間工学的課題をついに解消

Rust 1.83 で async closures（`async || { ... }`）が安定版として導入され、async/await 以来最大の人間工学的改善と呼ばれている。従来は `async move` ブロックを通常のクロージャーでラップする回避策が一般的だったが、ライフタイム管理が煩雑になり可読性を損なっていた。安定化により `Stream::then` など非同期イテレーターのコンビネーターに async クロージャーを直接渡せるようになり、データパイプラインのコードが大幅に簡潔になる。合わせて Rust Foundation が金融・ヘルスケア・航空などの規制産業をターゲットとした最初のエンタープライズ認定プログラムを発表しており、Rust の安全保証を制度的に担保するエコシステム整備が本格化している。

```rust
use futures::StreamExt;

// Rust 1.83 以前: async move ブロックを通常クロージャーで包む回避策が必要だった
// let process = |item: &str| {
//     let item = item.to_owned();
//     async move { item.to_uppercase() }
// };

// Rust 1.83 以降: async クロージャーを直接記述できる
let process = async |item: &str| -> String {
    tokio::time::sleep(std::time::Duration::from_millis(10)).await;
    item.to_uppercase()
};

let items = vec!["hello", "world", "rust"];
let results: Vec<String> = futures::stream::iter(items)
    .then(process)  // async クロージャーを Stream::then に直接渡せる
    .collect()
    .await;

println!("{:?}", results);
// ["HELLO", "WORLD", "RUST"]
```

### CVE-2026-32202 — Windows Shell ゼロクリック NTLMv2 ハッシュ漏洩、SMB 経由で悪用中

Microsoft が 4 月 27 日に緊急勧告を発行した CVE-2026-32202 は Windows Shell のなりすまし脆弱性で、細工した SMB リクエストへのゼロクリック認証を誘発することで被害者の NTLMv2 ハッシュを攻撃者のサーバーへ送信させる。取得したハッシュはオフラインクラックや Pass-the-Hash 攻撃に利用でき、認証なしでのネットワーク内ラテラルムーブメントが可能になる。特にファイル共有・プリントスプール・Active Directory 環境が影響を受けやすく、4 月の Windows Update 適用と SMB 外部通信のブロックが緊急の緩和策となる。

**出典**: [The Hacker News — Microsoft Confirms Active Exploitation of Windows Shell CVE-2026-32202](https://thehackernews.com/2026/04/microsoft-confirms-active-exploitation.html)

### Fortinet CVE-2026-35616（CVSS 9.1）— FortiClient EMS の権限昇格、3 月末から悪用継続

Fortinet が FortiClient EMS バージョン 7.4.5〜7.4.6 に影響する CVE-2026-35616（CVSS 9.1）にパッチを提供した。この脆弱性は 2026 年 3 月 31 日から継続的に悪用されており、攻撃者がエンドポイント管理サーバーの管理者権限を取得できる。FortiClient EMS はエンドポイントセキュリティの中枢に位置するため、侵害された場合は管理下にある全エンドポイントへの設定変更・マルウェア展開が可能になる。影響バージョンを使用している場合は即時パッチ適用が強く推奨される。

**出典**: [The Hacker News — Fortinet Patches Actively Exploited CVE-2026-35616 in FortiClient EMS](https://thehackernews.com/2026/04/fortinet-patches-actively-exploited-cve.html)
