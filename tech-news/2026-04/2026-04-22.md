## 新技術・新リリース

### CPython に Rust コードが初統合へ — Python 3.16（2027年10月予定）がターゲット
Python 公式ブログ「Python Insider」が4月22日、「Rust for CPython Progress Update April 2026」を公開した。最大のマイルストーンは、CPython の CI 上で全プラットフォーム（Linux x86/ARM、macOS、Windows）に渡って Rust コードのビルドが成功したことだ。ターゲットバージョンは当初 Python 3.15 から **Python 3.16**（2027年10月リリース予定）へ変更された。

**ロードマップ（抜粋）:**
- 2026年4月: 内部向け Rust API 設計開始（今月）
- 2026年6〜7月: PEP ドラフト公開
- 2027年5月: Python 3.16 Beta 1（Rust コード含む初の公式ビルド）
- 2027年10月: Python 3.16 正式リリース

**設計方針:**
- 初期は**オプション拡張モジュール**のみ Rust で実装 — Rust コンパイラは CPython のビルド・実行に不要
- `cpython-sys` クレートで C/Rust 境界をブリッジ、`bindgen` が CPython の C ヘッダーから Rust バインディングを自動生成
- Cargo の vendor 機能により、全 Rust 依存ライブラリを CPython ソースに同梱
- 最初の実装対象として `base64` モジュールが有力候補（純粋な C ロジック → Rust 置換でネイティブ性能向上）

```rust
// CPython 拡張モジュールの Rust 実装例（将来のイメージ）
use pyo3::prelude::*;

#[pyfunction]
fn b64encode(data: &[u8]) -> String {
    use base64::Engine as _;
    base64::engine::general_purpose::STANDARD.encode(data)
}

#[pymodule]
fn _base64_rs(m: &Bound<'_, PyModule>) -> PyResult<()> {
    m.add_function(wrap_pyfunction!(b64encode, m)?)?;
    Ok(())
}
```

この変更は「Rust コンパイラが必要になる」「既存の C 拡張との互換性が壊れる」といった懸念を回避しつつ、メモリ安全性と性能向上を段階的に取り込む慎重なアプローチを取っている。PyCon US 2026 でも本トピックのセッションが予定されており、コミュニティの注目度は高い。

## セキュリティ

### OAuth2 Proxy に認証バイパス脆弱性 CVE-2026-40575（CVSS 9.1）— 即時 v7.15.2 へ更新を
OAuth2 認証リバースプロキシとして広く使われる **OAuth2 Proxy** に、認証を完全にバイパスできるクリティカル脆弱性が公開された（CVE-2026-40575、CVSS 9.1）。

**技術的詳細:**
攻撃者が `X-Forwarded-Uri` ヘッダーを細工することで、OAuth2 Proxy が `--skip_auth_routes` / `--skip-auth-regex` ルールの評価を「偽パス」に対して行い、実際のリクエストパスへの認証をスキップさせることができる。認証不要のリモートアクセスが可能になるため、CVSS スコアは最高ランクに近い 9.1。

**影響バージョン:** v7.5.0 〜 v7.15.1  
**修正バージョン:** v7.15.2（即時更新推奨）

**緩和策（アップグレードが困難な場合）:**
```yaml
# nginx 設定例: クライアントからの X-Forwarded-Uri を除去
proxy_set_header X-Forwarded-Uri $request_uri;  # 実際の URI で上書き
# または
more_clear_input_headers "X-Forwarded-Uri";     # ヘッダーを剥奪
```

```bash
# OAuth2 Proxy v7.15.2 へのアップグレード
docker pull quay.io/oauth2-proxy/oauth2-proxy:v7.15.2

# Helm 利用の場合
helm upgrade oauth2-proxy oauth2-proxy/oauth2-proxy \
  --set image.tag=v7.15.2 \
  --set config.trustedProxyIPRanges="10.0.0.0/8"  # --trusted-proxy-ip の設定も推奨
```

Kubernetes の Ingress 認証・GitLab Pages の OAuth 保護・内部ダッシュボードのアクセス制御など、OAuth2 Proxy を認証フロントとして使っているシステムは直ちに影響を確認すること。Belgium CCB（サイバーセキュリティセンター）も独自勧告を発行している。
