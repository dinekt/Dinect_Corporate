### 1. Ollama「Bleeding Llama」(CVE-2026-7482 / CVSS 9.1) — 30万台の AI サーバーがヒープメモリ漏洩リスクに晒される

セキュリティ企業 Cyera が「**Bleeding Llama**」と命名した Ollama の重大脆弱性 **CVE-2026-7482**（CVSS 9.1）が、世界中の AI 開発者コミュニティで大きな話題を呼んでいる。脆弱性は Ollama の GGUF モデルローダーに存在するヒープ境界外読み取り（heap out-of-bounds read）で、**認証なし**かつ **API 呼び出し 3 回**だけでプロセスのヒープメモリ全体を外部サーバーへ漏洩できる。ローカル環境でロードされた全モデルのシステムプロンプト・ユーザーの会話履歴・環境変数に含まれる API キーや秘密鍵・AIモデルに送付された顧客データやソースコードまでが窃取対象となる。攻撃はログに一切エラーを残さないため、専用のエンドポイント監視なしには事実上検知不可能だ。Shodan による集計ではインターネット公開中の Ollama インスタンスは約 **30 万台**とされており、影響規模は AI インフラ史上最大クラスの脆弱性と言える。パッチは **Ollama v0.17.1**（2026 年 2 月 25 日リリース）で提供されているが、リリースノートにセキュリティ修正の記載がなかったため更新が遅れた環境が多数残存している。

## 新技術・新リリース

### Python フリースレッディング (PEP 703) が 2026 年に実用段階へ — GIL なし並列処理と「ty」型チェッカーが開発現場を変える

長年 Python の並列処理を制約してきた **GIL（Global Interpreter Lock）** の無効化が 2026 年の開発現場でいよいよ本格普及フェーズに入った。Python 3.13 以降で試験的に提供されていた GIL 無効化ビルド（`python3.13t`）の安定性が向上し、CPU バウンドな処理での真の並列実行が現実的な選択肢となっている。

```python
# GIL 無効化ビルドでの真のマルチスレッド並列実行
# python3.13t または PYTHON_GIL=0 環境変数で GIL を無効化
import threading
import sys

# GIL の状態を確認
print(f"GIL enabled: {sys._is_gil_enabled()}")  # False なら無効化済み

def cpu_heavy(n: int) -> int:
    total = 0
    for i in range(n):
        total += i * i
    return total

# GIL なし環境では複数スレッドが CPU コアを並列利用できる
threads = [threading.Thread(target=cpu_heavy, args=(10_000_000,)) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

また、`uv` や `ruff` を開発した Astral チームが新たな Python 型チェッカー **「ty」** を公開した。既存の `mypy` や `pyright` と比較して数十倍高速で、大規模コードベースでも数秒以内に型検査を完了できる。Django 6 のリリースと相まって、Python の開発者体験は 2026 年に大きなアップグレードを迎えている。

**出典**: [Python: What's Coming in 2026 — The New Stack](https://thenewstack.io/python-whats-coming-in-2026/) / [Python starts 2026 with a bang — InfoWorld](https://www.infoworld.com/article/4114529/python-starts-2026-with-a-bang.html)

## セキュリティ

### Ollama Bleeding Llama — 即時対応チェックリスト

CVE-2026-7482 の影響を受ける Ollama v0.17.0 以前を使用している場合、以下の手順で対処する。

```bash
# 1. 現在の Ollama バージョンを確認
ollama --version

# 2. インターネット公開状態を確認（0.0.0.0 でバインドされていないか）
ss -tlnp | grep 11434
# LISTEN 0 128 0.0.0.0:11434 ... → 外部公開中（危険）
# LISTEN 0 128 127.0.0.1:11434 ... → ローカル限定（安全）

# 3. ローカルホスト限定に設定する (systemd 環境)
# /etc/systemd/system/ollama.service.d/override.conf
[Service]
Environment="OLLAMA_HOST=127.0.0.1"

systemctl daemon-reload && systemctl restart ollama

# 4. 外部公開が必要な場合は認証プロキシを前段に配置
# nginx 例（Basic 認証 + IP 制限）
# location / {
#   allow 10.0.0.0/8;
#   deny all;
#   auth_basic "Ollama";
#   auth_basic_user_file /etc/nginx/.htpasswd;
#   proxy_pass http://127.0.0.1:11434;
# }

# 5. パッチ適用: v0.17.1 以上にアップデート
curl -fsSL https://ollama.com/install.sh | sh
```

ログに痕跡が残らないため、**既に攻撃を受けた可能性がある**場合は Ollama プロセスが参照できる環境変数（API キー類）を全て即時ローテーションすることを推奨する。

**出典**: [Bleeding Llama (CVE-2026-7482): Critical Unauthenticated Memory Leak in Ollama — Security Boulevard](https://securityboulevard.com/2026/05/bleeding-llama-cve-2026-7482-critical-unauthenticated-memory-leak-in-ollama/)

### Microsoft Exchange Server CVE-2026-42897 — XSS 起因のゼロデイ、野外悪用を確認

Microsoft がオンプレミス Exchange Server（Subscription Edition / 2016 / 2019）に影響する **CVE-2026-42897**（CVSS 8.1）を開示した。XSS を起因とするスプーフィング脆弱性で、**すでに野外での悪用が確認**されており、攻撃者は細工したリンクをメールで送付することで受信者のブラウザ上で任意スクリプトを実行し、Exchange 認証セッションを乗っ取ることができる。Exchange Online（クラウド版）は影響を受けない。Outlook Web App（OWA）を外部公開しているオンプレミス運用組織は特に危険度が高く、Microsoft が提供するパッチの即時適用が必要だ。5 月 13 日の Patch Tuesday（118 件修正）とは別の追加開示であり、5 月第 3 週は Cisco SD-WAN KEV に続く重大脆弱性の連続開示となっている。
