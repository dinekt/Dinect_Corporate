### 1. Palo Alto PAN-OS に CVSS 9.3 の未認証 RCE 脆弱性 CVE-2026-0300 — パッチは 5 月 13 日予定

Palo Alto Networks のファイアウォール OS「PAN-OS」の User-ID 認証ポータル（Captive Portal）にバッファオーバーフロー脆弱性 **CVE-2026-0300**（CVSS 9.3）が発見され、5 月 6 日に CISA の KEV（既知悪用済み脆弱性）カタログへ追加された。認証不要でリモートから root 権限での任意コード実行が可能という深刻な内容で、攻撃者は nginx ワーカープロセスへのシェルコード注入後に即座にログを削除して痕跡を隠滅する手口が確認されている。4 月 9 日頃から断続的な攻撃試行が記録されており、1 週間後には実際の RCE が成功した事例が報告された。ファーストパーティの修正パッチは 5 月 13 日リリース予定であり、それまでの間は User-ID 認証ポータルをインターネット非公開にするか無効化することが最優先の緩和策とされている。PA-Series および VM-Series ファイアウォールが対象で、Cloud NGFW と Panorama は影響を受けない。

## 新技術・新リリース

### Python 3.14 RC1 — GIL 廃止による真の並列実行と JIT コンパイラを同梱

Python 3.14 の最初のリリース候補（3.14.0rc1）が公開された（正式リリースは 2026 年 10 月予定）。最大の目玉は **フリースレッド CPython**（PEP 703）の正式サポートで、長年の制約だったグローバルインタープリタロック（GIL）がマルチコアワークロードで不要となり、真の並列 Python 実行が実現する。加えて macOS・Windows 公式ビルドに実験的 JIT コンパイラが同梱され、数値計算・データパイプライン系の処理で顕著な速度向上が期待される。

```python
# Python 3.14: フリースレッド CPython でのマルチスレッド並列実行例
# python3.14t (free-threaded ビルド) で実行する
import threading

results = []

def cpu_bound(n):
    # GIL 無しで真に並列実行される
    total = sum(i * i for i in range(n))
    results.append(total)

threads = [threading.Thread(target=cpu_bound, args=(10_000_000,)) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()

print(f"計算結果: {len(results)} 件完了")

# JIT の恩恵が大きいホットループの例
def tight_loop(n: int) -> int:
    acc = 0
    for i in range(n):
        acc += i
    return acc

print(tight_loop(100_000_000))  # 3.14 JIT で大幅高速化
```

フリースレッドビルドは通常ビルドとは別バイナリ（`python3.14t`）で提供されるため、既存コードとの互換性を保ちながら段階的移行が可能。科学計算・Web スクレイピング・データパイプラインなど I/O ではなく CPU がボトルネックのユースケースで特に効果が見込まれる。

**出典**: [Python 3.14 slithers closer with RC1 arrival — Developer Tech](https://www.developer-tech.com/news/python-3-14-slithers-closer-with-rc1-arrival/)

## セキュリティ

### CVE-2026-0300 の緩和策 — Palo Alto PAN-OS パッチ前の即時対応手順

パッチリリース（5 月 13 日予定）までの間に実施すべき緩和策を整理する。攻撃ベクタとなる User-ID 認証ポータルのインターネット公開を遮断することが最優先だ。

```bash
# PAN-OS バージョン確認（SSH 接続後）
show system info | match sw-version

# 管理インターフェースのアクセス制限（推奨: 管理専用インターフェースからのみ許可）
# GUI: Device > Setup > Management > Management Interface Settings
# 公開 IP からのアクセスを遮断し、管理 VLAN のみに制限する

# Captive Portal / User-ID が有効かどうかを確認
show user user-id-agent state all

# ログの異常を確認（nginxクラッシュ、コアダンプが消去されていないか）
show system logs | match nginx
show system logs | match core

# Panorama で全デバイスの状態を一括確認
show devices all | match sw-version
```

**影響範囲の優先度:** インターネット公開の Captive Portal 有効機 > 内部 NW 向けポータル有効機 > ポータル無効機（影響なし）

**出典**: [Root-level RCE vulnerability in PAN-OS exploited — Help Net Security](https://www.helpnetsecurity.com/2026/05/06/palo-alto-firewalls-vulnerability-exploited-cve-2026-0300/) / [Threat Brief: Exploitation of PAN-OS Captive Portal Zero-Day — Unit 42](https://unit42.paloaltonetworks.com/captive-portal-zero-day/)

### Apache HTTP/2 CVE-2026-23918 — double-free による DoS・RCE リスク

Apache HTTP Server 2.4.66 の HTTP/2 実装に double-free 脆弱性 **CVE-2026-23918** が発見された。サービス妨害（DoS）に加えてリモートコード実行（RCE）の可能性もあるとされており、広範に利用される Web サーバーだけに影響範囲は大きい。アップグレードが困難な環境では HTTP/2 を一時的に無効化する（`Protocols http/1.1`）ことが回避策となる。

### cPanel CVE-2026-41940 — 認証バイパスで攻撃者が管理者権限を獲得

cPanel および WebHost Manager（WHM）に認証バイパスの脆弱性 **CVE-2026-41940** が確認された。リモートの未認証攻撃者がコントロールパネルの管理者権限を取得できるとされており、政府機関・マネージドサービスプロバイダー（MSP）ネットワークを標的とした攻撃が報告されている。共有ホスティング環境では特に影響が大きく、ホスティング事業者は直ちにパッチ適用の要否を確認する必要がある。

**出典**: [Critical Apache HTTP/2 Flaw — The Hacker News](https://thehackernews.com/2026/05/critical-apache-http2-flaw-cve-2026.html) / [Critical cPanel Vulnerability Weaponized — The Hacker News](https://thehackernews.com/2026/05/critical-cpanel-vulnerability.html)
