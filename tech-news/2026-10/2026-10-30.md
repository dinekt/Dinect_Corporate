## 注目技術と実践ベストプラクティス

### 在庫スナップショットと購入承認を分離するエージェント型コマース

#### 目的

商品推薦に使った在庫や価格が、購入実行時にも正しいとは限らない。エージェント型コマースでは、商品を探す処理、最新条件を確定する処理、利用者が購入を承認する処理を分離し、古い在庫や別バリエーションを誤って注文しない設計が必要になる。NIQとGoogleの共同発表も、エージェントの信頼性を支える要素として商品情報、現実の店舗在庫、購買測定を挙げている。そこで、推薦時のスナップショットを根拠に直ちに購入せず、商品ID・店舗・数量・価格・有効期限を固定した確認票を作り、購入直前に在庫を再取得して照合する。

#### 対象・前提

対象は、オンライン販売、店舗受け取り、社内購買など、AIが商品候補を絞り込んだ後に注文APIを呼ぶワークフローである。Google Merchant Centerの公式仕様では、ローカル在庫に`store_code`、`id`、`quantity`、`price`、`availability`が必要で、在庫側の`id`は主要商品データの`id`と一致させる。価格と在庫はランディングページ、構造化データ、購入画面とも一致させる必要がある。以下はPython 3.11の標準ライブラリだけを使う一般化した実装例であり、Google、NIQ、決済事業者の実装例ではなく、外部APIや実注文には接続しない。

#### 手順

実装例では、ブランド商品の個体識別にGTIN、販売単位の識別にSKU相当の`offer_id`、店舗の識別に`store_code`を使う。推薦後に最新在庫を取得し、5分以内の観測値であること、商品・店舗・数量・価格が承認対象と一致することを確認してから、改ざん検知用HMACを付けた確認票を発行する。購入直前にも在庫を再取得し、価格が変わっていれば自動実行せず再承認へ戻す。

```python
from datetime import datetime, timedelta, timezone
import hashlib
import hmac
import json

JST = timezone(timedelta(hours=9))
SECRET = b"replace-with-a-secret-from-a-secret-manager"
MAX_INVENTORY_AGE = timedelta(minutes=5)


def parse_time(value):
    return datetime.fromisoformat(value)


def validate_inventory(item, request, now):
    required = {
        "offer_id", "gtin", "store_code", "quantity", "price_minor",
        "currency", "availability", "observed_at"
    }
    if required - item.keys():
        raise ValueError("missing_inventory_field")
    for key in ("offer_id", "gtin", "store_code"):
        if item[key] != request[key]:
            raise ValueError(f"identity_mismatch:{key}")
    if item["availability"] not in {"in_stock", "limited_availability"}:
        raise ValueError("not_available")
    if item["quantity"] < request["quantity"]:
        raise ValueError("insufficient_quantity")
    observed_at = parse_time(item["observed_at"])
    if now - observed_at > MAX_INVENTORY_AGE:
        raise ValueError("stale_inventory")


def sign(payload):
    canonical = json.dumps(payload, sort_keys=True, separators=(",", ":"))
    return hmac.new(SECRET, canonical.encode(), hashlib.sha256).hexdigest()


def prepare_confirmation(item, request, now):
    validate_inventory(item, request, now)
    confirmation = {
        "offer_id": item["offer_id"],
        "gtin": item["gtin"],
        "store_code": item["store_code"],
        "quantity": request["quantity"],
        "approved_price_minor": item["price_minor"],
        "currency": item["currency"],
        "expires_at": (now + timedelta(minutes=10)).isoformat(),
    }
    confirmation["token"] = sign(confirmation)
    return confirmation


def confirm_purchase(confirmation, fresh_item, now):
    token = confirmation.pop("token")
    try:
        if not hmac.compare_digest(token, sign(confirmation)):
            raise ValueError("invalid_confirmation")
        if now > parse_time(confirmation["expires_at"]):
            raise ValueError("confirmation_expired")
        request = {
            key: confirmation[key]
            for key in ("offer_id", "gtin", "store_code", "quantity")
        }
        validate_inventory(fresh_item, request, now)
        if fresh_item["currency"] != confirmation["currency"]:
            raise ValueError("currency_changed")
        if fresh_item["price_minor"] != confirmation["approved_price_minor"]:
            raise ValueError("price_changed")
        return {
            "status": "approved",
            "offer_id": request["offer_id"],
            "total_minor": fresh_item["price_minor"] * request["quantity"],
            "currency": fresh_item["currency"],
        }
    finally:
        confirmation["token"] = token


now = datetime(2026, 10, 30, 6, 1, tzinfo=JST)
request = {
    "offer_id": "SKU-RED-42",
    "gtin": "04512345678903",
    "store_code": "TOKYO-01",
    "quantity": 1,
}
inventory = {
    **request,
    "quantity": 2,
    "price_minor": 12800,
    "currency": "JPY",
    "availability": "in_stock",
    "observed_at": "2026-10-30T06:00:00+09:00",
}
confirmation = prepare_confirmation(inventory, request, now)
print("quote_ready", confirmation["approved_price_minor"], "JPY")

changed = {
    **inventory,
    "price_minor": 13500,
    "observed_at": "2026-10-30T06:01:30+09:00",
}
try:
    confirm_purchase(confirmation, changed, now + timedelta(minutes=1))
except ValueError as error:
    print("blocked", error)

fresh = {**inventory, "observed_at": "2026-10-30T06:01:30+09:00"}
result = confirm_purchase(confirmation, fresh, now + timedelta(minutes=1))
print(result["status"], result["offer_id"], result["total_minor"], "JPY")
```

このコードは、初回に`quote_ready 12800 JPY`を出力する。購入直前に価格が13,500円へ変わったケースは`blocked price_changed`として止まり、同じ価格と十分な在庫を再確認できたケースだけが`approved SKU-RED-42 12800 JPY`へ進む。実運用では、確認票に配送先や税・送料を含む最終総額、販売条件、利用者または承認者の識別子も含め、注文APIには確認票とは別の冪等キーを渡す。

#### 確認方法

上記コードはPython 3.11で実行し、想定した3行が出力されることを確認する。受け入れ試験では、商品バリエーション違い、店舗違い、在庫不足、5分超の古い在庫、通貨変更、価格変更、期限切れ、確認票改ざんをそれぞれ入力し、すべて購入処理の前で停止することを確かめる。さらに、実際の購入APIへ接続する前にサンドボックスで、注文件数が承認済み要求数を超えないこと、同じ冪等キーの再送で注文が増えないことを測る。この例はローカルでの検証のみ実行済みで、Google Merchant API、NIQ、決済・注文システムとの接続は未実行である。

#### 注意点

5分という鮮度上限は一般化した構成例であり、公式仕様の固定値ではない。限定品や在庫変動の大きい商品では短くし、受注生産品では別の引当手順を設けるなど、欠品リスクとAPI負荷の実測から決める必要がある。HMACの秘密鍵はコードへ埋め込まず秘密管理サービスで保管し、確認票には個人情報を入れず、利用者と承認権限はサーバー側のセッションで照合する。推薦品質が高くても、規制品、年齢確認、返品条件、配送可否、税・送料、決済認証は別の決定論的ルールとして購入前に検証する。
