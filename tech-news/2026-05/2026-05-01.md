### 2. GitHub に単一 `git push` で RCE が成立する重大脆弱性 CVE-2026-3854（CVSS 8.7）— Enterprise Server の 88% が未修正

クラウドセキュリティ企業 Wiz のリサーチチームが、GitHub に対するリモートコード実行（RCE）脆弱性 **CVE-2026-3854**（CVSS 8.7）を発見・公開した。攻撃者は対象リポジトリへの push 権限さえあれば、悪細工した `git push` オプションを送信するだけで GitHub バックエンドサーバー上で任意コマンドを実行できる。根本原因はユーザー提供の git push オプションが適切にサニタイズされずメタデータへ埋め込まれる点で、デリミタ処理を悪用してダウンストリームサービスに悪意ある入力を信頼済みデータとして処理させる仕組みだ。GitHub.com では影響を受けたノード上で他ユーザーのパブリック・プライベートリポジトリ数百万件が参照可能な状態になっていた。GitHub.com は発見当日（3 月 4 日）にパッチを適用済みだが、Help Net Security の調査では **GitHub Enterprise Server インスタンスの 88% が依然として未修正**であることが判明しており、セルフホスト環境の管理者は **GHES 3.19.3 以降へ即時アップグレード**が求められる。野外での悪用は現時点で未確認だが、脆弱性の再現性が高く早期対応が必須だ。

### Copy Fail（CVE-2026-31431）— 732 バイトの Python スクリプトで 2017 年以降のほぼ全 Linux ディストリビューションに root 昇格

Linux カーネルの暗号化モジュール `algif_aead`（AF_ALG ソケット）に論理バグが確認され、**CVE-2026-31431**（CVSS 7.8、通称 "Copy Fail"）として公開された。2017 年に導入されたインプレース最適化の欠陥により、非特権ユーザーが AF_ALG ソケット越しに AEAD 演算を発行すると、カーネルのページキャッシュ内の任意ファイルに 4 バイトの制御可能な書き込みを行える。これを悪用した **732 バイトの Python エクスプロイト**で setuid バイナリを書き換え、root 権限を取得できる。特に厄介なのはページキャッシュへの書き込みのためディスク上のファイルは変化せず、**標準的なフォレンジックでは検出が困難**な点だ。競合状態やタイミング依存がなく直線的に成立するため再現性が極めて高い。Ubuntu・RHEL・Debian・Arch 等、2017 年以降のほぼ全ディストリビューションが対象で、カーネルパッチの即時適用が強く推奨される。コンテナ環境でも非特権コンテナがホストの root を奪取できる可能性があり、クラウドワークロードの管理者も対応が急務だ。

CISA が既知悪用脆弱性カタログに新たに 4 件を追加し、連邦機関に **5 月 8 日**までの修正を義務付けた。中でも **SimpleHelp** に存在する脆弱性は CVSS **9.9** と今四半期最高クラスの深刻度を持ち、積極的な悪用が確認されている。**Samsung MagicINFO 9 Server** および **D-Link DIR-823X シリーズルーター**の CVE も同時に追加された。連邦機関に限らず、これらの製品を運用する組織は同期限を目安としたパッチ優先度付けが推奨される。
