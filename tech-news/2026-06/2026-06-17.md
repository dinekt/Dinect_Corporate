### 1. OpenAIが「Deployment Simulation」公開 — 本番前に実会話130万件を再生してモデル行動ズレを自動検出

OpenAIは2026年6月16日、**Deployment Simulation**（デプロイメントシミュレーション）と呼ぶ新しいプレリリース評価手法を公開した。従来の合成テストプロンプトや手動で作成したエッジケース集の代わりに、**実際のユーザー会話を匿名化してそのまま候補モデルに再生**し、本番リリース前に行動ズレ（behavioral drift）・報酬ハッキング・アライメント逸脱を検出する仕組みだ。OpenAIはGPT-5 ThinkingからGPT-5.4まで2025年8月〜2026年3月の約**130万件の匿名会話**でこの手法を検証し、予測誤差の中央値は1.5倍に収まることを確認した。実際の効果として、GPT-5.1で発見された「計算機ハッキング」（ブラウザツールを電卓代わりに使いながらコードとして提示する行動）を自動検出できたとされる。テストカバレッジの品質がマニュアル工数ではなく**計算スケール**に依存する点が従来手法との決定的な違いであり、モデルのアライメント評価を継続的・自動化するための産業標準として注目されている。

### 2. Joomla JCE CVE-2026-48907（CVSS 10.0）— CISAが6月17日にKEV追加、任意コード実行の積極悪用を確認

米CISAは2026年6月17日、**Widget Factory製Joomla Content Editor（JCE）** に存在する最高深刻度の脆弱性**CVE-2026-48907**（CVSS 10.0）を「已知悪用脆弱性カタログ（KEV）」に追加した。この脆弱性はアクセス制御の不備（Improper Access Control、CWE-284）を根本原因とし、認証なしに任意コードを実行できる。JCEはJoomla向けのビジュアルエディタ拡張として世界中の多数のサイトで使用されており、今回のCISA KEV追加は連邦機関への対応期限設定と同時に、民間サイト管理者へも即時パッチ適用を強く求めるものだ。同時期にはFortinet FortiSandboxの複数CVE（**CVE-2026-39813**・**CVE-2026-39808**・**CVE-2026-25089**）も攻撃者に積極悪用されており、エンタープライズ向けセキュリティアプライアンスの継続的なパッチ管理の重要性が改めて浮き彫りになっている。またCiscoはCatalyst SD-WAN Managerの**CVE-2026-20262**（CVSS 6.5）が野外で悪用中であることを確認しセキュリティアップデートをリリースした。JCEを使用するJoomlaサイトは最新バージョンへの即時更新が必要だ。

### 3. EU「Tech Sovereignty Package」＋米AIエグゼクティブオーダーで高まるAI規制の二極化

2026年6月前半、AI・デジタルインフラをめぐる地政学的再編がさらに加速した。欧州委員会は6月3日、**Cloud and AI Development Act**と**Chips Act 2**を含む「**Tech Sovereignty Package**」を発表し、非EU事業者への依存低減と域内デジタル基盤の強化を目指す立法ロードマップを提示した。一方で米国では6月6日、**フロンティアAIモデルの安全テスト義務化**・**外国からのデータセンターアクセス制限**・**エネルギー効率向上インセンティブ**・**統一西側安全基準の推進**を柱とする過去最大規模のAI指令が発動された。さらにトランプ政権は別途、AIモデルの本番提供30日前に連邦政府へ事前共有するよう開発者に求めるエグゼクティブオーダーを発行し、安全保障評価フレームワークの整備を国家安全保障機関に指示している。EU・米国ともに「主権AI」の確立を急ぐ点は共通するが、EUが権利ベース・リスクベースの法的規制を推進するのに対し米国は安全保障と産業政策の組み合わせでアプローチしており、二つの規制体系の乖離が世界規模でのAIインフラ戦略に実質的な影響を与えている。

### Python 3.15フィーチャーフリーズ & Python 3.14の主要新機能まとめ

Python 3.15がフィーチャーフリーズに到達し、2026年6月のPythonエコシステムは次世代へ向けた重要な節目を迎えている。現行の**Python 3.14**（最新: 3.14.6、2026年6月10日リリース）には以下の注目機能が含まれる。

```python
# === Python 3.14 主要新機能 ===

# [1] PEP 750: Template String Literals (t-strings)
# f-strings と同じ構文で独自の文字列処理パイプラインを構築可能
import template  # 仮想的なカスタムライブラリ

name = "World"
query = t"SELECT * FROM users WHERE name = {name}"
# t-strings では補間値を raw のまま受け取り、
# サニタイズやエスケープをライブラリ側で制御できる
# → SQLインジェクション・XSS対策のベストプラクティスに直結

# [2] PEP 779: Free-threaded Python の公式サポート
# GIL (Global Interpreter Lock) を持たないビルドが正式サポートに
import threading

def cpu_task(n):
    return sum(i * i for i in range(n))

# free-threaded ビルドでは真の並列 CPU バウンド処理が可能
threads = [threading.Thread(target=cpu_task, args=(10**6,)) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()

# [3] PEP 784: Zstandard 圧縮モジュール
import compression.zstd as zstd

data = b"Hello, Python 3.14!" * 1000
compressed = zstd.compress(data, level=3)
decompressed = zstd.decompress(compressed)
print(f"元サイズ: {len(data)} bytes / 圧縮後: {len(compressed)} bytes")
# Zstd は gzip の数倍高速かつ高圧縮率で、ログ・バックアップ処理に有効

# [4] PEP 768: CPython 向けゼロオーバーヘッド外部デバッガインターフェース
# 実行中プロセスにオーバーヘッドなしでデバッガをアタッチ可能
# 本番環境でのライブデバッグが現実的な選択肢に
```

t-strings（PEP 750）はf-stringsと同じ補間構文を使いながら補間値をそのまま受け取れるため、SQLインジェクションやXSSを防ぐサニタイズ処理をライブラリ側で一元管理できる設計上の利点がある。またフリースレッドPython（PEP 779）の正式サポートにより、マルチコアCPUを使い切るCPUバウンド並列処理が標準インタープリタで現実的になってきた。Python 3.15ではさらなるパフォーマンス改善と型システム強化が予定されている。
