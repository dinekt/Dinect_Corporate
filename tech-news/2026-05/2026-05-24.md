### 1. Microsoft Exchange OWA ゼロデイ CVE-2026-42897 — 細工されたメール経由の XSS が実環境で悪用中

オンプレミス版 Microsoft Exchange Server の Outlook Web Access（OWA）コンポーネントに、クロスサイトスクリプティング（XSS）に起因するスプーフィング脆弱性 CVE-2026-42897（CVSS 8.1）が発見され、野生での悪用が確認されている。Exchange Server が受信メールのコンテンツを OWA 上でレンダリングする際に入力を十分にサニタイズしないことが原因で、攻撃者は特細工されたメールを送信するだけでブラウザコンテキスト上で任意の JavaScript を実行でき、セッションハイジャックやスプーフィングへと繋げられる。影響範囲は Exchange Server 2016・2019・Subscription Edition RTM で、Exchange Online は対象外だ。Microsoft はコードレベルの恒久修正をまだリリースしていないが、Exchange EM Service が有効な環境向けに自動緩和策を公開しており、適用済みの場合は自動有効化される。ベルギーのサイバーセキュリティセンター（CCB）も緊急警告を発しており、オンプレミス Exchange を運用する組織は即時の緩和策適用が求められる。

### 3. Linux 7.0 が Rust を正式安定化 — NVMe・ネットワークドライバが mainline に移行、Debian も Rust を必須依存として採用

Linux カーネル 7.0 がリリースされ、Rust の "experimental" ラベルが正式に外れた。これは 2025 年 Tokyo のカーネルメンテナーサミットで決定された方針に基づくもので、Rust で書かれたドライバを書くことが公式にサポートされる初のリリースとなった。NVMe ストレージドライバとハイスピードネットワークドライバが実験ブランチから mainline 安定ツリーに移行し、Rust 製 NVMe ドライバは高 IOPS ワークロードにおいてレガシー C ドライバと比較して約 10% のレイテンシ削減を実現している。Google が Android 向けに展開した Rust カーネルドライバコードではメモリ安全性バグのゼロ件継続が報告されており、効果の実証例として注目される。Debian のパッケージマネージャーは 2026 年 5 月から Rust をハード依存として要求しはじめ、Ubuntu・Kali・Raspberry Pi OS など Debian 系全ディストリビューションに Rust が実質的に組み込まれる状況となった。

### Linux Kernel 7.0 Rust 安定化 — カーネルドライバ開発の選択肢が広がる

Linux 7.0 での Rust 安定化により、システムプログラマがカーネルドライバを Rust で書くための公式パスが整備された。以下はカーネルモジュールを Rust で実装する際の最小限の構成例だ。

```rust
// Linux カーネル Rust モジュールの最小構成（概念コード）
#![no_std]

use kernel::prelude::*;

module! {
    type: MyDriver,
    name: "my_driver",
    author: "Example",
    description: "Minimal Rust kernel module",
    license: "GPL",
}

struct MyDriver;

impl kernel::Module for MyDriver {
    fn init(_module: &'static ThisModule) -> Result<Self> {
        pr_info!("MyDriver: initialized\n");
        Ok(MyDriver)
    }
}

impl Drop for MyDriver {
    fn drop(&mut self) {
        pr_info!("MyDriver: unloaded\n");
    }
}
```

従来の C カーネルドライバと比較して、Rust モジュールはコンパイル時に所有権モデルによる use-after-free・ダブルフリー・データ競合を排除できる。実際に Android 向けに展開された Rust ドライバコードではメモリ安全性起因のバグがゼロ件であることが確認されており、セキュリティクリティカルなカーネルコードへの Rust 採用が本格化している。

**出典**: [Rust Is Stable in Linux Kernel 7.0 — byteiota](https://byteiota.com/rust-stable-linux-kernel-7-driver-developers/) / [Rust for Systems & Kernel Development — dasroot.net](https://dasroot.net/posts/2026/03/rust-systems-kernel-development-performance/)

### Microsoft Exchange CVE-2026-42897 — OWA XSS ゼロデイの緊急対処手順

```bash
# 1. Exchange のバージョン確認（Exchange Management Shell）
Get-ExchangeDiagnosticInfo -Server <ServerName> -Process EdgeTransport -Component VariantConfiguration -Setting Configured

# 2. Exchange EM Service による自動緩和策の適用確認
# Exchange 2016/2019/SE で EM Service が有効な場合、緩和策は自動適用済み
Get-ExchangeDiagnosticInfo -Server <ServerName> -Process MSExchangeHMHost -Component VariantConfiguration -Setting Configured | Select-Object -ExpandProperty Result

# 3. OWA へのアクセスを一時制限（緩和策未適用環境向け）
# IIS で OWA 仮想ディレクトリを無効化（業務影響に注意）
Set-OwaVirtualDirectory -Identity "<ServerName>\owa (Default Web Site)" -ExternalUrl $null

# 4. Exchange ログでの不審アクティビティ確認
# OWA アクセスログのパス
Get-Item "C:\Program Files\Microsoft\Exchange Server\V15\Logging\OWA\*" | Sort-Object LastWriteTime -Descending | Select-Object -First 10

# 5. Microsoft 公式緩和策の手動適用（EM Service 無効環境）
# https://techcommunity.microsoft.com/blog/exchange/addressing-exchange-server-may-2026-vulnerability-cve-2026-42897/4518498
# のスクリプトに従い IIS モジュールを更新

# 6. 疑わしいセッショントークンの無効化
# ユーザーのアクティブセッションを強制終了
Revoke-AllClientAccessTokens -Identity <UserName>
```

Exchange Online は本脆弱性の影響を受けないため、Microsoft 365 に移行済みの組織はリスク対象外だ。オンプレミス Exchange を継続運用している組織は Microsoft EM Service の有効化と自動緩和策の適用確認を最優先で行うこと。

### Ivanti EPMM CVE-2026-6973 — 認証済み RCE が CISA KEV に追加、クレデンシャル連鎖攻撃に注意

Ivanti Endpoint Manager Mobile（EPMM）の入力値検証不備に起因する CVE-2026-6973（CVSS 7.2）が CISA の既知悪用脆弱性（KEV）カタログに追加された。攻撃者は 2026 年 1 月に悪用された別の Ivanti 脆弱性 CVE-2026-1340 で窃取した管理者クレデンシャルを本脆弱性に連鎖させ、ホスト OS 上で任意コード実行を達成している。5/7 時点でベルギー CCB も一定数の顧客が侵害済みであることを確認しており、連邦機関には 5/10 までのパッチ適用が義務付けられた。修正済みバージョンは 12.6.1.1・12.7.0.1・12.8.0.1 で、未適用環境は早急にアップグレードすること。
