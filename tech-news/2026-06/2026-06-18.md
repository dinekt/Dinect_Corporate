### 2. Google Gemini CLI 本日（6/18）廃止 — Antigravity CLI への強制移行でCI/CDパイプラインに影響

Googleは本日2026年6月18日をもって**Gemini CLI（旧来の対話型コーディング支援CLI）**の提供を終了し、後継ツール**Antigravity CLI（コマンド名: `agy`）**への移行を完了させた。5月19日に発表されたこの廃止措置により、Google AI Pro・Ultra・無償版Gemini Code Assistユーザーは本日以降レガシーCLIを使用できなくなった（法人契約の Gemini Code Assist ライセンス保有組織は当面継続利用可能）。Antigravity CLIはGoで書かれたクローズドソースのバイナリで、並列実行サポートとAntigravity 2.0デスクトップアプリとの連携が特徴だが、**移行時点で1:1の機能パリティは保証されていない**とGoogleは明言している。また利用制限モデルも変更されており、従来の「1日1,000リクエスト」から「週次コンピュートベースの上限」に切り替わるため、大量呼び出しを組み込んだ自動化スクリプトやCI/CDパイプラインは上限設計の見直しが必要だ。Googleは移行ドキュメントを `antigravity.google/docs/gcli-migration` で公開している。

### 3. CVE-2026-54420（CVSS 8.5）LiteSpeed cPanel 特権昇格 — CISA KEV 追加・本日が連邦機関の修正期限

米CISAは**LiteSpeed cPanel プラグイン**に存在する特権昇格脆弱性**CVE-2026-54420**（CVSS 8.5）を「已知悪用脆弱性カタログ（KEV）」に追加し、連邦機関の修正適用期限を本日2026年6月18日と設定した。この脆弱性はLiteSpeed cPanelプラグイン v2.4.8以前（LiteSpeed WHM Plugin v5.3.2.0以前）が対象で、**FTPアクセスやウェブシェル権限を持つ攻撃者がシンリンクを悪用してCloudLinux/CageFSの隔離境界を突破し、rootに特権昇格できる**というものだ。攻撃チェーンはcPanel内部APIの意図しない呼び出し連結によって構成されており、共有ホスティング環境では1つの侵害アカウントから同一サーバー上の全テナントに影響が波及する危険がある。脆弱性は5月31日に報告、6月1日にパッチ版（v2.4.8 / WHM Plugin v5.3.2.1）がリリース、6月14日にCVE識別子が付与された。野外での積極悪用が確認されており、LiteSpeedを利用する共有ホスティング事業者やサイト管理者は即時のプラグインアップデートが必要だ。

### Kotlin 2.4.0 — Context Parameters 安定化・Explicit Backing Fields でAPI設計が変わる

JetBrainsはKotlin 2.4.0をリリースし、長らくプレビュー段階にあった**Context Parameters**が安定版（Stable）に昇格した。Context Parametersはレシーバー（`this`）を使わずに関数スコープへコンテキストを注入できる機能で、依存性注入パターンやDSL設計における定型コードを大幅に削減する。合わせて**Explicit Backing Fields**（明示的バッキングフィールド）が導入され、`field` キーワードでプロパティの内部フィールドを直接制御できるようになった。

```kotlin
// === Kotlin 2.4.0: Context Parameters の例 ===

// コンテキストとして渡したい型を定義
class Logger {
    fun log(message: String) = println("[LOG] $message")
}

class Database {
    fun query(sql: String): List<String> = listOf("row1", "row2")
}

// context() で複数のコンテキストを受け取る関数
context(Logger, Database)
fun fetchAndLogUsers(): List<String> {
    log("Fetching users...")          // Logger の log() を直接呼べる
    return query("SELECT * FROM users") // Database の query() を直接呼べる
}

// 呼び出し側: with() でコンテキストを提供
fun main() {
    with(Logger()) {
        with(Database()) {
            val users = fetchAndLogUsers()
            log("Found ${users.size} users")
        }
    }
}

// === Explicit Backing Fields の例 ===

class Counter {
    var count: Int = 0
        get() = field           // field で内部の Int に直接アクセス
        set(value) {
            field = maxOf(0, value)  // 負値を防ぐバリデーションを backing field 経由で適用
        }
}

// === guard conditions（2.2.0 で Stable 化済み）との組み合わせ ===
fun describeList(items: List<String>): String {
    val first = items.firstOrNull() ?: return "空のリスト"
    // guard により first は非 null が保証されるため以降のスコープが簡潔に
    return "先頭: $first, 合計: ${items.size}件"
}
```

Context Parametersは関数型プログラミングにおける「リーダーモナド」パターンに近い設計で、テスト時に依存関係をコンテキスト差し替えで注入できる。JetBrainsはAndroid・サーバーサイドKotlin・Kotlin Multiplatformいずれのターゲットで安定動作を確認済みとしている。また同リリースでは標準ライブラリにUUID APIサポートとソート順検証ユーティリティが追加された。

**出典**: [Kotlin 2.4.0 Release Notes](https://kotlinlang.org/docs/whatsnew24.html) / [JetBrains: Kotlin 2.3.20 Released](https://blog.jetbrains.com/kotlin/2026/03/kotlin-2-3-20-released/) / [IDE.com: Kotlin 2.4.0 Released](https://ide.com/kotlin-2-4-0-released/)

### CVE-2026-54420 LiteSpeed cPanel 詳細 — シンリンク攻撃でCageFSを突破、共有ホスティング全体が危険に

```bash
# === CVE-2026-54420 対応チェックリスト (2026-06-18) ===

# ---- 影響確認: LiteSpeed WHM Plugin バージョン確認 ----
# cPanel/WHM管理画面 または CLI で確認
/usr/local/lsws/admin/misc/lsup.sh -v
# → 出力が 5.3.2.1 未満なら即時アップデートが必要

# ---- 修正版への更新 ----
# WHM > LiteSpeed WebServer > Upgrade/Update から実施
# または CLI:
/usr/local/cpanel/scripts/install_litespeed_plugin --update
# 修正版: cPanel Plugin v2.4.8 / WHM Plugin v5.3.2.1

# ---- 攻撃ベクトルの概要 ----
# 1. 攻撃者がFTPアクセスまたはウェブシェルを取得（初期侵害）
# 2. シンリンクをcPanelプラグインの内部パスへ向けて作成
# 3. cPanel内部APIを意図しない順序でチェーン呼び出し
# 4. CageFS / CloudLinux の隔離を突破 → root 昇格

# ---- 暫定緩和策（即時アップデートが困難な場合）----
# LiteSpeed cPanel Plugin の一時無効化
whmapi1 disablefeature feature=litespeedtech-webserver

# ---- 確認: 侵害の痕跡 ----
# 不審なシンリンクを探す（ドキュメントルート以外を指すもの）
find /home -type l -maxdepth 5 | xargs -I{} sh -c 'target=$(readlink -f {}); echo "{} -> $target"' 2>/dev/null | grep -v "^/home"

echo "=== CVE-2026-54420 優先度 ==="
echo "CVSS: 8.5 (High) | CISA KEV 追加: 2026-06-16 | 野外悪用確認済み"
echo "連邦機関修正期限: 2026-06-18（本日）"
echo "修正版: LiteSpeed cPanel Plugin v2.4.8 / WHM Plugin v5.3.2.1"
```

この脆弱性の本質的な危険性は**共有ホスティング環境のマルチテナント性**にある。CageFSはCloudLinux上で各ユーザーを仮想的に分離するセキュリティレイヤーだが、今回の攻撃ではcPanelプラグイン経由でその境界を突破できる。1つのテナントアカウントが侵害されると同一サーバー上の全テナントデータへのアクセスが可能になるため、ホスティング事業者側の一括対応が特に重要だ。パッチが5月31日の報告から2日以内にリリースされたにもかかわらず野外での悪用が確認されている点は、ホスティング環境でのパッチ適用遅延という構造的な問題を改めて浮き彫りにしている。
