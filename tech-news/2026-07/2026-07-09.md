### 1. AnthropicとOpenAIのIPO期待値が過去25年の米国テック出口合計を超過 — 同日「Claude Reflect」も公開でエンドユーザー囲い込みを加速

TechCrunchの試算によると、**Anthropic・OpenAI・SpaceXの3社の合算評価額は過去25年間における米国ベンチャー支援企業の全エグジット総額を上回る**見通しであることが報じられた。SpaceXはすでに約1.77兆ドルの評価でIPOを実施しており、AnthropicとOpenAIが近く続くことで3社の合算は4兆ドルを超える可能性がある。1999〜2024年の25年間で達成した価値を、AI産業は数年間で生み出したことになる。AnthropicはIPO観測報道と同日に**Claude「Reflect」機能**を正式公開した。Reflectはユーザーが自身のClaude使用状況を可視化するダッシュボードで、会話テーマの傾向・利用時間帯・よく依頼するタスクの種類などをパーソナルインサイトとして表示する。同機能はオプトイン制で使用データはAIトレーニングに用いないとAnthropicは明言しているが、ユーザーエンゲージメントと製品粘着性（リテンション）を高める戦略的な位置付けでもある。AI企業の競争軸が「モデル性能」から「ユーザー体験・エコシステム統合」へとシフトしつつある局面を象徴するリリースといえる。

### 2. ランサムウェア各グループがCitrix Bleed 2（CVE-2025-5777）・BYOVD・サプライチェーン認証情報へ戦術転換 — Anubis・INC・Lynxが2026年後半の侵入経路を刷新

The Hacker Newsが報じたところによると、2026年後半のランサムウェア各グループは初期侵入手法を複数のベクタへ分散させる動向が顕著になっている。**Anubisランサムウェア**グループは**Citrix Bleed 2（CVE-2025-5777）**を悪用してセッショントークンを窃取し認証をバイパスした後、正規の**RMM（リモート管理監視）ツール**を使ってネットワーク内を横展開する手法が確認されている。正規ツールを「武器」として使うことで、EDR（エンドポイント検知・対応）ソフトウェアによる検知を回避できる点が攻撃側の大きな利点だ。一方**INCおよびLynxランサムウェア**は**FortiBleedキャンペーン**（Fortinetデバイスから認証情報を大量搾取する手口）で得た資格情報を使い、VPNやリモートアクセス経由で企業環境に侵入するパターンが増加している。また複数グループが**BYOVD（Bring Your Own Vulnerable Driver）**手法—脆弱なカーネルドライバを意図的に持ち込みカーネルレベルの権限昇格を行う技術—を採用しており、パッチ済み環境でもOSの深部に到達できる高度な攻撃が一般化しつつある。2026年の特徴として「単一CVE依存から複合戦術への移行」が顕著であり、脆弱性管理だけでなく異常な正規ツール利用の検知（LOLBins / RMM監視）が防御上の優先課題となっている。

### 3. EU AI Act が 2026年8月2日に完全施行 — 最大€3,500万の制裁金・米国Section 232半導体調査が7月に臨界点

欧州連合の**EU AI Act**が**2026年8月2日に完全施行**され、人類史上初めて包括的・拘束力のある包括的AI規制が現実のものとなる。高リスクAIシステムに対する要件違反には最大**€3,500万（約400億円）または全世界売上高の7%のいずれか高い方**の罰則が科され、監督機関が本格稼働する。域外適用条項により、EU域内でサービスを提供する非EU企業も対象となるため、日本を含む世界各国のサービスプロバイダにとっても無関係ではない。一方で**米国はSection 232調査**（半導体・重要鉱物の安全保障上の影響調査）が7月に臨界点を迎えており、Nvidia H200・AMD MI325Xなどへの新関税や輸入制限の発動可能性が浮上している。EU規制強化と米国輸出規制・関税の組み合わせは、グローバルAIサービスのコスト構造と展開地域の選択に複合的な影響を及ぼしつつある。マーク・ザッカーバーグはこの週、社内タウンホールで「AIエージェントの進化が当初想定より遅い」と認める発言をしており、巨大インフラ投資（Metaは今年最大1,450億ドルのAIインフラ支出を計画）と技術進捗のギャップへの懸念が経営幹部レベルでも意識されていることが明らかになった。

### Rust 1.97.0 リリース — v0シンボルマングリングをデフォルト化・Cargo build.warnings永続化・整数ビット操作API追加

本日（7月9日）**Rust 1.97.0**が安定版としてリリースされた。6週間ごとのリリースサイクルで届けられた今回の主な変更点は以下のとおりだ。

```bash
# Rust 1.97.0 へのアップデート
rustup update stable
rustc --version
# rustc 1.97.0 (XXXXXXXX 2026-07-09)

# --- 変更点 1: v0 シンボルマングリングがデフォルト ---
# 以前は -Z symbol-mangling-version=v0 で明示が必要だったが
# 1.97.0 からデフォルトになりレガシーマングリングは削除予定
# デバッガやプロファイラで Rust シンボルが読みやすくなる

# --- 変更点 2: Cargo build.warnings の永続化 ---
# Cargo.toml または .cargo/config.toml で警告ポリシーを固定可能に
# CI で警告をエラー扱いにしてもビルドキャッシュが壊れなくなった

# .cargo/config.toml 例
# [build]
# warnings = "deny"   # すべての警告をエラーとして扱う

# --- 変更点 3: 整数ビット操作 API の安定化 ---
let x: u32 = 0b1010_1100;

// 最上位ビット(MSB)から最初の1ビットまでのゼロ数を返す
println!("{}", x.leading_zeros());   // 24

// 最下位ビット(LSB)から最初の1ビットまでのゼロ数を返す
println!("{}", x.trailing_zeros());  // 2

// ビットの総数（ポピュレーションカウント）
println!("{}", x.count_ones());      // 4

// ARMv8.6-A 向けベクトル命令セットのコンパイラサポートも追加
// #[target_feature(enable = "i8mm")] が stable に
```

v0シンボルマングリングのデフォルト化は長らくコミュニティから要望されており、`cargo-flamegraph`や`perf`などプロファイリングツールでのRustシンボル可読性が大幅に改善される。`build.warnings`設定の永続化により、CIパイプラインで`RUSTFLAGS="-D warnings"`を毎回渡す必要がなくなり、特に大規模モノレポでのビルド効率向上が期待できる。ARMv8.6-A命令セットの安定サポートはApple Silicon・Ampere Altraなどのサーバー向けARM環境を対象としており、ML推論ワークロードのパフォーマンス改善に寄与する見込みだ。

**出典**: [Rust Blog: Announcing Rust 1.97.0](https://blog.rust-lang.org/releases/latest/) / [Linux Compatible: Rust 1.97.0 release notes](https://www.linuxcompatible.org/story/rust-1970-drops-legacy-symbol-mangling-and-stabilizes-cargo-warning-controls)

### Citrix Bleed 2（CVE-2025-5777）・FortiBleed・BYOVD — 2026年後半ランサムウェアの複合侵入パターン詳細

```bash
# === 2026年後半 ランサムウェア侵入経路 対応チェックリスト ===

# ---- [1] Citrix Bleed 2 (CVE-2025-5777) ----
# Citrix NetScaler ADC / Gateway でセッショントークン漏洩
# Anubis グループが認証バイパスに活用中

# 影響バージョン確認 (Citrix CLI)
# show version | grep "Build"
# 13.1-53.17 未満 / 14.1-29.72 未満が対象

# セッションハイジャック痕跡: 同一ユーザーの異なるIPからの短時間アクセス
# Citrix ADM / Splunk 等でクエリ例:
# index=citrix sourcetype=netscaler | stats dc(src_ip) as unique_ip by user | where unique_ip > 3

# ---- [2] FortiBleed — Fortinet デバイスからの認証情報搾取 ----
# INC / Lynx ランサムウェアが取得済みクレデンシャルを利用
# FortiGate / FortiProxy の未パッチ環境が標的

# FortiGate ファームウェアバージョン確認 (SSH)
# get system status | grep "Version"
# 推奨: FortiOS 7.6.2 以上（2026年5月以降リリース）

# ---- [3] BYOVD (Bring Your Own Vulnerable Driver) ----
# 脆弱な署名付きドライバを意図的にロードしカーネル権限を取得
# EDR バイパス・ドライバ署名制限回避に使われる

# Windows: 既知の脆弱ドライバのブロックリスト適用
# Microsoft 推奨の HVCI (Hypervisor-Protected Code Integrity) を有効化
# Set-VMSecurity -VMName <VM> -VirtualizationBasedSecurityOptOut $false
# または グループポリシー: Computer Configuration > Credential Guard

# ---- [4] 正規 RMM ツールの不審な利用を検知 ----
# Anubis ほか複数グループが AnyDesk / TeamViewer / Connectwise 等を横展開に使用
# 業務外時間・非標準エンドポイントからの RMM 接続をアラート化

echo "=== 推奨アクション優先順位 ==="
echo "1. Citrix NetScaler: CVE-2025-5777 パッチ適用 + セッション異常監視"
echo "2. FortiGate/FortiProxy: 最新ファームウェアへ更新 + アクセスログ精査"
echo "3. BYOVD対策: HVCI / 脆弱ドライバブロックリスト適用"
echo "4. RMMツール: 利用承認リストの整備 + 業務外アクセス検知ルール追加"
```

2026年後半のランサムウェア攻撃の特徴は「パッチされていない単一CVEへの依存から複合戦術への移行」だ。Citrix Bleed 2を使ったセッションハイジャック → 正規RMMツールによる横展開 → BYOVD経由のEDR無効化 → ランサムウェア展開という多段構成により、単一の防御層では阻止が困難な攻撃パターンが常態化している。組織側は脆弱性管理（パッチ）に加え、ネットワークセグメンテーション・最小権限・異常な正規ツール利用（LOLBins）の行動検知を重ねたゼロトラスト的アプローチが求められる。
