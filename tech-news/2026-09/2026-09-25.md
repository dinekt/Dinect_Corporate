### 1. GoogleがGemini 3.8の音声生成モデル2種を発表

Googleは9月23日、表現力と演出制御を重視する「Gemini 3.8 Flash TTS」と、大量処理向けの「Gemini 3.8 Flash-Lite TTS」を発表しました。自然言語による声の設計、行単位の話し方指定、2人の会話生成に対応し、Gemini APIとGoogle AI Studioなどで提供が始まっています。Flashは130言語、Flash-Liteは101言語をサポートし、音声複製では本人の同意確認、生成音声にはSynthIDによる透かしが組み込まれます。音声コンテンツや対話エージェントを作る組織は、品質だけでなく、声の利用権、同意記録、生成物の表示を含む運用設計が必要です。

**出典**: [Google — Gemini 3.8 text-to-speech says hello](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-8-text-to-speech/)

### 2. GitHub Copilotアプリがローカル実行のサンドボックスに対応

GitHubは9月23日、GitHub Copilotアプリのローカルリポジトリとワーキングツリーのセッション向けに、プロジェクト単位のサンドボックスを公開プレビューとして追加しました。ファイルシステム、外部・ローカルネットワーク、GitおよびGitHub CLIの認証情報へのアクセスを制御でき、OSがポリシーを強制できない場合はサンドボックスなしで続行せずエラーになります。機能は既定で無効で、新規または再起動したセッションに設定が反映され、クラウドやリモートホストのセッションには適用されません。ローカルでコーディングエージェントを動かす利用者は、利便性のために広い権限を渡す前に、必要なディレクトリと通信先だけを許可する構成を検討できます。

**出典**: [GitHub — Local sandboxing in the GitHub Copilot app](https://github.blog/changelog/2026-09-23-local-sandboxing-in-the-github-copilot-app/)

### 3. GitHub Copilotコードレビューの自動実行とレビュー強度設定が一般提供

GitHubは9月23日、Copilotコードレビューの個人設定ページと、企業全体の既定レビュー強度を一般提供しました。すべてのCopilotプランで、プルリクエスト作成時・共同作成時・ドラフト解除時の自動レビューに加え、新しいpushやドラフトPRを対象にするかを個別に設定できます。個人はLiteまたはBalancedを既定にでき、企業管理者は組織所有リポジトリに継承される既定値を設定しつつ、組織・リポジトリ単位の上書きを許可できます。導入時は全PRを同じ強度で処理するのではなく、変更リスクと待ち時間に応じて自動レビューの範囲と強度を決めることが重要です。

## 注目技術と実践ベストプラクティス

### TTSを台本固定と聴取テストで評価する

#### 目的

生成AIのTTSを業務に取り入れる際、同じ台本でも声、読み方、固有名詞、数字、間の取り方によって品質が変わります。そこで台本と評価項目を先に固定し、モデルや設定を変更するたびに同じ条件で比較します。特に案内音声や研修教材では、自然さだけでなく、情報が正しく聞き取れることと、表現が用途に合うことを分けて確認するのが有効です。

#### 対象・前提

対象は、短い案内音声、教材、ポッドキャストなど、入力文を正確に読み上げたい用途です。例はGemini APIの `gemini-3.8-flash-tts`、Python 3、公式SDK `google-genai`、環境変数 `GEMINI_API_KEY` を前提とします。APIには利用条件と費用が発生し得るため、実行前に組織の契約、データ取り扱い、現行料金を確認してください。

#### 手順

まず、読み間違いが業務上の問題になりやすい要素を含む固定台本を用意します。以下は一般化した構成例で、日時、英数字、製品名を一度に確認できる短い案内文です。

```python
import base64
from google import genai

client = genai.Client()
script = "次回の点検は9月30日14時です。受付番号A-204と製品名Dinektを確認してください。"

interaction = client.interactions.create(
    model="gemini-3.8-flash-tts",
    input=[{
        "type": "user_input",
        "content": [{
            "type": "text",
            "text": script,
            "annotations": [{"type": "speech_metadata", "style": ""}],
        }],
    }],
    response_format={"type": "audio"},
    generation_config={"speech_config": [{"voice": "Kore"}]},
)

with open("baseline.wav", "wb") as audio_file:
    audio_file.write(base64.b64decode(interaction.output_audio.data))
```

公式ガイドに沿って最初は `style` を空にし、台本、モデルID、voice、SDKバージョンを結果と一緒に記録します。次に、同じ台本を変えずに必要な場合だけ `style` を短い一定の表現へ変更し、基準音声と比較します。複数の用途を試す場合も、台本ごとに「数字」「固有名詞」「意味の区切り」「用途に合う話速」のチェック項目を固定すると、好みだけに依存しない比較ができます。

#### 確認方法

生成ファイルを再生し、台本との一致、数字と英数字の聞き取り、固有名詞の発音、不自然な無音やノイズ、話速をチェックします。実運用を想定する場合は、内容を知らない確認者にも聞いてもらい、受付番号や日時を正しく書き取れるかを記録します。このコード例は記事作成時には未実行であり、音声品質やAPI応答も未確認です。導入先では少量の代表台本で実行し、合格条件を満たしてから対象を広げてください。

#### 注意点

`text` は読み上げる本文として扱われるため、全体の話し方は `speech_metadata.style`、一時的な間や非言語音はインラインタグというように役割を分けます。長い人物設定や過剰な指示は一貫性を崩す可能性があり、公式ガイドもまず指示なしで試し、必要な調整だけを短く加える方法を案内しています。声の複製を利用する場合は権利者の明示的な同意を取得し、地域による提供制限、保存期間、生成物の表示方針も確認してください。一度の聴取結果を全言語・全台本の品質保証として扱わず、実際の利用条件を代表する台本を継続的に評価します。

**出典**: [Google AI for Developers — Text-to-speech generation](https://ai.google.dev/gemini-api/docs/speech-generation), [Google — Gemini 3.8 text-to-speech says hello](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-8-text-to-speech/)

## まとめ

- 音声生成では、表現力の比較とあわせて、声の利用権、同意、生成物の表示まで運用に組み込みます。
- ローカルのコーディングエージェントは、必要なファイル、通信先、認証情報だけを許可するサンドボックスから始めます。
- TTSを採用する前に固定台本を作り、数字・固有名詞・聞き取りやすさを同じ基準で評価します。
