### 1. AI モデル競争 2026年5月 — GPT-5.5・Claude Sonnet 4.6・Gemini 3.1 Pro が三者三様の性能優位を確立、組織はタスク別マルチモデル戦略へ移行

### 2. GitHub CVE-2026-3854 — git push 1 コマンドでサーバー上の数百万リポジトリに RCE、GHES の 88% が未パッチのまま公開

Wiz Research が発見・報告した **CVE-2026-3854**（CVSS 8.7）は、GitHub の内部 git プロキシ「babeld」における HTTP ヘッダーインジェクション脆弱性だ。babeld は git push オプション値をセミコロン区切りの内部ヘッダー `X-Stat` に直接コピーしていたため、攻撃者はセミコロンを含む push オプションを細工するだけで任意のヘッダーフィールドを注入し、バックエンドサーバーで任意コードを実行できた。標準の git クライアント 1 本さえあれば認証済みユーザーなら誰でも他のユーザー・組織のプライベートリポジトリを含む共有ストレージノードにアクセス可能であったことが確認されている。GitHub は 2026 年 3 月 4 日の報告から 2 時間以内に GitHub.com への修正を展開し、法医学調査の結果 Wiz のテスト以外の悪用は確認されていない。しかし 4 月 28 日の公開開示時点で、**GitHub Enterprise Server（GHES）インスタンスの 88% がパッチ済みバージョン（3.19.3 以降）に更新されていない**ことが明らかになっており、自己ホスト型 GHES を運用している組織は即時のアップグレードが必要な状況だ。また今回の脆弱性はクローズドソースバイナリへの AI 支援解析で発見された初の重大脆弱性の一つとして注目されている。

## セキュリティ

### GitHub CVE-2026-3854 — GHES 運用者向け緊急対応チェックリスト

GHES（GitHub Enterprise Server）自己ホスト環境への影響が特に深刻で、公開開示から数日経過した現在も大多数がパッチ未適用の状態にある。

**即時確認事項:**
- `ghe-config core.git-version` でバージョンを確認し、**3.19.3 以降でなければ即刻アップグレード**
- GitHub.com および Enterprise Cloud は GitHub 側で修正済みのため追加対応不要
- パッチ前に悪用されていないか確認: GitHub はすべての異常なコードパスは Wiz のテストのみと断言しているが、自組織ログの独立検証も推奨

**再発防止:**
- git push オプションを使うカスタムフックや CI スクリプトがある場合、受け取る値のサニタイズを必ず実装する
- GHES の自動アップデート通知を有効化し、セキュリティリリースの即日適用を運用フローに組み込む

### cPanel CVE-2026-41940 — 東南アジアの政府・軍事機関が標的の認証バイパス

cPanel と WebHost Manager に影響する **CVE-2026-41940**（認証バイパス）が、東南アジアの政府・軍事機関を標的とした攻撃に使用されていることが確認された。公開済みの PoC コードを使った攻撃が進行中のため、cPanel を運用するホスティング事業者・Web 管理者は最新パッチの即時適用と管理パネルへのアクセス制限（IP ホワイトリスト化）を優先すべき状況だ。
