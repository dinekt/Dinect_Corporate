## 注目技術と実践ベストプラクティス

### ローカル忠実度テストをAIコーディングエージェントの実行ゲートにする

#### 目的

ローカル忠実度テストは、AIコーディングエージェントが生成したクラウド連携コードを、実サービスに近いAPI契約と状態遷移に対して繰り返し検証し、合格した変更だけを次の環境へ送る方法です。モックが正常応答だけを返す構成では見落としやすい、再試行、可視性タイムアウト、存在しないリソース、入力検証などの差を、エージェント自身が修正ループへ取り込めます。AWS Emulatorの公開事例が、実AWSで確かめた忠実度テスト、失敗の課題化、1課題ごとの修正、マージゲートという具体的な流れを示したため取り上げます。

#### 対象・前提

対象は、AWS APIを呼ぶアプリケーションをAIコーディングエージェントに実装・修正させる開発者とCI基盤の担当者です。AWS Emulatorをエージェントから設定する場合はAWS CLI 2.35.0以降が必要で、Linuxではパッケージ、WindowsとmacOSではDockerを使う手順が公式に案内されています。利用するAWSサービスと操作が最新リリースで再現できるか、公開されている忠実度スコアと`issues/things-that-do-not-work/`を先に確認し、実AWSとは分離したテストデータを用意します。

#### 手順

AWSが公開した実在事例では、最初のエージェント群が公開Smithy APIモデルからテストを作り、実AWSへ実行して期待動作を確定します。たとえばAmazon SQSでは、受信したメッセージが可視性タイムアウト中は他の受信者から見えず、期限後に再び受信できることを一つの忠実度シナリオにします。次のエージェント群が同じテストをエミュレーターへ再実行して差分を課題化し、修正担当のエージェントが1課題ずつ直した後、コンパイル、コーディング基準、セキュリティレビュー、忠実度の回帰確認を通過した変更だけをマージします。

自分のプロジェクトへ持ち込む場合は、まず利用サービスごとに「実装が満たすべき状態遷移」を小さな受け入れシナリオへします。次はSQSの可視性タイムアウトを表す一般化した構成例で、AWS Emulator固有の実行形式ではありません。

```yaml
name: sqs_visibility_timeout
precondition: empty_test_queue
steps:
  - send: order-001
  - receive:
      expect_body: order-001
      visibility_timeout_seconds: 2
  - receive_immediately:
      expect_count: 0
  - wait_seconds: 3
  - receive:
      expect_body: order-001
```

次に、AWS CLI 2.35.0以降で公式スキルを追加し、エージェントへエミュレーターの設定とプロジェクトの接続先変更を依頼します。

```bash
aws agent-toolkit add-skill --skill-name aws-emulator --region us-east-1
```

実行順序はプロジェクトのSDK、テストランナー、OSに依存しますが、基本は「リリースを固定する、エミュレーターを起動する、同じプロセスで接続先を設定する、忠実度テストを実行する、差分を1課題へ分解する、全回帰テストを通す」です。エージェントには修正可能なディレクトリと1回の変更範囲を限定し、合格後もステージングの実AWSで統合・権限テストを行ってから本番へ進めます。

#### 確認方法

上記のコマンドと構成例は本記事の作成環境では未実行です。SQSの例では、最初の受信で`order-001`が返り、2秒の可視性タイムアウト中の再受信件数が0、3秒待った後の受信で同じ本文が返ることが期待結果です。エミュレーターの合格だけで完了とせず、固定したリリース番号、利用したサービスと操作、テストケース、既知の忠実度ギャップ、エージェントが変更したファイル、全回帰テストの結果をCI成果物として残します。最後にステージングの実AWSで同じ業務シナリオと権限拒否を確認し、エミュレーターとの差が許容範囲かを人が判定します。

#### 注意点

AWSはAWS Emulatorをセキュリティテストへ使わないよう明記しており、IAMポリシー、リソースポリシー、KMSキーポリシー、アカウント・リージョン間アクセスは実AWSと同じ挙動ではありません。実AWSの資格情報や顧客・本番データを入れず、エミュレーターは既定の`127.0.0.1:9297`から外部へ公開せず、テストプロセス内で接続先を確実に設定して意図しないクラウド呼び出しを防ぎます。関数コードなどは利用者権限でローカル実行されるため、エージェントが生成した未確認コードをホストへ無制限に実行させないことも重要です。忠実度には既知・未知の差があり、テレメトリは既定で有効なため、利用条件と収集内容を確認し、必要なら公式手順で無効化します。

## まとめ

- AIコーディングエージェントへクラウド連携を任せる場合は、正常応答だけでなく状態遷移と失敗条件を忠実度テストにし、変更範囲を限定したマージゲートへ組み込みます。
- エミュレーターの合格はAPI動作の早期確認に使い、権限とセキュリティは分離したステージングの実AWSで確認します。
- 複数モデルを使い分ける場合も、計画・実行・検証の役割ごとに成功率、待ち時間、費用を測って選択します。
