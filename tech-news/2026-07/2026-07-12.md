### 2. SharePoint RCE CVE-2026-45659がCISA KEVに追加 — Warlockランサムウェアが認証済みDeserialization攻撃を実行中

MicrosoftのSharePoint Serverに存在する**CVE-2026-45659**（CVSS 8.8、非信頼データのDeserialization起因RCE）が2026年7月1日にCISAの既知悪用脆弱性（KEV）カタログに追加され、米連邦機関に対し7月4日までのパッチ適用が義務付けられた。影響範囲はSharePoint Server Subscription Edition・2019・Enterprise Server 2016の全バージョンで、Microsoftは5月のPatch Tuesdayで修正済みだったが「悪用可能性：低」の評価を付けていた。実際にはKEV登録が示す通り野外での悪用が確認されており、攻撃者はSharePointのSite Member以上の権限さえ持てば認証情報をそのままコード実行に転用できる。調査によれば**STORM-2603**と呼ばれる脅威アクターグループが**Warlockランサムウェア**の展開と連動した形でこの脆弱性を悪用していることが判明している。MicrosoftがSharePoint 2016・2019を2026年中にサポート終了とするスケジュールと重なるため、レガシーバージョンを運用する組織は移行計画の前倒しを余儀なくされる可能性が高い。

### 3. 国連AI統治対話がジュネーブで開催、アジェンティックAIを「測定・監査不能」と科学委員会が警告

2026年7月6〜7日、国連の「AIガバナンスに関するグローバル対話」が初めてジュネーブで開催された。UNESCOをはじめ多数の加盟国が参加したこの対話では、国連独立国際AIパネルが7月1日に公開した予備報告書の内容が中心議題となった。同報告書は「アジェンティックAIの能力は、それを測定・監査・統治する人類の能力を上回るペースで成長している」と明言しており、AIガバナンスにおける多国間科学機関が自律型エージェントリスクを公式に認定した画期的な文書として評価されている。背景には、Five Eyesの6機関（米CISA・NSA、豪ACSC、加CCCS、NZ NCSC、英NCSC）が5月に発表したアジェンティックAIセキュリティ共同ガイダンス「Careful Adoption of Agentic AI Services」があり、重要インフラ内で稼働するエージェントへのガバナンス整備が急務であることを国際的に位置付けた。並行して米国では半導体・重要鉱物に関するSection 232調査が正念場を迎えており、新たな関税・輸入制限・国内生産要件の発動が議論されている。中国のZ.ai GLM-5.2がAnthropicやOpenAIの最前線モデルと競合する性能を示したことも、AIを国家安全保障上の戦略資産として管理する動きを加速させる要因となっている。

### Rust 1.97.0リリース — v0シンボルマングリングがデフォルト化し8年越しの移行完了

2026年7月9日、**Rust 1.97.0**が安定版としてリリースされた。最大の変更点は**v0シンボルマングリングスキーム**のデフォルト化だ。v0はRust固有のスキームであり、バイナリのシンボルテーブルにジェネリック型シグネチャが完全に読める形で埋め込まれるため、デバッガ・プロファイラ・クラッシュレポートツールでの可読性が大幅に向上する。Rust 1.59（2022年）からコンパイルフラグ `-Csymbol-mangling-version=v0` でオプトインが可能だった経緯を持ち、今回のデフォルト化でレガシーのC互換スキームへの依存がエコシステム全体から段階的に排除される。

```bash
# Rust 1.97.0 へのアップデート
rustup update stable

# v0 マングリングで生成されたシンボルを確認
rustup show active-toolchain  # → stable-x86_64-unknown-linux-gnu (1.97.0)

# nm でシンボルが読みやすくなった例
cat > /tmp/example.rs << 'EOF'
use std::collections::HashMap;

pub fn lookup<K: std::hash::Hash + Eq, V>(map: &HashMap<K, V>, key: &K) -> Option<&V> {
    map.get(key)
}
EOF

rustc --edition 2024 /tmp/example.rs --crate-type lib -o /tmp/example.rlib
# v0 マングリングにより "lookup::<K,V>" のような可読シンボルが生成される
nm /tmp/example.rlib 2>/dev/null | grep lookup | head -5
```

1.97.0のもう一つの重要な変更は**Cargo Warning Controls**の安定化だ。`build.warnings` 設定でビルド時の警告をサイレント・警告・エラーの3段階で制御できるようになり、CIパイプラインでwarning-freeビルドを強制する長年の課題が解決された。またリンカのstderrがターミナルに直接流れるようになり、リンクエラーのデバッグ体験が改善。安定化APIとして `isolate_highest_one`・`isolate_lowest_one` 等のビット操作メソッド、`char::is_control` のconst文脈での使用が追加された。

**出典**: [Rust Blog: Announcing Rust 1.97.0](https://blog.rust-lang.org/2026/07/09/Rust-1.97.0/) / [linuxiac.com: Rust 1.97 v0 Symbol Mangling](https://linuxiac.com/rust-1-97-released-with-new-default-symbol-mangling-scheme/) / [linuxcompatible.org: Rust 1.97.0](https://www.linuxcompatible.org/story/rust-1970-drops-legacy-symbol-mangling-and-stabilizes-cargo-warning-controls)
