### 2. EU AI Act、完全施行まで残り37日 — 高リスクAI透明性義務と最大€15M制裁が8月2日に発動、5月の部分延期合意と合わせて最終整備局面へ

2026年8月2日をもってEU AI Act（AI法）が**完全施行**される。発効から丸2年となるこの節目に最も重要な2つの義務が実効力を持つ。第1は**高リスクAIシステムへの義務群**（人間監督・ログ保持・リスク評価文書化・公共部門向け基本権影響評価）、第2は**透明性規則の完全執行**（チャットボット・生成AI・ディープフェイクへの開示義務）だ。違反した場合の制裁は最大**€1,500万または世界年間売上高の3%**に上る。ただし5月7日に成立した政治合意により、医療・教育・採用等**特定高リスク分野**への義務適用は2027年12月2日まで延期されており、すべての義務が8月2日に一斉発動するわけではない。米国企業も「EU市民向けサービスを提供すれば所在地を問わず対象」という域外適用の対象であり、コンプライアンス体制の整備が急務となっている。米国は同月6月6日のホワイトハウス指令でフロンティアAIへの義務的安全テスト国内標準を制定しており、EU・米・中の三極による「AI規制の標準覇権」争いが最終局面を迎えつつある。

### 3. Linux "pedit COW"（CVE-2026-46331）が武器化完了 — カーネルv5.18〜v7.1-rc6全域でroot権限奪取PoC公開済み、CISA KEV Lantronix EDS5000の対応期限も本日

Linuxカーネルのトラフィック制御（tc）サブシステムに存在する**CVE-2026-46331（通称: pedit COW）**が本格的な脅威となっている。`net/sched`の`act_pedit`（パケット編集アクション）における**境界外書き込み**により、攻撃者はページキャッシュを汚染してsetuid rootバイナリ（`/bin/su`等）にペイロードを注入し、rootシェルを得ることが可能だ。攻撃の前提条件は「非特権ユーザー名前空間が開放されていること」と「`act_pedit`がロード可能なこと」のみであり、Ubuntu・Fedoraのデフォルト設定で大多数の環境が該当する。武器化したPoC（概念実証）はCVE割り当て（6月16日）の翌日に公開されており、パッチ未適用の猶予は実質的にない。影響バージョンはLinuxカーネル**v5.18〜v7.1-rc6**と広大であり、修正はv7.1-rc7以降に収録されている。加えて本日6月26日は、CISAが**Lantronix EDS5000シリーズ**の重大なRCE脆弱性（積極的悪用確認済み）に設定した**FCEB機関向けKEV対応期限**日でもあり、IoT・OT環境を持つ組織は今日中の対応が必須だ。

### TIOBE 2026年6月確定 & BASIC09がLLVMバックエンド対応（46年越しの近代化）— Python 19%割れ、C++が3位返り咲き

2026年6月のTIOBEインデックス確定値で、Pythonが**18.96%**と初めて19%を割り込んだ（前月比〜0.4pp低下）。C++が**13.62%**でJava（**13.41%**）を再逆転し3位に返り咲き、Javaは4位となった。Python低下の背景には、AIコード生成ツールが多様な言語で実装コードを生成するようになりランキング母数が分散したことと、Rustをはじめとするシステム言語へのシフトがある。AI研究論文では依然としてPythonが主流だが、インフラ・ドライバ・WebAssemblyの領域では代替言語への移行が定着しつつある。

一方、6月23日にLLVMコミュニティへアナウンスされたのが**BASIC09のLLVMフロントエンド実装**だ。1980年にMicroware社がTandy/RadioShackのOS-9システム向けに設計した構造化BASIC言語が、46年越しにモダンコンパイラ基盤を獲得することになった。「AIが普及した時代でも新しいプログラミング言語の価値はあるか？」というHacker Newsの議論が盛んな2026年において、この出来事は「言語の長寿」と「コンパイラ技術の汎用化」を象徴するエピソードとして注目を集めている。

```python
# Python 3.14 の新機能: t-strings (PEP 750, Python 3.14で標準化)
# f-strings と構文は似ているが、即時展開せずテンプレートオブジェクトを返す

import string

user_id = 42
# f-string: 即時文字列化 → SQLインジェクションリスク
f_query = f"SELECT * FROM users WHERE id = {user_id}"  # 文字列 (危険)

# t-string: テンプレートオブジェクト → サニタイズ層を挟める
t_query = t"SELECT * FROM users WHERE id = {user_id}"  # <template> オブジェクト

def safe_sql(tmpl) -> str:
    # 実際のライブラリはパラメータ化クエリとして渡す
    parts = []
    for item in tmpl:
        if isinstance(item, str):
            parts.append(item)
        else:
            # 補間値を安全にエスケープ/バインド
            parts.append(f"${item.expression!r}")
    return "".join(parts)

# → "SELECT * FROM users WHERE id = $42"  (ドライバにバインド変数として渡す)
print(safe_sql(t_query))
```

Python 3.14のt-strings（PEP 750）はf-stringsと同様の構文ながら「即時展開しないテンプレートオブジェクト」として遅延評価され、SQLやHTMLのような文脈依存のサニタイズが必要な場面で型安全なDSL構築を実現する。2026年時点でORMやテンプレートエンジンへの対応が広がりつつある。
