### 1. MCP 2026-07-28 仕様リリース候補（RC）公開 — ステートレスHTTPコアへ転換、MCP Apps・Tasksで「エージェント基盤プロトコル」が本格始動

10週間の検証期間（5月21日〜7月28日）を経て、**Model Context Protocol（MCP）の次期仕様リリース候補（2026-07-28 RC）が本日正式公開**された。これはMCP発足以来最大の仕様改訂であり、プロトコルの根幹アーキテクチャを刷新するものだ。最大の変更は**ステートレスHTTPコアへの転換**で、`Mcp-Session-Id`ヘッダーとプロトコルレベルのセッション管理が廃止され、任意のMCPリクエストが任意のサーバーインスタンスに到達できるようになる。これにより、スティッキールーティングや共有セッションストアなしで水平スケールが可能となり、Kubernetes/Cloud Run等の標準HTTPインフラ上での大規模展開が飛躍的に容易になる。仕様は5つのスレッドを一本化している：ステートレスコア、**MCP Apps**（初の公式Extension：サーバーがUIをレンダリングしてクライアントに配信）、再設計された**Tasksエクステンション**（長時間ジョブの非同期管理）、認証強化パッケージ（6つのSEP）、そして正式な廃止ポリシーだ。Python・TypeScript・Go・C#のSDKベータも同時公開されており、すでに950以上のMCPサーバーが登録されているエコシステムへのインパクトは大きい。エージェントAI時代のデファクト通信プロトコルとして、MCPがさらに地位を固める節目となった。

### 2. CVE-2026-16812: Arista VeloCloud Orchestrator CVSS 10.0 ゼロデイ — 認証不要OSコマンドインジェクションでSD-WAN管理基盤が積極悪用中、CISA KEV追加

**CVE-2026-16812**（CVSSスコア10.0）が7月28日、複数の主要セキュリティメディアで一斉に報告された。Arista NetworksのVeloCloud Orchestrator（VCO）オンプレミス版に存在するOSコマンドインジェクション脆弱性で、攻撃者は**VCOのWebインターフェースへのネットワークアクセスのみで任意コード実行**が可能だ。テナント・オペレーター権限など一切の認証を必要とせず、オンプレミスVCOはデフォルトで外部公開されており、設定変更で露出を完全に除去することもできない。VeloCloudはエンタープライズが広域ネットワーク（SD-WAN）を集中管理するためのオーケストレーター基盤で、製造業・金融・通信事業者などの大規模ネットワーク環境で広く使われている。Aristaは「脆弱性は外部発見であり、積極的に悪用されていることが確認されている」と認めているが、攻撃者の正体・悪用開始時期・具体的な手口は非開示だ。CISAは7月27日にKEV（Known Exploited Vulnerabilities）カタログへ追加し、連邦機関に対してはEMD（限定指令）の期限内の対応を義務づけた。修正済みバージョンは5.2.3.14、6.1.3.4、6.4.2.4以降で、未更新の場合は即時アップデートとともにVCO Webインターフェースへの外部アクセスを暫定遮断することが強く推奨される。

### 3. FastJson ゼロデイRCEが悪用拡大 ＆ Linux カーネルCVE-2026-53264 — JavaライブラリとCentOS Stream 9のローカル権限昇格が同時多発

Javaの主要オープンソースJSONライブラリ**FastJson**でリモートコード実行（RCE）を可能にする脆弱性の積極悪用が確認された。特権・ユーザー操作を必要とせず、ネットワーク経由で任意コード実行が可能という危険な攻撃条件だ。FastJsonはJavaのWebアプリケーション・マイクロサービスで広く採用されており、Spring Boot等のフレームワークとの組み合わせで使われているケースが多い。パッチ適用または安全な代替ライブラリ（Jackson等）への移行が急務だ。一方、**CVE-2026-53264**（CVSSスコア7.8）はLinuxカーネルのネットワークトラフィック制御サブシステムに存在する**use-after-free競合**で、通常の一般ユーザーがCentOS Stream 9のroot権限を取得できる。ローカル権限昇格ではあるが、コンテナ環境・マルチテナントサーバー・侵入後の権限昇格フェーズで脅威度が増す。さらに、**24,000台以上のインターネット公開サーバー**がBaseboard Management Controller（BMC）インターフェースの20年来の脆弱性により認証ハッシュを漏洩していることも今週報告されており、データセンター機器のファームウェア管理が再び焦点となっている。

## 新技術・新リリース

### MCP 2026-07-28 RC — ステートレス移行の要点とコードへの影響

今回のMCP仕様改訂でクライアント・サーバー双方の実装に影響する最大の変化は「セッション管理の廃止」だ。従来の`2025-11-05`仕様では`initialize` → `Mcp-Session-Id`取得 → 後続リクエストへのヘッダー付与という流れが必須だったが、RC版では**セッションIDの概念自体がプロトコルから除去**される。

```typescript
// === 旧仕様 (2025-11-05) — セッションフルモデル ===
// 初期化でセッションIDを取得し、以後すべてのリクエストに付与していた

const initResponse = await fetch('/mcp', {
  method: 'POST',
  body: JSON.stringify({ method: 'initialize', ... }),
});
const sessionId = initResponse.headers.get('Mcp-Session-Id'); // 必須ヘッダー

const toolResponse = await fetch('/mcp', {
  method: 'POST',
  headers: { 'Mcp-Session-Id': sessionId },  // ← 削除される
  body: JSON.stringify({ method: 'tools/call', ... }),
});
```

```typescript
// === 新仕様 (2026-07-28 RC) — ステートレスモデル ===
// セッションIDなし。任意のリクエストが任意のサーバーインスタンスに届く

const toolResponse = await fetch('/mcp', {
  method: 'POST',
  // Mcp-Session-Id ヘッダー不要・不在
  body: JSON.stringify({ method: 'tools/call', params: { name: 'search', arguments: { q: 'hello' } } }),
});
const result = await toolResponse.json();
```

```python
# === Tasksエクステンション (新仕様) — 長時間ジョブの非同期処理 ===
# tools/call がタスクハンドルを返し、クライアントがポーリングで進捗を取得

import httpx

# 1. ツール呼び出し → タスクハンドル取得
res = httpx.post('/mcp', json={'method': 'tools/call', 'params': {'name': 'slow_analysis'}})
task_id = res.json().get('task_id')  # 長時間ジョブはタスクハンドルを返す

# 2. 完了まで tasks/get でポーリング
while True:
    status = httpx.post('/mcp', json={'method': 'tasks/get', 'params': {'task_id': task_id}})
    state = status.json()['state']  # 'running' | 'completed' | 'failed'
    if state != 'running':
        break
    import time; time.sleep(2)

# 3. 必要に応じてキャンセル
# httpx.post('/mcp', json={'method': 'tasks/cancel', 'params': {'task_id': task_id}})
```

このステートレス化によってKubernetes上の水平スケールが劇的に簡単になる一方、**既存の有状態MCP実装は破壊的変更を受ける**。現行の`2025-11-05`仕様準拠のサーバーがRCをデプロイする際は、セッションID依存のロジック（サーバーサイドの会話コンテキスト保持など）を再設計する必要がある。10週間のRCウィンドウはその移行猶予でもある。

## セキュリティ

### 今週の優先対応 — VeloCloud CVSS 10 ゼロデイ・FastJson RCE・Linux LPE・BMC24K台漏洩

```bash
# === 2026-07-28 セキュリティ優先対応チェックリスト ===

# ---- [1] CVE-2026-16812: Arista VeloCloud Orchestrator Pre-Auth RCE (CVSS 10.0) ----
# 影響: VeloCloud Orchestrator On-Prem 5.2.3.14未満 / 6.1.3.4未満 / 6.4.2.4未満
# 経路: 認証不要・VCO Webインターフェースへのネットワークアクセスのみ
# 対応: 即時 VCO 5.2.3.14 / 6.1.3.4 / 6.4.2.4 以上へ更新
#       更新完了までVCO Webインターフェースへの外部アクセスを暫定遮断
#
# VCOバージョン確認 (VCO管理画面またはAPI経由)
# curl -sk https://<VCO-IP>/rest/v1/vco/info | python3 -m json.tool | grep version

# ---- [2] FastJson RCE (ゼロデイ・悪用中) ----
# 影響: FastJson を使用するすべてのJavaアプリケーション
# 経路: 認証不要・ネットワーク経由でRCE
# 対応: FastJsonを最新版に更新、または Jackson / Gson への移行を検討
#
# FastJson 利用確認
# grep -r 'fastjson' /path/to/project/pom.xml /path/to/project/build.gradle 2>/dev/null
# grep -r 'com.alibaba.fastjson' /path/to/project/pom.xml 2>/dev/null

# ---- [3] CVE-2026-53264: Linux Kernel LPE (CVSS 7.8) ----
# 影響: CentOS Stream 9 (use-after-free in network TC subsystem)
# 経路: ローカルユーザーからroot権限昇格
# 対応: kernel パッケージを最新に更新後、再起動
#
# カーネルバージョン確認
# uname -r
# dnf check-update kernel  # CentOS Stream 9

# ---- [4] BMC インターフェース パスワードハッシュ漏洩 ----
# 影響: 24,000台以上のインターネット公開サーバーのBMC (IPMI/Redfish)
# 経路: 20年来の脆弱性・BMCが認証ハッシュを漏洩
# 対応: BMCインターフェースをパブリックIPに直接公開しない
#       ファイアウォールでBMC管理ポート(623/udp, 443, 80)を制限
#       BMCファームウェアを最新版に更新
#
# 公開確認 (自組織のIPで確認)
# nmap -p 623 --script ipmi-version <BMC-IP>

echo "=== 2026-07-28 優先対応サマリー ==="
echo "CVE-2026-16812 (VeloCloud):  CVSS10 Pre-Auth RCE CISA KEV → 即時更新+外部遮断"
echo "FastJson RCE:                認証不要RCE悪用中              → 最新版更新or移行"
echo "CVE-2026-53264 (Linux LPE):  CentOS Stream 9 ローカルroot   → kernel更新+再起動"
echo "BMC 漏洩24K台:               パスワードハッシュ漏洩         → 外部公開遮断+FW制限"
```

今週のセキュリティ状況を一言で表すなら「インフラ管理基盤への複数同時攻撃」だ。VeloCloud OrchestratorはエンタープライズのSD-WAN全体を制御する中枢であり、ここが突破されれば拠点間通信の可視化・改ざん・遮断が可能になる。FastJsonはJava製マイクロサービスの多くに組み込まれており、攻撃者がどのサービスにバックドアを仕込んだか追跡が困難という厄介さがある。BMCの認証ハッシュ漏洩は20年来の古い問題の再燃だが、24,000台というスケールは改めてファームウェアセキュリティの後回し文化の深刻さを示している。CVE-2026-16812がCISA KEVカタログに追加されたことで、米国連邦機関は期限内の対応が法的義務となったが、民間企業においても「CISA KEVはパッチ優先度の事実上の業界標準」として活用することが推奨される。
