### 1. Jeff Dean ら Google 上位研究者 4 名が退社 — AI が科学的方法を自動化するスタートアップ「Discovery Loop」設立

Google のチーフサイエンティストであり、MapReduce・Google Brain・Gemini の礎を築いた**Jeff Dean**（58）が27年間在籍した Google を退社し、**Discovery Loop** を共同設立したと 8 月 5 日に発表された。共同創業者は Dean のほか、Google シニアフェローの **Sanjay Ghemawat**、Google Brain 共同創設者の **Quoc Le**、Gemini 技術リードだった Google DeepMind VP の **Oriol Vinyals** の計 4 名で、Google の中核的 AI 人材が一挙に離れる形となった。Discovery Loop の目標は「**科学的方法そのものを自動化する**」こと――仮説立案、実験実行、結果評価、反復というサイクルを AI が人間の代わりに何千件も並列実行する。さらに長期的には AI が AI 自身の開発を改善する再帰的自己改善（Recursive Self-Improvement）も視野に入れている。資金面では **Alphabet（Google 親会社）** が初期投資家として参画し、**Radical Ventures・Khosla Ventures** がラウンドをリード、**Kleiner Perkins・Lightspeed・Doerr Capital** も参加。Google は初年度の計算資源（クラウドコンピュート）を提供する。テック大手から最高クラスの AI 研究者が独立スタートアップへ流出するトレンドが、今回の人事でいっそう鮮明になった。

### 2. Cloudflare、AI エージェント専用ブラウザ「Kitesurf」を発表 — Chromium 比で CPU・メモリを最大 7 分の 1 に圧縮

Cloudflare が 8 月 7 日、**Kitesurf** を発表した。Kitesurf は Rust で書かれた**ステートレス・エージェントファーストブラウザ**で、Cloudflare Workers 上の V8 アイソレートとして完全動作する。Chromium と比較してスクリーンショット取得・HTML 抽出などの典型的なエージェントタスクにおいて **CPU・メモリ使用量を 3〜7 分の 1** に抑えるとされ、ベータ期間中は**無料**で利用可能。Puppeteer・Playwright・CDP（Chrome DevTools Protocol）をサポートするため既存のエージェントコードをほぼそのまま移行できる一方、ビデオや WebGL には未対応で、タブ・拡張機能・テーマといった「人間向け」機能は省かれている。設計思想の核は「AIエージェントは視覚的UIではなく、コンテキストウィンドウ・パフォーマンス・トークンコスト・スケーラビリティを最優先する」という点だ。リクエストごとに新インスタンスが起動するステートレス設計は、複数エージェントが並列で Web をスクレイピングする際のリソース効率を大幅に改善し、オープンソース化も予告されている。従来型のヘッドレス Chromium 運用との置き換え候補として、AIエージェント・パイプライン構築者の注目を集めている。

### 3. SCTPhantom（CVE-2026-64564）— 18 年放置の Linux カーネル SCTP Use-After-Free でローカルユーザーが root 取得＆コンテナ脱出

Tencent のセキュリティ研究者が 8 月 6 日に公開した **CVE-2026-64564**（通称 **SCTPhantom**）は、Linux カーネルの SCTP（Stream Control Transmission Protocol）動的アドレス再設定機能に存在する **Use-After-Free** 脆弱性で、2007 年 12 月（Linux 2.6.25）に導入されたコードが発端という**18 年放置の欠陥**だ。悪用に成功した攻撃者はローカル権限から**ホスト上の root 権限に昇格**でき、Tencent 研究者は実際にコンテナから脱出してホスト側への到達も実証している。技術的な根本原因は「DEL-IP 削除操作においてカーネルがパケットの送信元アドレスで検証を行う一方、ネットワークパスを選択するために使うキャッシュポインターはアドレスパラメータを参照するというアイデンティティ不一致」にある。脆弱性の悪用にはターゲット上で SCTP が到達可能である必要があるため、すべての Linux 環境が影響を受けるわけではないが、コンテナ環境を多用するクラウドネイティブインフラでは評価が必要だ。修正済みカーネル（**7.1.6 / 6.18.42 / 6.12.101 / 6.6.148**、2026 年 8 月 3 日リリース）はすでに公開されており、公開エクスプロイトコードは執筆時点では確認されていない。また同日、AI コーディングエージェント（Anthropic・Google・OpenAI 製品を含む）のワークフローに影響するアーキテクチャ上の脆弱性開示も別途あり、LLM を利用したシステム固有のセキュリティ検討の重要性が再び浮き彫りになった。

### Meta「Muse Code」ベータ公開 — サブエージェントが並列ワークツリーで大規模リポジトリを攻略

Meta が 8 月 5 日、ターミナルベースの AI コーディングエージェント **Muse Code** のベータ版を macOS・Linux 向けに公開した。Claude Code・OpenAI Codex に対抗する位置付けで、背後には新コーディングモデル **Muse Spark 1.2** が動作する。最大の特徴は「**リポジトリが大きくなると自動的にサブエージェントに仕事を分散し、各エージェントが独立したワークツリーで並列作業する**」アーキテクチャで、計画→コード実装→検証の一連サイクルを単一コマンドで実行できる。

```bash
# Muse Code のインストール（ベータ）
curl -fsSL https://musecode.meta.com/install.sh | sh

# リポジトリ全体を分析してバグを修正するタスクの例
muse "Fix the failing tests in the payment module and add missing edge-case coverage"

# 大規模タスク時のサブエージェント展開（自動）
# → planning agent → N個の sub-agents (isolated worktrees) → validation agent
```

Muse Code のリリースは、AI コーディングエージェント市場への Meta の本格参入を示す。単一の大規模コンテキストウィンドウではなく、**複数エージェントが分散並列協調する**アプローチは、ソフトウェア開発の自動化パラダイムとして業界全体に波及しつつある。

## セキュリティ

### N-able N-central CVE-2026-18577 が CISA KEV に追加 — 認証バイパスから管理対象エンドポイント全体への横展開リスク

```bash
# === 2026-08-07 セキュリティ対応チェックリスト ===

# ---- [1] SCTPhantom CVE-2026-64564 (Linux SCTP UAF) ----
# 影響確認: SCTP が有効かどうかをチェック
lsmod | grep sctp
# sctp が出力された場合は修正済みカーネルへのアップデートが必要

# 修正済みカーネルバージョン（2026-08-03 リリース）
# 7.1.6 / 6.18.42 / 6.12.101 / 6.6.148
uname -r  # 現在のカーネルバージョン確認

# SCTP を使用しない環境での緩和策
echo "install sctp /bin/true" >> /etc/modprobe.d/disable-sctp.conf
# → モジュールのロードを無効化（再起動後に有効）

# ---- [2] N-able N-central CVE-2026-18577 (認証バイパス) ----
# N-central を使用している場合は即時パッチ適用
# 悪用成功時: 攻撃者が admin 権限を取得 → Take Control 機能で管理対象エンドポイントへ横展開
# N-able サポートサイトでパッチバージョンを確認:
# https://www.n-able.com/security-advisories

# ---- [3] CISA KEV 8月第1週の主要追加エントリ ----
# CVE-2026-64564: Linux SCTP UAF   → ローカルroot+コンテナ脱出
# CVE-2026-18577: N-able N-central → 認証バイパス・リモートadmin
# → 組織内でこれらの製品・OS を使用している場合は今週中に対応

echo "=== 本日の優先対応 ==="
echo "1. Linux カーネルを 7.1.6/6.18.42/6.12.101/6.6.148 のいずれかへアップデート"
echo "2. SCTP 不使用環境ではモジュールを無効化"
echo "3. N-able N-central を使用している場合は CVE-2026-18577 パッチを適用"
echo "4. AI コーディングエージェント利用時はワークフロー上のツール呼び出し検証を見直し"
```

N-able の RMM プラットフォーム **N-central** の認証バイパス（CVE-2026-18577）が実際の攻撃に利用されており、CISA の KEV カタログに追加された。N-central は企業 IT インフラの管理・監視に広く使われるため、侵害された場合は管理対象のすべてのエンドポイントへのアクセスが攻撃者に渡るリスクがある。同日に開示された SCTPhantom も含め、8月第 1 週のセキュリティ対応の優先度は高い。AI コーディングエージェントのワークフローに影響するアーキテクチャ脆弱性も別途開示されており、LLM を使ったシステムへのセキュリティ評価が新たな課題として浮上している。
