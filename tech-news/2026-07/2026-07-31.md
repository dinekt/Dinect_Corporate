### 1. Google Earth AI衛星画像生成機能を即日撤回 — 「空のディープフェイク」問題で世界的批判

Googleは7月30日、Google Earthに**Imagen 3**を使ったAI衛星画像オーバーレイ機能を密かに追加した。ユーザーが地図上の任意の場所にAI生成画像を重ねられるこの機能は、「地理をより創造的に探索する」目的とされていた。しかし翌7月31日、テックメディア404 MediaがAIを使って**ロサンゼルスの爆発クレーター**や**Googleキャンパス外での抗議活動**のフェイク衛星画像を簡単に作成できることを実証し、「空のディープフェイク（deepfakes in the sky）」として広く拡散。NPR、Engadget、TechCrunchが批判報道を行い、Googleはわずか**リリースから1日**で機能を全面ロールバックすると発表した。Googleは「地理空間の専門家による有益な活用事例も確認したが、ポリシー違反の生成画像のスクリーンショット共有も確認した」と述べ、「より強固なガードレールの実装中は機能を停止する」と説明した。本件は、AI生成ツールをリリース前に「悪用シナリオ」の観点から十分に評価することの重要性を改めて示す事例となった。

### 2. 米財務省、中国AIモデルに制裁警告 — Kimi K3「蒸留疑惑」で米中AI地政学が臨界点へ

米国財務長官**Scott Bessent**は7月21日、中国AI企業が米国のAIモデルを盗用（IP theft）している場合、制裁を発動する可能性があると表明した。焦点となっているのはMoonshot AIの**Kimi K3**で、米政権はKimi K3が**Anthropicの Claude Fable 5**を無断蒸留して構築されたと主張している。Anthropicは2026年2月時点で、Moonshot AI関連の不正アカウントが数百のフェイクアカウントを通じて**340万件以上のインタラクション**を自社モデルに行っていたと明らかにしており、ホワイトハウスはこれを「隠密かつ産業規模の蒸留攻撃」と位置づけた。トランプ政権はオープンソースAIの普及は支持しつつも、「IPを越えた盗用行為に対してはEntity List指定や制裁をためらわない」と警告している。中国商務省は即座に反論し、「**AIヘゲモニズム**」と批判して対抗措置を表明。この一連の動きにより、AIモデル開発競争は純粋な技術競争から**モデルリリースに制裁リスクが伴う地政学的対立**の構図へと移行しつつある。DeepSeekのR-seriesを契機に始まったAI性能格差の急速な縮小を巡る緊張が、ついに明確な通商・外交問題へと昇格した形だ。

### 3. Ruby on Rails CVE-2026-66066（CVSS 9.5）— 認証不要でサーバー上の任意ファイルを読み取り可能、RCEへの発展も

RailsのActive StorageとlibvipsライブラリのインタラクションにCVSS 9.5の**クリティカルな任意ファイル読み取り脆弱性**が発見された（CVE-2026-66066、通称「KindaRails2Shell」）。**認証なしの攻撃者**が細工した画像ファイルをアップロードすることで、Railsアプリケーションプロセスが読み取り可能なサーバー上の任意ファイルを取得できる。漏洩し得る情報は**アプリケーション署名シークレット・Railsクレデンシャル・データベースパスワード・クラウドストレージキー・サードパーティAPIトークン**など。さらにRapid7の分析によれば、取得したアプリケーションシークレットを使ったRCE（リモートコード実行）や横展開への発展も現実的なリスクとして明示されている。影響範囲はRails 7.0.0〜7.2.3.1、Rails 8.0.0〜8.0.5、Rails 8.1.0〜8.1.3で、Rails 6.x系もActive StorageをVipsで構成している場合は対象。修正版は**7.2.3.2・8.0.5.1・8.1.3.1**で、libvips 8.13以上との組み合わせが推奨される。7月29日に脆弱性情報が公開されており、Railsを使用するすべての組織に即時パッチ適用が求められる。

### TypeScript 7.0 正式リリース — GoによるネイティブコンパイラでビルドタイムがTypescript 6比11.9倍高速化

Microsoftは7月8日、**TypeScript 7.0**を正式リリースした。最大の特徴はコンパイラを**Go言語でフルリライト**した点で、ベンチマーク上VS Codeの型チェック時間が**TypeScript 6の125.7秒からわずか10.6秒（11.9倍高速）**へと短縮された。言語仕様自体は変更されておらず、型チェック・コンパイルツールのパフォーマンスのみが向上している。strict modeと6.0での非推奨設定がハードデフォルトになったほか、安定したプログラマティックAPIは7.1以降に持ち越しとなるため、Vue・Svelteなど一部のエコシステムはまだ完全移行待ちの状態だ。Vueコミュニティは「プログラマティックAPIが安定するまで移行しない」と表明しており、エコシステム全体の完全移行には数ヶ月かかる見通しだ。

```bash
# TypeScript 7.0 への移行コマンド
npm install -D typescript@7

# 型チェックのみ実行（コンパイルなし）
npx tsc --noEmit

# Go製コンパイラを使った高速ビルド確認
npx tsc --version
# 出力例: Version 7.0.0

# 移行時の主な注意点
# 1. strict: true および 6.0 deprecated オプションがデフォルト有効に
# 2. プログラマティックAPI (ts.Program 等) は 7.1 まで安定API提供なし
# 3. Vue / Svelte プロジェクトは vue-tsc / svelte-check の対応版を待つこと

# tsconfig.json の最小推奨設定 (TypeScript 7.0)
# {
#   "compilerOptions": {
#     "strict": true,
#     "target": "ES2022",
#     "module": "NodeNext",
#     "moduleResolution": "NodeNext"
#   }
# }

# ビルド時間の比較（大規模プロジェクトの目安）
# TypeScript 6: ~125秒 (VS Code相当規模)
# TypeScript 7: ~11秒  (11.9x speedup)
echo "TypeScript 7.0: Go-powered native compiler, 10x+ faster builds"
```

TypeScript 7.0の登場は、JavaScriptエコシステムにおけるビルドツールの「Rustification・Go化」という潮流を象徴している。既にBun（Zig）、esbuild（Go）、Rspack（Rust）などのツールが既存の遅いNode.jsベースのツールを置き換えてきたが、TypeScript本体のコンパイラがGoで書き直されたことはその流れの決定的な到達点だ。言語仕様が変わらない以上、採用コストは低く、既存プロジェクトへの段階的移行が現実的に進みやすい点も普及を後押しする。
