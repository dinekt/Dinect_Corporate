## 注目技術と実践ベストプラクティス

### RAGの取得・引用・回答を分離するコンテンツ利用ゲート

#### 目的

検索拡張生成（RAG）では、検索できることと、取得・再利用する権限があることは同義ではありません。さらに、取得が認められた資料でも、回答が原文の創作的表現を長く再現すれば別のリスクが生じます。そこで、情報源の取得条件を判定する「取得ゲート」と、生成文の原文重複を確認する「出力ゲート」を分離し、公開前に人間審査へ送れるようにします。これは法的判断を自動化する仕組みではなく、アクセス制限の回避や長い逐語再現を早期に止め、監査可能な記録を残すための実務的な統制です。

#### 対象・前提

ウェブ検索、社内文書検索、ニュース要約、調査支援など、外部または契約制のコンテンツを回答根拠にするRAGが対象です。情報源ごとにURL、取得方法、ペイウォールやアクセス制限の有無、契約・ライセンス上の利用可否を登録できることを前提とします。以下の一般化した実装例はPython 3.11以上の標準ライブラリだけで動き、文字列の長い連続一致を検出しますが、翻訳・言い換え・著作物性や適法性は判定しません。実運用では法務・調達部門が決めた利用区分、保管期間、審査基準を別途設定してください。

#### 手順

まず検索インデックスへ本文だけを入れず、`access`と`authorized`を含む情報源台帳を結び付けます。取得時にアクセス制限があるのに利用許諾を確認できない資料はモデルへ渡さず、回答生成後は採用した各根拠との最長連続一致を測り、設定値を超えた場合だけ人間審査へ送ります。次の最小例は、アクセス制限資料を遮断し、公開資料の事実を言い換えた回答を許可し、原文を長くコピーした回答を審査対象にする流れです。

```python
from dataclasses import dataclass
from difflib import SequenceMatcher
import re

@dataclass(frozen=True)
class Source:
    source_id: str
    url: str
    access: str          # public / paywalled / blocked
    authorized: bool     # 契約・許諾を台帳で確認済みか
    text: str

def normalize(text: str) -> str:
    return re.sub(r"\s+", "", text)

def content_gate(source: Source, answer: str, max_match: int = 18) -> dict:
    if source.access in {"paywalled", "blocked"} and not source.authorized:
        return {"decision": "block", "reason": "access_not_authorized"}

    original = normalize(source.text)
    generated = normalize(answer)
    match = SequenceMatcher(
        None, original, generated, autojunk=False
    ).find_longest_match()

    if match.size > max_match:
        return {
            "decision": "review",
            "reason": "long_verbatim_overlap",
            "match_length": match.size,
            "match": original[match.a:match.a + match.size],
        }
    return {
        "decision": "allow_with_citation",
        "reason": "no_long_verbatim_overlap",
        "source_url": source.url,
    }

source = Source(
    source_id="city-bridge-2026",
    url="https://example.org/bridge",
    access="public",
    authorized=True,
    text="市は老朽化した橋の補修を2027年4月に開始すると発表した。工事は夜間に実施する。",
)

paraphrase = "自治体によると、橋の改修は2027年4月から始まり、作業時間は夜間です。"
copied = "市は老朽化した橋の補修を2027年4月に開始すると発表した。"
restricted = Source("paid-1", "https://example.org/paid", "paywalled", False, "有料記事本文")

assert content_gate(source, paraphrase)["decision"] == "allow_with_citation"
assert content_gate(source, copied)["decision"] == "review"
assert content_gate(restricted, "要約")["decision"] == "block"
```

実装順は、情報源台帳の整備、取得前ゲート、生成、出力ゲート、引用URL付与、必要時の人間承認です。判定結果には情報源ID、台帳の版、生成モデル、閾値、審査者、最終判断を記録します。閾値18文字は動作説明用であり、実際には許諾済みデータと審査済み回答から誤検知・見逃しを測って用途別に決めます。

#### 確認方法

上のコードはPython 3.12.14で実行し、3つの`assert`がすべて成功することを確認しました。運用前には、公開・契約済み・利用不可の情報源を含む固定テスト集合を作り、取得遮断率、逐語一致の検知率、誤って審査へ送る割合、引用URLの欠落、審査待ち時間を継続測定します。期待結果は、無許諾の制限資料が生成前に遮断され、長い原文一致が公開前に審査へ送られ、許容された回答には利用したURLが残ることです。実際のRAG、モデル生成、各社の利用規約、法的妥当性については未検証です。

#### 注意点

文字列一致だけでは、翻訳、語順変更、複数資料をつないだ再構成、表現上の類似を十分に検知できず、短い定型句では誤検知も起きます。逆に、一致しない回答でも事実誤認や権利侵害がないとは限らず、「事実」と「創作的表現」の境界をコードだけで確定できません。アクセス制限の有無や契約状態はクローラーの観察だけに頼らず、調達・法務が管理する台帳を正として、失効時に即時遮断できる設計にします。CJEU法務官意見は最終判決ではなくEU法に関する事案であるため、対象地域、利用目的、引用要件、契約条件に応じて専門家の確認が必要です。

## まとめ

- RAGでは、検索結果をモデルへ渡す前の取得権限と、生成後の原文再現を別のゲートで確認する。
- AIを使った攻撃への備えは、パッチ適用、最小権限、復旧可能なバックアップ、レガシー機器の露出削減から始める。
- 地理限定推論を採用する場合は、モデル名だけでなく、送信元・送信先リージョンとログ・保存データの所在まで検証する。
