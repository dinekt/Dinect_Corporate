### LangGraphのinterruptで公開前に人間承認を挟む

**区分：公式推奨を土台にした編集部の提案**

#### 目的

エージェントが生成した変更をそのまま外部公開せず、公開内容を人間が確認してから後続処理へ進める。承認待ちの状態を保存し、同じ実行を後から安全に再開できるワークフローにする。

#### 対象・前提

LangGraph 1.x系のPython APIで状態遷移を構築する開発者を対象とする。公式ドキュメントにある`interrupt()`、`Command(resume=...)`、checkpointer、`thread_id`の組み合わせを前提にする。以下は構造を示す最小例であり、記事作成環境では実行していない。

#### 手順

承認処理を専用ノードに分け、承認前には外部公開や通知などの非冪等な副作用を置かない。開発時は`InMemorySaver`で流れを確認できるが、本番ではプロセス再起動後も状態が残る永続checkpointerへ置き換える。

```python
from typing import Literal, TypedDict

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph
from langgraph.types import Command, interrupt


class State(TypedDict):
    draft: str
    status: str


def approval(state: State) -> Command[Literal["publish", "cancel"]]:
    approved = interrupt({
        "question": "この記事案を公開しますか",
        "draft": state["draft"],
    })
    return Command(goto="publish" if approved else "cancel")


def publish(state: State):
    # 実運用では、このノードで外部公開を行う
    return {"status": "published"}


def cancel(state: State):
    return {"status": "cancelled"}


builder = StateGraph(State)
builder.add_node("approval", approval)
builder.add_node("publish", publish)
builder.add_node("cancel", cancel)
builder.add_edge(START, "approval")
builder.add_edge("publish", END)
builder.add_edge("cancel", END)

graph = builder.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "release-2026-09-20"}}

paused = graph.invoke(
    {"draft": "公開候補", "status": "pending"},
    config=config,
)
print(paused["__interrupt__"])

result = graph.invoke(Command(resume=True), config=config)
print(result["status"])
```

承認待ちから再開するときは同じ`thread_id`を使う。公開処理は承認ノードから分離し、`Command`の遷移先で実行する。これは公式の割り込み仕様に基づき、公開前承認へ適用した編集部の提案である。

#### 確認方法

最初の`invoke()`が`__interrupt__`を返し、`publish`へ進んでいないことを確認する。次に同じ`thread_id`で`Command(resume=True)`を渡した場合だけ`status`が`published`になること、`False`なら`cancelled`になることをテストする。さらに公開処理をテストダブルへ差し替え、承認前と却下時には呼ばれず、承認時に1回だけ呼ばれることを自動テストで確認する。この例は記事作成環境では未実行であり、動作確認済みとはしていない。

#### 注意点

- `interrupt()`から再開すると、そのノードは先頭から再実行される。割り込み前に非冪等なAPI呼び出しやレコード追加を置くと重複実行の恐れがある。
- `InMemorySaver`はプロセス再起動で状態を失うため、本番用途には永続checkpointerを使う。
- `thread_id`は承認対象と一対一に対応させ、別案件で再利用しない。承認者の認証・認可や監査ログはLangGraphの状態管理とは別に実装する。
- `interrupt()`を広い`try/except`で囲むと、停止に使う例外まで捕捉する可能性がある。
