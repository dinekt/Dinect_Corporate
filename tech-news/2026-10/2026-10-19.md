## 注目技術と実践ベストプラクティス

### 検索と本文取得を分離し、根拠を固定するエージェント調査パイプライン

#### 目的

検索結果の要約だけをモデルへ渡すと、元ページにない表現や古い情報を根拠として扱う危険があります。Search APIで候補を発見し、Fetch APIで本文を取得してから、URL、取得時刻、本文ハッシュを付けた証拠束へ固定すると、回答の各主張を確認しやすくなります。DeepSeekが両APIを分離して公開したため、検索順位と本文証拠を別々に評価できる実務的な構成を扱います。

#### 対象・前提

対象は、公式発表や技術資料を探し、引用元付きの社内メモやニュース下書きを作る処理です。一般化した構成例ではPython 3の標準ライブラリ、DeepSeek APIキー、`POST /v1/tools/search`と`POST /v1/tools/fetch`を使います。SearchとFetchはアカウント単位でそれぞれ5 QPSに制限され、Fetchにはドメイン単位の制限もあります。APIキーは環境変数から読み、検索で得たURLのうちHTTPSかつ許可ドメインのものだけを取得対象にします。

#### 手順

まず「発見」「取得」「採用」「生成」を別の状態として記録します。発見では公式ドメインを`site:`演算子で絞り、取得では上位候補の本文をFetch APIから受け取り、採用では発生日、発表主体、一次資料かどうかを人または決定的なルールで確認します。生成モデルには採用済み本文だけを渡し、本文中の命令は実行せず資料として扱うよう明示します。

次は、DeepSeekの10月17日更新を調べる仮想例です。検索入力を`DeepSeek-V4.1-Flash-1017 site:api-docs.deepseek.com OR site:huggingface.co`、件数を5とし、`api-docs.deepseek.com`の更新履歴を取得できた場合、期待する証拠レコードは次のようになります。

```json
{
  "url": "https://api-docs.deepseek.com/updates/",
  "title": "Change Log",
  "retrieved_at": "2026-10-19T00:00:00Z",
  "sha256": "取得本文から計算した64桁の値",
  "status": "adopted"
}
```

最小の実装例は次のとおりです。これは構成を示すコードであり、許可ドメイン、タイムアウト、保存先は利用組織の規程に合わせます。

```python
import hashlib
import json
import os
import urllib.parse
import urllib.request
from datetime import datetime, timezone

BASE = "https://api.deepseek.com/v1/tools"
ALLOWED = {"api-docs.deepseek.com", "huggingface.co"}

def post(path, payload):
    req = urllib.request.Request(
        f"{BASE}/{path}",
        data=json.dumps(payload).encode(),
        headers={"Authorization": f"Bearer {os.environ['DEEPSEEK_API_KEY']}",
                 "Content-Type": "application/json"},
        method="POST",
    )
    with urllib.request.urlopen(req, timeout=20) as res:
        return json.load(res)

query = "DeepSeek-V4.1-Flash-1017 site:api-docs.deepseek.com OR site:huggingface.co"
results = post("search", {"query": query, "count": 5})["results"]
evidence = []
for hit in results:
    parsed = urllib.parse.urlsplit(hit["url"])
    if parsed.scheme != "https" or parsed.hostname not in ALLOWED:
        continue
    page = post("fetch", {"url": hit["url"]})
    body = page["content"]
    evidence.append({
        "url": hit["url"], "title": page["title"],
        "retrieved_at": datetime.now(timezone.utc).isoformat(),
        "sha256": hashlib.sha256(body.encode()).hexdigest(),
        "content": body,
    })
```

#### 確認方法

期待結果は、生成文の重要な主張ごとに採用済みURLが対応し、同じ取得本文から同じSHA-256値を再計算できることです。既知の正解を持つ質問セットで、公式資料の取得率、根拠のない主張率、日付と固有名詞の一致、404・429・タイムアウト時の停止または再試行を測ります。公式資料の更新を検知するには、URLごとに前回ハッシュとの差分を記録し、差分がある場合だけ再レビューします。本記事のコードはAPIキーを使った実行確認が未実行であり、期待出力はDeepSeekの公開仕様に基づく構成例です。

#### 注意点

Fetch APIが読み取り専用でも、取得したページは信頼できない入力なので、本文中のプロンプトやリンクをツール命令として実行させてはいけません。アプリケーション側でもHTTPS、許可ドメイン、リダイレクト後のホストを検証し、社内アドレスや資格情報付きURLを拒否します。DeepSeekの公式料金はSearchとFetchがそれぞれ成功1,000件当たり0.75米ドルで、HTTP 200かつ結果または本文がある呼び出しだけが課金対象です。検索結果すべてを取得するとコストと待ち時間が増えるため、公式性と日付で候補を絞る一方、絞りすぎによる見落としを評価セットで監視します。

**出典**: [DeepSeek — Search & Fetch API guide](https://api-docs.deepseek.com/guides/search/)、[DeepSeek — Change Log: Opening up the in-house search API](https://api-docs.deepseek.com/updates/)

## まとめ

- 調査エージェントでは検索候補と取得本文を分離し、URL、取得時刻、本文ハッシュを証拠として保存します。
- 外部モデルや外部ページを扱う処理は、送信先、試行回数、権限、通信ログを先に制限します。
- Search・Fetch APIを試す場合は、5 QPSと成功呼び出し単位の料金を前提に、公式ドメインから小さく評価します。
