## 注目技術と実践ベストプラクティス

### 構造化出力をスキーマ検証してから業務フローへ渡す

#### 目的

生成AIの回答を業務システムへ渡す場合、見た目がJSONでも、必須項目の欠落や想定外の値があると後続処理が不安定になります。Structured Outputsは、モデルの回答を定義したJSON Schemaへ適合させ、形式上の揺れを減らす仕組みです。ただし、スキーマへの適合は内容の正しさを保証しないため、型の検証と業務上の妥当性確認を分けて設計します。

#### 対象・前提

対象は、問い合わせ分類、文書抽出、承認ルーティングなど、AIの結果をプログラムで扱う用途です。以下の一般化した実装例は、Python 3環境、OpenAIの公式Python SDK、Pydantic、Structured Outputs対応モデル `gpt-6-astra` を前提とします。実際に導入する際は、検証したSDKとPydanticのバージョンを固定し、APIの利用条件、料金、入力データの取り扱いを確認してください。

#### 手順

例として、問い合わせを分類し、緊急度が高い場合や判断材料が不足する場合は自動処理せず、人の確認へ回す構造を定義します。

```python
from typing import Literal

from openai import OpenAI
from pydantic import BaseModel


class TriageResult(BaseModel):
    category: Literal["billing", "technical", "other"]
    priority: Literal["low", "normal", "high"]
    action: Literal["reply_draft", "human_review"]
    reason: str


client = OpenAI()
ticket = "本番データベースに接続できず、注文処理が停止しています。"

completion = client.chat.completions.parse(
    model="gpt-6-astra",
    messages=[
        {
            "role": "system",
            "content": (
                "問い合わせを分類してください。緊急障害、判断材料不足、"
                "または対象外の入力は action を human_review にしてください。"
            ),
        },
        {"role": "user", "content": ticket},
    ],
    response_format=TriageResult,
)

message = completion.choices[0].message
if message.refusal:
    raise RuntimeError(f"model refused: {message.refusal}")
if message.parsed is None:
    raise RuntimeError("structured output was not completed")

result = message.parsed
if result.action == "human_review":
    print("担当者へ通知:", result.model_dump())
else:
    print("返信案の作成工程へ:", result.model_dump())
```

この入力では、期待値を `category="technical"`、`priority="high"`、`action="human_review"` とします。公式資料に基づき、プログラム側の型とJSON Schemaが分岐しないようSDKのスキーマ補助機能を使い、入力がタスクと無関係な場合の退避先もプロンプトと列挙値で定義します。出力は直接メール送信やシステム変更へ接続せず、まず人の確認または返信案の作成までに制限します。

#### 確認方法

代表的な問い合わせと期待値を表形式で用意し、分類、優先度、処理先が一致する割合を測ります。通常問い合わせ、緊急障害、情報不足、対象外の文章を含め、情報不足と対象外が `human_review` へ送られることを確認します。また、APIの拒否、出力打ち切り、通信エラーを別の失敗として記録し、自動再試行の対象を限定します。このコード例とAPI呼び出しは記事作成時には未実行であり、例示した分類結果も実測値ではありません。

#### 注意点

Structured Outputsはスキーマ準拠を保証しますが、分類理由や抽出値の事実性までは保証しません。ユーザー入力がスキーマと無関係でもモデルは項目を埋めようとする可能性があるため、不明時の値や人への退避条件を明示します。安全上の拒否やトークン上限による出力打ち切りは通常の構造化結果とは別に扱い、後続処理を開始しないでください。サポートされないJSON Schema機能もあるため、複雑な条件はアプリケーション側で追加検証し、スキーマまたは型の変更をCIで検知する運用が有効です。

## まとめ

- AIのJSON出力を業務へ渡す場合は、JSONモードではなく対応する構造化出力と型定義を利用します。
- 形式検証とは別に、代表データで内容の正しさと人へ退避する条件を評価します。
- 拒否、出力打ち切り、情報不足では自動処理を止め、担当者が確認できる経路を用意します。
