### 1. Next.js 16.2 リリース — エージェント対応の create-next-app とブラウザログ転送が登場

Next.js 16.2 が正式リリースされた。今バージョンの最大の特徴は「AI エージェントが Next.js プロジェクトを操作しやすくする」方向性が明示的に取り込まれたことにある。

**主な新機能:**

**Agent-ready create-next-app**
- `create-next-app` が AI エージェント（Claude Code、Copilot Workspace 等）からの利用を前提とした構造を出力
- プロジェクトメタデータが機械読み取りしやすい形式で生成される

**ブラウザログ転送（Browser Log Forwarding）**
- ブラウザの console ログが開発サーバーのターミナルにリアルタイムで転送される
- フロントエンドエラーを IDE を切り替えずに確認可能

**開発サーバーロックファイル**
- 複数のエージェントが同時に開発サーバーを起動しようとする競合を防止

**実験的 Agent DevTools**
- AI エージェントのアクション・状態をダッシュボードで可視化（`next.config.ts` の `experimental.agentDevTools: true` で有効化）

**Turbopack の改善:**
- サーバーサイドの細粒度ホットリロード（Server Fast Refresh）
- WASM ライブラリ向けのウェブワーカーオリジン対応
- JavaScript ファイルのサブリソース整合性（SRI）サポート

**アップグレード手順:**
```bash
npm install next@16.2 react@latest react-dom@latest
# または
npx @next/upgrade@latest
```

**next.config.ts で Agent DevTools を有効化:**
```typescript
const nextConfig = {
  experimental: {
    agentDevTools: true,
  },
}
export default nextConfig
```

**開発者への影響**:
- ブラウザログ転送により Claude Code などのエージェントが「ブラウザで何が起きているか」を即座に取得できるようになり、フロントエンドデバッグの自動化精度が向上する
- Agent DevTools はエージェントが複数タスクを並列実行する際の状態追跡を可能にし、デバッグサイクルが短縮される
- SRI サポートは CDN 経由のスクリプト改ざんを検出できるため、セキュリティ要件が高いプロジェクトでの採用障壁が下がる

### 2. MCP エコシステム：Anthropic が per-tool 結果サイズ設定と SSE 安定性を修正

Claude Code の MCP（Model Context Protocol）レイヤーに複数の重要な改善が投入された。特に大きな変更は「ツール単位での結果サイズ上限設定」の導入で、DBスキーマ全文やディレクトリツリーなどの大容量レスポンスを扱うユースケースへの対応が改善された。

**変更内容詳細:**

**Per-tool 結果サイズ設定（新機能）**
- 従来: グローバル上限でどのツールも同じ制限
- 変更後: MCP サーバーの `tools/list` エントリに `anthropic/maxResultSizeChars` を設定することで、ツール単位で上限を引き上げ可能
- 上限の上限（ハードシーリング）: 500K 文字
- 効果: 大容量レスポンスが以前はディスク参照（ファイル参照）に切り出されていたのが、インライン返却に変わる

**SSE/HTTP トランスポートの安定性修正**
- 接続切断時に MCP ツールコールが無期限ハングする問題を修正
- 長時間実行のエージェントワークフローでの信頼性が向上

**サブエージェントの MCP ツール継承修正**
- 動的注入サーバーからの MCP ツールがサブエージェントに引き継がれない問題を修正

**MCP サーバー設定例（tools/list での上限指定）:**
```json
{
  "tools": [
    {
      "name": "get_database_schema",
      "description": "データベースの全スキーマを返す",
      "anthropic/maxResultSizeChars": 200000,
      "inputSchema": { "type": "object", "properties": {} }
    }
  ]
}
```

**Claude API への Opus 4.7 追加:**
- Vercel AI Gateway に `claude-opus-4-7` が追加された
- 長時間非同期エージェント向けに最適化、プログラマティックなツールコールと画像処理能力が強化

**開発者への影響**:
- DBスキーマ・大量ファイルツリーを扱う MCP サーバー開発者は `anthropic/maxResultSizeChars` を設定することで「結果がファイル参照に切り出される」問題を回避できる
- SSE 安定性修正により、長時間実行の自動化ワークフロー（CI 統合、夜間バッチ等）の信頼性が実用レベルに近づく

**出典**: [Anthropic Claude Code Changelog](https://claudefa.st/blog/guide/changelog) / [Releasebot — Claude Code by Anthropic Release Notes April 2026](https://releasebot.io/updates/anthropic/claude-code) / [Vercel Changelog](https://vercel.com/changelog)

## セキュリティ

### IDP / 文書処理 AI の精度 2026 — 印刷文字 99%・手書き 95% に到達

AI 駆動の文書処理（IDP）分野で 2026 年の精度ベンチマークが出揃い始めた。

**精度の現状:**
- 印刷テキスト: エンタープライズ向けプラットフォームで 95〜99% 達成
- 手書き文字: GPT-5 等マルチモーダル LLM で 95%（従来 OCR は 46〜70%）
- 非構造化文書の直通処理率: 成熟した請求書自動化で 75〜90%（人手不要）

**主要ベンダー動向:**
- Microsoft Azure AI Foundry: Mistral Document AI を追加、OCR 精度 95.9%
- IBM Docling: GitHub スター 3.7 万超、シングルパス抽出で注目
- SAP Document AI: 32 業務プロセスで GA

**技術の焦点移動:** 2026 年の競争軸は「文字認識精度」から「文書推論」（文脈理解・異常検出・後続アクションのトリガー）に移行している。単なる OCR 精度競争の段階は実質的に終わっている。

**出典**: [VAO World — OCR AI Updates 2026](https://www.vao.world/blogs/OCR%20AI%20Updates%202026:%20What%E2%80%99s%20New%20in%20Accuracy,%20Cost,%20and%20Document%20Automation) / [IDP Software — Unverified: What Practitioners Post About OCR, Agents, and Tables](https://idp-software.com/news/idp-accuracy-reckoning-2026/) / [BizData360 — Intelligent Document Processing IDP Ultimate Guide 2026](https://www.bizdata360.com/intelligent-document-processing-idp-ultimate-guide-2025/)
