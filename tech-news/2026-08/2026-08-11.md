### 1. Microsoft Patch Tuesday 2026年8月版 — 400件以上のCVE修正、CVE-2026-68820（afd.sys）が野生で悪用中

2026年8月11日（第二火曜日）、Microsoftは月例セキュリティ更新プログラムを公開した。修正件数は400件超（情報源によって394〜421件）に上り、うち3件がゼロデイ脆弱性として認定されている。最も緊急度が高いのは**CVE-2026-68820**で、Windows Sockets APIの基盤カーネルドライバ `afd.sys`（Ancillary Function Driver for WinSock）にあるuse-after-free脆弱性だ。ローカルの認証済み攻撃者が特細工したアプリケーションを実行することでレースコンディションを引き起こし、SYSTEM権限への昇格が可能で、ユーザー操作は不要とされる。CVSSv3スコアは7.0（Important）だが、Microsoft自身が「野生での悪用を確認」と明言しており、実質的な緊急度は高い。afd.sysは2022年以降、CVE-2024-38193をはじめ合計4件の野生悪用ゼロデイを抱える常連ファイルとなっており、北朝鮮のLazarusグループが過去に同ドライバを悪用した実績も報告されている。残り2件のゼロデイはWindows Container Isolation（CVE-2026-72971、改ざん）とWindows User Profile Service（CVE-2026-62832、特権昇格・公開済み）だ。Windowsを運用する組織はWindows Updateの適用を本日中に完了させることが推奨される。

### 3. Rust 1.98 が8月20日にStable公開予定 — C可変引数関数の定義が解禁、18年来のFFIギャップを解消

Rust 1.98.0のstableリリースが2026年8月20日に予定されている。最大の新機能は **C可変引数関数の定義**（`c_variadic`フィーチャーの安定化）で、これまでRustはCの可変引数関数を呼び出すことはできたが「定義する」ことはできなかった。これにより、例えばC APIから可変引数コールバックを要求されるケースでCのシム（shim）を別途用意する必要がなくなる。もう一つの注目点は**PartialOrd最適化**で、`Ord`と`PartialOrd`を同一型に同時に`derive`した場合（最も一般的なパターン）、`partial_cmp`が`cmp`に直接委譲するよう修正された。これまで2018年から存在していたderiveマクロのバグで、無駄な比較処理が走っていた問題を解消する。また、インラインアセンブリで128ビット整数（i128/u128）が利用可能になり、ARMターゲット（thumbv7a/thumbv7r/thumbv8r系）がTier 2に昇格された。ライブラリ面ではString::from_utf16のエンディアン明示版、nonzero_from_str_radix、strip_circumfixなども安定化される。現在beta段階にあり、日程は予定通りのリリースが見込まれる。

## 新技術・新リリース

### Rust 1.98：C可変引数関数の定義とその意義

Rust 1.98で安定化される`c_variadic`により、CのABIに完全準拠した可変引数関数をRustで定義できるようになる。

```rust
// Rust 1.98 以降: C可変引数関数をRust側で定義可能
use std::ffi::VaList;

#[no_mangle]
pub unsafe extern "C" fn my_log(fmt: *const std::ffi::c_char, mut args: ...) {
    // argsはVaListとして処理可能
    let va: VaList = args.as_va_list();
    // ... Cライブラリ(例: vprintf)へ渡す処理など
}

// Rust 1.97以前: 可変引数関数の定義はコンパイルエラー
// → CのシムをCで書いてリンクする回り道が必要だった

// PartialOrd最適化（1.98で修正）
#[derive(PartialEq, Eq, PartialOrd, Ord)]  // 最も一般的なパターン
struct Priority(u32);

// 1.98以前: partial_cmpは独立した比較ロジックを生成（二重計算）
// 1.98以降: partial_cmpはcmpに直接委譲 → ゼロコスト

// インラインアセンブリで128bit整数が使用可能（1.98で追加）
let x: u128 = 0xDEAD_BEEF_CAFE_1234_5678_9ABC_DEF0_0001u128;
unsafe {
    std::arch::asm!(
        "/* 128bit ops on supported arches */",
        in("x0") x as u64,
    );
}
```

CのFFIとRustの統合における最後の主要な壁の一つが取り除かれたことで、既存のCライブラリをRustで段階的に置き換えるプロジェクト（Linuxカーネルのprintk系、組み込みファームウェアのログ基盤など）において、CシムなしのピュアRust実装が現実的な選択肢となる。コンパイラが型安全な可変引数の受け渡しを保証するため、Cで手書きすると発生しがちなva_listの取り違えによるUBリスクも軽減される。

**出典**: [Rust 1.98 Stable — byteiota](https://byteiota.com/rust-1-98-stable-c-variadic-naked-functions-august-2026/) / [Draft release notes for 1.98.0 — GitHub](https://github.com/rust-lang/rust/issues/160700)

## セキュリティ

### Patch Tuesday 2026年8月版 緊急対応ガイド — CVE-2026-68820（afd.sys）を最優先で

今月のPatch Tuesdayは件数（400件超）の多さよりも「野生悪用ゼロデイが含まれる」点が重要だ。

```text
=== 2026-08-11 Microsoft Patch Tuesday 緊急対応チェックリスト ===

[優先度: 緊急] CVE-2026-68820 — Windows Ancillary Function Driver for WinSock (afd.sys)
  種別:         Use-After-Free → Elevation of Privilege (→ SYSTEM)
  悪用状況:     野生で確認済み (Exploited in the Wild)
  CVSSv3:       7.0 (Important)
  攻撃条件:     ローカルアクセス + 認証済み / ユーザー操作不要
  注意:         afd.sysは2022年以降4件の野生ゼロデイの前歴あり
                過去にLazarusグループ（北朝鮮系）が同ドライバを悪用

  対応: Windows Update を適用 (2026-08 Cumulative Update)
  確認: winver でOSバージョンを確認 → KBxxxxxx を手動適用でも可

[優先度: 高] CVE-2026-72971 — Windows Container Isolation (unionfs.sys)
  種別:         Tampering（改ざん）
  影響:         コンテナ分離環境を利用する開発・本番環境

[優先度: 高] CVE-2026-62832 — Windows User Profile Service
  種別:         Elevation of Privilege（公開済み・悪用は未確認）
  影響:         ローカルユーザーからの特権昇格

[その他の重要パッチ（今週の優先対応）]
  N-able N-central     : CISA KEVに追加済み → 顧客環境での侵害が報告
  Progress LoadMaster  : CVE-2026-8037 コマンドインジェクション
  Veeam SPC            : 複数CVE（1件はCVSS 10.0）→ 即時パッチ必須

[確認コマンド例（Windows PowerShell）]
  # 適用済みKBを確認
  Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 10
  # Windowsの最終更新日確認
  (Get-Date (gwmi Win32_OperatingSystem).LastBootUpTime)
```

afd.sysの野生悪用は国家支援型攻撃者による標的型攻撃と関連する可能性が高く、特に防衛・政府・金融セクターは他の組織より迅速なパッチ適用が求められる。N-able N-centralはCISAのKEV（Known Exploited Vulnerabilities）カタログへの追加がすでに確認されており、MSP（マネージドサービスプロバイダー）経由で多数の顧客環境に影響が広がるサプライチェーンリスクを持つ点にも注意が必要だ。
