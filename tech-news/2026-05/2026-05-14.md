### Cloudflare Infire — カスタム LLM 推論エンジンで複数 GPU のメモリ効率を改善

Cloudflare が独自開発した LLM 推論エンジン **Infire** を InfoQ が詳報した。Infire は複数 GPU をまたいで大規模言語モデルを実行し、従来フレームワーク比でメモリ使用量を大幅に削減する設計になっている。Cloudflare Workers AI の基盤として組み込まれており、テナントごとに LLM を隔離しながらエッジノード上で効率的に推論を実行できるのが特徴だ。標準的な推論フレームワーク（vLLM / TGI）が前提とする「1 モデル・1 クラスター」設計とは異なり、マルチテナント・マルチモデルを想定したアーキテクチャになっている点が差別化要素で、エッジ AI インフラの設計思想として注目に値する。

```python
# Cloudflare Workers AI (Python SDK) を使った推論の基本パターン
# Infire バックエンドの恩恵を受けるクライアント側コード例
import cloudflare

client = cloudflare.Cloudflare(api_token="YOUR_API_TOKEN")

# Infire が裏側でマルチ GPU スケジューリングを処理する
response = client.workers.ai.run(
    account_id="YOUR_ACCOUNT_ID",
    model_name="@cf/meta/llama-4-scout-17b-16e-instruct",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain the Infire architecture in one sentence."},
    ],
    max_tokens=256,
)

print(response.result["response"])
# Infire は複数 GPU にモデルをシャーディングし、
# メモリ効率を保ちながらマルチテナントで LLM を提供する
```

### NGINX Rift（CVE-2026-42945）— CVSS v4 9.2、PoC 公開済み・即時パッチ適用を

NGINX Open Source 1.30.1 および 1.31.0 で修正された **CVE-2026-42945（NGINX Rift）** は、影響ノードの特定とバージョン確認から始めることが最優先だ。以下のコマンドで現在のバージョンと設定の危険箇所を確認できる。

```bash
# 現在の NGINX バージョンを確認
nginx -v
# 例: nginx/1.28.0 → 脆弱。1.30.1 または 1.31.0 に要アップグレード

# rewrite モジュールで危険なパターンが使われていないか確認
# ( $1, $2 キャプチャ + ? を含む rewrite ルールが対象 )
grep -rn 'rewrite.*\$[0-9].*?' /etc/nginx/
# 出力があった場合、該当ディレクティブの設定見直しが必要

# Ubuntu / Debian 系でのアップグレード手順
sudo apt update && sudo apt upgrade nginx

# RHEL / CentOS 系
sudo dnf update nginx

# アップグレード後の確認
nginx -v
# nginx/1.30.1 以上であれば対応完了

# PoC 公開済みのため、アップグレード完了まで
# 外部からの不審なリクエストをモニタリングすること
tail -f /var/log/nginx/error.log | grep -i "rewrite\|segfault\|heap"
```

### Microsoft 5 月 Patch Tuesday — 130 脆弱性・ゼロデイなし、Hyper-V と Azure DevOps に高危険度

Microsoft が 5 月の Patch Tuesday で **130 件以上の脆弱性**に対するセキュリティ更新を公開した。約 2 年ぶりにゼロデイ（野外悪用確認済み）なしの月となったが、高危険度の修正が複数含まれている。特に注目すべきは **CVE-2026-42826**（Azure DevOps、情報漏えい、CVSS 10.0）と **CVE-2026-40402**（Windows Hyper-V、特権昇格、CVSS 9.3）で、後者は低特権ゲスト VM からホスト環境への昇格を可能にする use-after-free の欠陥だ。パッチカテゴリ別では特権昇格が 61 件（47%）で最多、次いで RCE が 31 件（24%）。Windows が 66 件と最多のパッチを受け取り、Office 24 件・Azure 16 件が続く。ゼロデイなしという状況に安心せず、Hyper-V ホストと Azure DevOps 環境を使う組織は優先適用を推奨する。
