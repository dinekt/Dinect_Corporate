### 1. SAP Commerce Cloud CVE-2026-58231（CVSS 10.0）——パッチ公開3日後に実被害、無認証RCEが即時悪用される現実

SAP が 2026年8月のセキュリティパッチデー（8月11日）で修正した**CVE-2026-58231**は、CVSS スコア**10.0**という最大深刻度を持つ SAP Commerce Cloud の認証バイパス + リモートコード実行（RCE）脆弱性だ。脆弱性の根本原因は、プラットフォームの「Data Hub Adapter」拡張モジュールに存在する不適切な認可処理であり、攻撃者はデフォルトの認証クライアントを悪用し、検証が不十分な関数へ細工済み入力を送り込むことで、**有効な資格情報なしに任意コードを実行**できる。影響バージョンは COM_CLOUD 2211 および COM_CLOUD 2211-JDK21 で、修正済みバージョン 2211.55 / 2211-jdk21.17 以降へのアップグレードが推奨されている。8月14日、セキュリティ研究者 Defused がハニーポットへの悪用試行を検出——公開 PoC が存在しない状態でも攻撃者が独自に脆弱性を再現したことを意味し、「パッチ公開から悪用までの猶予時間」が3日以内に縮小していることを改めて示した。SAP Commerce Cloud はグローバルな電子商取引基盤として大手製造業・小売業・メディア企業が広く採用しており、未適用環境はサプライチェーン全体に波及するリスクをはらんでいる。

### 2. EU AI Act 第50条（透明性義務）施行——汎用AI提供者に技術文書・著作権遵守・学習データ開示を義務化

EU AI 規則（AI Act）の第50条「一般目的 AI モデルの透明性義務」が**2026年8月2日**に正式発効した。対象は汎用 AI（GPAI）モデルの提供者全般で、主な義務は①**技術文書**（モデルアーキテクチャ・学習手法・評価基準）の作成・更新、②**著作権法第53条(1)(c)および(d)を遵守**するための情報開示、③**学習データの概要サマリ**の公開——の3点だ。違反した場合の制裁は**全世界年間売上高の最大3%**に相当する課徴金で、大規模モデル（計算量 10²⁵ FLOP 超）には追加の「システミックリスク」評価義務も課される。8月中旬時点で、主要クラウドプロバイダーはコンプライアンス対応ドキュメントを順次公開しており、欧州の規制が事実上のグローバルスタンダードとして機能し始めている。一方、米中は独自のガバナンス路線を維持しており、企業が複数の規制体制へ同時対応する「コンプライアンス多重化」コストが業界課題として浮上している。AI モデルの競争力が性能ベンチマークだけでなく、透明性・説明可能性へと多次元化する転換点とも言える。

### 3. 米ミネソタ州で30以上の水道施設に協調サイバー攻撃——ICS/OTを直撃、浄水場の制御システムが一時停止

米ミネソタ州 IT サービス（MNIT）は、**30以上のコミュニティ水道施設**を標的とした協調型サイバー攻撃を確認した。攻撃はブラハム市の浄水処理施設で処理プロセスを一時的に停止させたほか、複数施設の**産業制御システム（ICS）/ 運用技術（OT）**に影響を与えた。水道インフラへのサイバー攻撃は 2021年のフロリダ州オールドスマー浄水場事件以降も散発的に発生しているが、今回は複数施設を同時に狙う「協調型」という点で規模が異なる。調査中の攻撃者の帰属や侵入経路は公表されていないが、水処理設備のネットワーク露出面（HMI の直接インターネット接続、古い SCADA システムへのデフォルト認証情報残存など）が依然として広く存在することが改めて浮き彫りになった。CISA は以前から水道・廃水処理セクターの OT セキュリティガイダンスを発行しているが、予算制約の大きな地方自治体運営施設への対策普及が追いついていないことが課題として残る。

## 新技術・新リリース

### Rust 1.98 ベータ公開——C 可変長引数関数の定義解禁・128ビット整数インラインASM対応、8月20日に安定版リリース予定

Rust 1.98.0 のベータ版が公開中で、**2026年8月20日**に安定版リリースが予定されている。主要な新機能は以下の3点だ。

**① C 可変長引数関数（c_variadic）の安定化**

これまで Rust は C の可変長引数関数を「呼び出す」ことはできたが、「定義する」ことはできなかった。1.98 でこの制限が撤廃される。対応呼び出し規約は `"aapcs"`・`"efiapi"`・`"sysv64"`・`"win64"`・`"cdecl"` およびそれぞれの `-unwind` バリアントで、ARM 組み込みボード・UEFI ファームウェア・Linux x86-64 ユーザーランド・Win64 をカバーする。

```rust
// Rust 1.98: C 可変長引数関数の定義（例: printf ラッパー）
#![feature(c_variadic)]  // 1.98 で stable に昇格

use std::ffi::VaList;

// 'cdecl' 呼び出し規約で可変長引数を受け取る関数
unsafe extern "C" fn my_printf(fmt: *const u8, mut args: ...) {
    // VaList を使って可変引数を順に取り出す
    let n: i32 = args.arg::<i32>();
    // ... (実装省略)
}

fn main() {
    unsafe {
        // 外部から呼び出す C 関数として公開可能
        my_printf(b"value: %d\n\0".as_ptr(), 42i32);
    }
}
```

**② 128ビット整数インラインASM サポート**

`u128` / `i128` がインラインアセンブリ制約に直接使用できるようになり、暗号ライブラリや高精度演算でのアセンブリ最適化が容易になる。

```rust
// u128 をインラインASM で扱う例（x86-64）
fn add128(a: u128, b: u128) -> u128 {
    let result: u128;
    unsafe {
        std::arch::asm!(
            "add {lo}, {blo}",
            "adc {hi}, {bhi}",
            lo = inout(reg) a as u64 => _,
            hi = inout(reg) (a >> 64) as u64 => _,
            blo = in(reg) b as u64,
            bhi = in(reg) (b >> 64) as u64,
            // 1.98: u128 を直接 inout に使用可能
        );
        result = 0; // 簡略化（実際は lo/hi を結合）
    }
    result
}
```

**③ `#[derive(PartialOrd)]` の比較ロジック改善**

2018年に Issue #49505 として報告されていた `#[derive(PartialOrd)]` の生成コードが非効率な比較ロジックを出力する問題が修正された。LLVM が最適化しやすいコードを生成するように変更され、派生マクロを多用する大規模ライブラリでのコンパイル後バイナリサイズ・実行速度が改善する。

```bash
# Rust 1.98 beta でテスト（安定版は 2026-08-20）
rustup install beta
rustup default beta
rustc --version
# rustc 1.98.0-beta.x (... 2026-08-xx)
```

**Langflow に RCE 脆弱性——AI パイプライン構築ツールが攻撃面に**

オープンソースの AI ワークフロー構築ツール**Langflow**に RCE 脆弱性が確認され、KEV に追加された。Langflow は非技術者が LLM・エージェント・RAG パイプラインを GUI で構築できるツールとして急速に普及しており、組織内での自己ホスト型 AI 開発環境が新たな攻撃対象として浮上している。AI ツールチェーンのセキュリティ評価が急務となっている。
