### 1. Kimi K3 オープンウェイト、7月27日公開確定——2.8兆パラメータ・MIT準ライセンスで史上最大のオープンモデルへ

Moonshot AI（月之暗面）の **Kimi K3** が7月27日（現地時間）にフルモデルウェイトをオープン公開する。K3は総パラメータ数2.8兆の混合エキスパート（MoE）アーキテクチャを採用し、100万トークンのコンテキストウィンドウをサポートするマルチモーダルモデルだ。ライセンスはModified MIT準拠（商用利用可・再配布可・改変可）で、自己ホスティングや派生モデルの開発が広く可能になる。Moonshot自身がClaude Fable 5やGPT-5.6 Solよりも総合性能が劣ることを認めているが、コーディングや汎用エージェントタスクではClaude Opus 4.8・GPT-5.5を上回るベンチマーク結果を示している。実務上の課題はモデルサイズにある——MXFP4（4ビット精度）でも重みファイルは約1.4TB、フル16ビットでは5.6TBに達する。個人でのセルフホストはH100クラスのGPUクラスターを前提とする規模だが、公開後にコミュニティによるAWQ/GGUF量子化版が登場することで段階的に普及が広がると見られている。3兆パラメータ級のオープンウェイトモデルが登場することで、オープンソースコミュニティでの研究・ファインチューニング・評価のダイナミクスが大きく変わる可能性がある。

### 2. 国連がAIガバナンス全加盟国対話を史上初開催——科学パネルが「壊滅的被害を防ぐ保証はない」と明言

7月5日にジュネーブで開幕した国連の**AI全加盟国グローバル対話**が、7月25日現在も各国の政策策定に影響を与え続けている。これは国連史上初めてすべての加盟国が参加する多国間AIガバナンス会議で、「AIが人類全体に安全・公平に利益をもたらせるか」という問いを中心に、政府・テック企業・学術・市民社会が議論した。同対話に先立つ7月1日、ヨシュア・ベンジオ（Yoshua Bengio）とマリア・レッサを共同委員長とする40人の専門家からなる**独立国際科学パネル（IISP on AI）**が予備報告書を公表し、「現時点の科学では、能力が向上し続けるAIシステムが壊滅的被害を引き起こさないという保証はできない」と明言した。特に深刻として指摘された課題は、ディープフェイクの99%がセクシュアルな内容で96%が女性・少女を標的にしているという現状と、「AIの能力進化が科学的理解および各国政府の適応速度を上回っている」という構造問題だ。EUのAI ActやG7 AI指針が既存する中で、国連レベルでの全加盟国合意形成の難しさも浮き彫りになっており、規制フレームワークの「断片化 vs 国際標準化」が今後の論点となる。

### 3. エージェントAIが2026年CISOの最大リスクに——「Agent Zero Trust」がBlack Hat 2026の主要議題へ

Forresterが「2026年CISOにとってエージェントAIの脅威が最大のリスク」と発表し、Black Hat USA 2026（7月26-31日）でMicrosoftをはじめ複数のセキュリティベンダーがエージェントAIのゼロトラスト設計を主要セッションで取り上げた。7月22日に公開された**Sophos AI Security 2026レポート**は、企業内でのAIエージェント・AIアシスタント採用拡大に伴い、「AIアイデンティティ」が新たな攻撃表面として確立したことを警告している。エージェントAIは自律的にタスクを実行し、データベースへのアクセス・ファイル操作・クロスプラットフォーム通信を行うため、侵害時の横展開が従来のマルウェアより高速かつ広範になる。代表的な攻撃ベクターとして挙がっているのは、プロンプトインジェクション・ツール悪用による権限昇格・メモリポイズニング・カスケード障害・サプライチェーン攻撃の5種類だ。「Agent Zero Trust」という概念が台頭し、AIエージェントを「内部の潜在的脅威」として扱い、ランタイム監視と厳格なガードレールを敷くアーキテクチャが業界標準へと向かっている。セキュリティ専門家の48%がエージェントAIをヘッドライントップの攻撃ベクターとして挙げており、従来のエンドポイント・ネットワーク中心の防御からAIランタイム監視へのシフトが加速している。

### Kimi K3 アーキテクチャ詳細と自己ホストの現実

7月27日にオープンウェイトが解禁されるKimi K3は、MXFP4精度での推論を前提として設計されており、FP16より4倍のメモリ効率を実現している。ただし実際の推論には以下のハードウェア要件が必要となる：

```text
=== Kimi K3 自己ホスト要件試算 ===

モデルウェイト（MXFP4）: 約 1.4 TB
モデルウェイト（FP16）:  約 5.6 TB

最小構成（MXFP4 推論）:
  H100 SXM5 (80 GB VRAM) × 18〜20 枚
  または HBM3e 搭載 GPU クラスター相当

推奨構成（スループット重視）:
  H100 SXM5 (80 GB VRAM) × 32 枚 以上
  高速 NVLink バックプレーン推奨

コンテキストウィンドウ: 1,000,000 トークン
ライセンス:             Modified MIT（商用可・改変可）
マルチモーダル:         テキスト + 画像 ネイティブ対応
公開予定日:             2026-07-27（Hugging Face）
```

Hugging Faceへの公開後、コミュニティによるAWQ/GGUF量子化版が登場することが予想されており、より低スペック環境への展開も数週間以内に可能になる見込みだ。また、Moonshot AIはKimi K3のAPIを既にサービスとして提供しており、クラウド経由での利用はすぐに可能だ。

## セキュリティ

### ClamAV 7件のCVE修正——20年前のコードに起源を持つパーサ脆弱性が一斉対処

Cisco傘下のオープンソースアンチウイルス**ClamAV**が**バージョン1.5.3 / 1.4.5**を7月初旬にリリースし、パッカー・アーカイブ・DMGパーサに起因する7件のCVEを修正した。中でも注目される2件が以下だ：

```text
=== ClamAV CVE 優先対応チェックリスト ===

[CVE-2026-20215 — 7zパーサ サブストリームカウントオーバーフロー]
  影響バージョン: ClamAV < 1.5.3 / < 1.4.5
  攻撃ベクター:   細工した .7z ファイルをスキャンさせるだけで DoS
  根本原因:       サブストリーム数の整数オーバーフロー
                  → パーサメタデータ配列の過少アロケーション
  悪用状況:       野生での悪用なし（報告時点）

[CVE-2026-20216 — InstallShield アーカイブ 展開制限バイパス]
  影響バージョン: ClamAV < 1.5.3 / < 1.4.5
  攻撃ベクター:   悪意ある InstallShield アーカイブ経由で DoS
  根本原因:       展開制限の境界チェック不備
  悪用状況:       野生での悪用なし（報告時点）

[共通対処手順]
  1. clamav --version で現在のバージョンを確認
  2. 1.5.3（安定版）または 1.4.5（LTS系）へアップデート
  3. メール / Web / ファイル共有経由のスキャン対象ファイルに注意
  4. Cisco Secure Endpoint 等 Cisco 製品利用者は該当アドバイザリを確認
```

これら脆弱性の根源は最大20年前のコードに起因するものが含まれており、レガシーOSSコンポーネントの技術的負債がいかに長期にわたって潜在リスクを生み出すかを示す事例として注目されている。未認証の攻撃者がメール・Webダウンロード・ファイル共有経由で細工したファイルを送り込むことでClamAVプロセスを強制終了できるため、スキャン機能が無効化されるリスクがある点に注意が必要だ。
