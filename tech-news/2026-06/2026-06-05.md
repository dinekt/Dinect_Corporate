### 2. 米議会に超党派 AI 大枠立法「大アメリカ AI 法案」— 269 ページ、3 年間の州 AI 法プリエンプションが最大の争点

共和党 Jay Obernolte 議員と民主党 Lori Trahan 議員を中心とした超党派グループが 6 月 4 日、**「The Great American Artificial Intelligence Act（大アメリカ AI 法案）」**のディスカッションドラフト（269 ページ）を公開した。最大の特徴は**フロンティア AI モデルの「開発」を規制する州法を 3 年間プリエンプション（連邦法優先）する条項**で、カリフォルニア州の AI 訓練データ開示法（AB 2013）やコンテンツウォーターマーク法（SB 942 の一部）が対象として名指しされている。法案は同時に AI 安全保障機関 CAISI を法定機関として正式化し、ガイドライン・ベストプラクティスの策定と米国・外国製 AI システムの評価を担わせる。消費者団体 Public Citizen・労働組合 AFT・Public Knowledge はいずれも反対声明を発表し、「州が積み上げてきた AI 安全規制の最低水準が連邦上限に変わる」と強く批判している。EU AI Act の高リスク区分本格適用（8 月）・中国 AI データ規制と同じ時期に米国が連邦統一ルール構築に向かうかどうかは、グローバル AI ガバナンスの地図を塗り替える可能性を秘めており、国際展開する AI 企業のコンプライアンス設計に直接影響する。

### Mojo 1.0 ファーストベータ公開 — Python 構文互換でシステムレベルの性能を狙うハイブリッド言語

Modular が開発する **Mojo 1.0** のファーストベータが 2026 年に公開された。Mojo は「Python の可読性 × Rust のパフォーマンス」を掲げる新言語で、Python 構文と高い互換性を保ちつつ、`fn`（静的型付き関数）・`struct`（スタック確保型データ構造）・SIMD ベクトル演算などの低レベル最適化機能を同一ファイル内で混在させられる点が最大の特徴だ。AI/ML ワークロードで C++ 水準の実行速度を達成しながら、NumPy・PyTorch などの Python 資産をそのまま呼び出せる。`def` で書いた既存 Python コードを `.mojo` ファイルにほぼそのまま移行し、パフォーマンスクリティカルな箇所だけ `fn` に書き直す段階的最適化アプローチが採用されており、Python から移行しやすい設計になっている。AI インファレンス・高性能数値計算・システムプログラミングを一つの言語スタックで完結させたい開発者にとって注目の選択肢が増えた格好だ。

```mojo
# Mojo 1.0 Beta — Python 互換構文 + 静的型で高速な数値計算
from math import sqrt

# fn: 静的型付き関数（引数・戻り値の型を明示、コンパイル時最適化が有効）
fn dot_product(a: List[Float64], b: List[Float64]) -> Float64:
    var result: Float64 = 0.0
    for i in range(len(a)):
        result += a[i] * b[i]
    return result

# struct: スタック確保型データ構造（ヒープアロケーション不要）
struct Vec3:
    var x: Float64
    var y: Float64
    var z: Float64

    fn __init__(inout self, x: Float64, y: Float64, z: Float64):
        self.x = x
        self.y = y
        self.z = z

    fn magnitude(self) -> Float64:
        return sqrt(self.x ** 2 + self.y ** 2 + self.z ** 2)

    fn normalize(self) -> Vec3:
        let mag = self.magnitude()
        return Vec3(self.x / mag, self.y / mag, self.z / mag)

fn main():
    let v = Vec3(1.0, 2.0, 2.0)
    print("magnitude:", v.magnitude())    # → 3.0
    let n = v.normalize()
    print("normalized:", n.x, n.y, n.z)  # → 0.333 0.666 0.666

    # Python コードと相互運用（def で書いた関数をそのまま混在可）
    let scores = List[Float64](0.9, 0.7, 0.85)
    let weights = List[Float64](0.5, 0.3, 0.2)
    print("weighted score:", dot_product(scores, weights))  # → 0.822
```

### 6 月 Patch Tuesday 予報 — Windows Netlogon RCE（CVE-2026-41089）が野放しで悪用中、Exchange XSS・Android 特権昇格も重点対応

6 月 10 日（米国時間）の **6 月 Patch Tuesday** に先立ち、Help Net Security が事前予報を公開した。最優先事項は既に野良悪用（In-the-Wild Exploitation）が確認されている **CVE-2026-41089** で、Windows Netlogon のスタックベースバッファオーバーフローを突いてドメインコントローラ（DC）上でリモートコード実行が可能となる。特別細工したネットワークリクエスト一本で DC 上でコードが実行できるこの脆弱性は、Active Directory 環境全体の掌握に直結するため緊急対応が求められている。Exchange Server の **CVE-2026-42897**（Outlook Web Access クロスサイトスクリプティング・CVSS 8.1）も悪用確認済みで同パッチに含まれる見通しだ。Google の 6 月 Android セキュリティ情報では計 124 件（うち Critical 18 件）が修正対象となっており、**CVE-2025-48595**（フレームワーク整数オーバーフロー → ローカル特権昇格・CVSS 8.4）が標的型攻撃で悪用されたことが確認されている。また Adobe は Creative Cloud（inCopy・inDesign・Photoshop・Acrobat）のアップデートを予定しており、Google Chrome 150 最終版も Patch Tuesday 前後にリリースされる見通しだ。

```powershell
# --- CVE-2026-41089 (Windows Netlogon RCE) 暫定軽減策 ---

# 1. Netlogon 通信を DC 管理サブネットのみに制限するファイアウォールルール
New-NetFirewallRule -DisplayName "Block-Netlogon-External" `
    -Direction Inbound -Protocol TCP -LocalPort 135,49152-65535 `
    -RemoteAddress Internet -Action Block

# 2. Netlogon サービスのセキュア チャネル設定を最大強度に
Set-ItemProperty `
    -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Netlogon\Parameters" `
    -Name "RequireSignOrSeal" -Value 1 -Type DWord
Set-ItemProperty `
    -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Netlogon\Parameters" `
    -Name "SealSecureChannel" -Value 1 -Type DWord

# 3. パッチ適用状況の確認（Netlogon 関連 KB）
Get-HotFix | Where-Object { $_.Description -match "Security" } |
    Sort-Object InstalledOn -Descending | Select-Object -First 10

# --- CVE-2026-42897 (Exchange OWA XSS) 暫定対策 ---
# OWA を外部公開している場合はリバースプロキシで CSP ヘッダを追加する
# Add-WebConfigurationProperty `
#     -pspath 'IIS:\Sites\Default Web Site\owa' `
#     -filter "system.webServer/httpProtocol/customHeaders" `
#     -name "." `
#     -value @{name="Content-Security-Policy";value="default-src 'self'"}

# --- Android パッチレベルの確認（ADB 経由）---
adb shell getprop ro.build.version.security_patch
# 出力が 2026-06-01 以上であれば CVE-2025-48595 は修正済み
```

**影響範囲と優先度**: CVE-2026-41089 は Active Directory 環境の全 DC が対象で、悪用が確認されているため Patch Tuesday 公開と同時に DC から優先適用する。Exchange Server は OWA 外部公開の有無を確認し CSP ヘッダを即時追加する。Android は MDM でセキュリティパッチレベル 2026-06-01 以上への強制更新を展開する。
