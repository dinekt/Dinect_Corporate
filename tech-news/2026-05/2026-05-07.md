### 2. GitHub Enterprise Server の RCE（CVE-2026-3854）— 「git push 1 回」でバックエンドをハイジャック、自ホスト型の 88% が未パッチ

Wiz Research が 3 月 4 日に発見し、GitHub が即日修正をデプロイした重大 RCE 脆弱性 **CVE-2026-3854（CVSS 8.7）** について、GitHub Enterprise Server（GHES）の自ホスト型インスタンスのうち **88% がいまだバージョン 3.19.3 以降へのアップグレードを完了していない**ことが明らかになった。攻撃手法は巧妙で、Git の push option 値がサニタイズされないまま内部サービス `babeld` の X-Stat ヘッダー（セミコロン区切り形式）に挿入されることを悪用する。攻撃者はセミコロンを含む crafted push option を送信することで、①非本番 `rails_env` の注入によるサンドボックス回避、②`custom_hooks_dir` の差し替えによるフックディレクトリ制御、③`repo_pre_receive_hooks` へのパストラバーサルを経由した任意コマンド実行、という 3 段階インジェクションチェーンを構成できる。GitHub.com は修正済みで利用者側の対応は不要だが、自ホスト型 GHES を運用する組織は **3.19.3 以降への即時アップグレード**が必要で、遅延はリポジトリ内の全コードとシークレットの漏洩リスクを意味する。

### 3. CISA、Linux root 権限昇格バグ（CVE-2026-31431）を KEV に追加 — 連邦機関の対応期限は 5 月 15 日

米 CISA（Cybersecurity and Infrastructure Security Agency）が、Linux カーネルのローカル権限昇格脆弱性 **CVE-2026-31431（CVSS 7.8）** を「既知の悪用済み脆弱性カタログ（KEV）」に追加した。この脆弱性は、非特権のローカルユーザーが root 権限を取得できる欠陥で、すでに実環境での悪用が確認されている。米連邦機関には **5 月 15 日**までの修正適用が義務付けられており、民間組織にも同様の優先対応が強く推奨される。Mandiant の M-Trends 2026 レポートが同時期に示したデータによると、CVE 開示から 24 時間以内に悪用が開始される割合が **28.3%** に達しており、パッチ適用サイクルの短縮が業界全体の急務となっている。クラウド環境でも Linux ホストを運用している場合、コンテナ脱出・横断移動（lateral movement）の踏み台になるリスクがあるため、カーネルバージョンの確認と迅速なアップデートが求められる。

### Anthropic 開発者デーで発表された「Dreaming」— AI がセッション間に自律的に振り返り・自己更新

Anthropic は開発者向けイベントで、Claude に**「Dreaming」**と呼ぶ新機能を公開した。人間の睡眠中の記憶統合になぞらえた名称で、AI がセッションとセッションの合間に直前の作業ログを自律的にレビューし、ユーザーの好みや繰り返しパターンをプロファイルファイルへ書き出す仕組みを指す。従来の長期記憶アプローチが「会話内の明示的な指示を記録する」ものだったのに対し、Dreaming は**暗黙の行動パターンを統計的に抽出してコンテキストファイルを更新**する点が新しい。

同イベントでは Claude Code および Claude API の**利用制限の大幅緩和**も発表された。Pro・Max・Team・Enterprise の全プランでレートリミットが最大 2 倍に引き上げられ、従来 Pro / Max ユーザーに適用されていたピーク時間帯の制限（peak-hour reduction）も撤廃された。

```python
# Dreaming パターンの概念実装イメージ（公式実装ではなく概念説明コード）
# セッション終了フックで呼び出されると想定

import anthropic

client = anthropic.Anthropic()

def run_dreaming_review(session_log: str, profile_path: str) -> None:
    """セッションログを振り返り、ユーザープロファイルを更新する。"""
    with open(profile_path, "r") as f:
        current_profile = f.read()

    response = client.messages.create(
        model="claude-opus-4-7-20260416",
        max_tokens=1024,
        system=(
            "あなたはセッション終了後にユーザーの行動ログを分析し、"
            "好みやパターンを抽出してプロファイルを更新するエージェントです。"
            "既存プロファイルとの差分のみを JSON で返してください。"
        ),
        messages=[
            {
                "role": "user",
                "content": (
                    f"<current_profile>\n{current_profile}\n</current_profile>\n\n"
                    f"<session_log>\n{session_log}\n</session_log>"
                ),
            }
        ],
    )

    diff = response.content[0].text
    # 差分を既存プロファイルにマージ（実装省略）
    print(f"Profile updated: {diff}")
```

## セキュリティ

### CVE-2026-31431（Linux 権限昇格）— 対応チェックリスト

CISA が KEV 追加した脆弱性に対する即時対応をまとめる。

**確認・対処事項:**
- 実行中の Linux カーネルバージョンを確認（`uname -r`）し、ディストリビューションのセキュリティアドバイザリで対象バージョン範囲を照合
- 物理・仮想ホストに加え、**コンテナホスト（EKS / GKE ノードプール含む）** も対象になるため、マネージドクラウドサービスのノード更新機能を確認
- 修正済みカーネルが提供されている場合は即時適用。連邦機関は 5 月 15 日が法的期限
- 多層防御として、非特権プロセスからのカーネル syscall を制限する seccomp プロファイルの適用状況を確認

### CVE-2026-23918（Apache HTTP/2）— CVSS 8.8 の DoS・潜在的 RCE

Apache HTTP Server 2.4.66 以前に存在する **CVE-2026-23918** は、HTTP/2 プロトコル処理における double free に起因し、サービス停止（DoS）に加え潜在的な RCE も研究者が指摘している。修正版は **2.4.67** で提供済み。Apache を直接ホストしている場合のほか、リバースプロキシ構成や CDN オリジンとして Apache を利用しているケースも対象になるため、インフラ全体のバージョン棚卸しが必要になる。
