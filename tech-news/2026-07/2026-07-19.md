### 1. TypeScript 7.0 GA（7/8）＋ Rust 1.97 stable（7/9）— 開発者ツールチェーン刷新の週

Microsoft が **TypeScript 7.0** を7月8日に正式リリース（GA）した。最大の変更点はコンパイラそのものの実装言語をJavaScriptからGo言語へ全面移植したことで、型チェック・パース・エミットを並列実行することで**従来比最大10倍の高速化**を実現している。大規模プロジェクトでのビルド時間短縮が即効性の高い恩恵として注目されており、`npm install -D typescript` で新コンパイラを取得できる。プログラマティックAPIは7.1まで安定保証されないため、移行期間中はTypeScript 6.0を並走させる互換パッケージ `@typescript/typescript6`（`tsc6` コマンドを提供）が用意された。翌7月9日には **Rust 1.97 stable** もリリースされ、同月の TIOBE Index で Rust が**初めてTop 10入り（10位）**を記録した（1年前は18位）。PythonはTop 1位を堅持（シェア18.94%）し、Go は13位へ後退した。TypeScript 7.0のGoベース移行とRustのTop 10入りという2つの出来事が重なり、システム言語がWebエコシステムの「裏側」まで浸透しつつある転換点として記憶される週となった。

大手会計・コンサルティングファームの **Ernst & Young（EY）** が、ITサポートチケット基盤への不正アクセスを確認した。侵害期間は2026年3月28日〜4月12日で、第三者が顧客の**税務書類・投資保有文書**などをダウンロードしていたことが判明した。企業向けITサポート基盤というサプライチェーン上の中間層を狙った攻撃パターンは、直接的なシステム侵害より検知が困難なため、監査・コンプライアンス業界全体への警戒を高めている。一方、米国政府はイラン系国家支援ハッカーグループが**米国の民間水道施設**を標的にした攻撃活動を継続していると警告を発した。水道・廃水処理インフラは老朽化したOT（運用技術）システムが残存しており、インターネット露出した管理インターフェースが攻撃の足がかりとなるケースが多い。また今週の **Cybersecurity News Weekly Newsletter** ではEYブリーチのほか、Wpzshellエクスプロイトや Notepad++ の脆弱性を含む20本以上の重要インシデントが報告されており、大企業・OSS・重要インフラが同時並行で攻撃にさらされている現状が浮き彫りになった。

### TypeScript 7.0: Goベースコンパイラへの移行ガイド

TypeScript 7.0 は npm の `latest` タグで配布されており、新規プロジェクトは通常の `npm install -D typescript` で取得できる。既存プロジェクトでは以下の点に注意が必要だ。

```bash
# TypeScript 7.0 をインストール（latest タグ = 7.0 GA）
npm install -D typescript

# バージョン確認
npx tsc --version
# Version 7.0.x

# TypeScript 6.x を並走させたい場合（互換パッケージ）
npm install -D @typescript/typescript6
# → tsc6 コマンドで TS6 コンパイラを呼び出せる
npx tsc6 --version
# Version 6.x.x
```

```typescript
// TypeScript 7.0 では構文上の破壊的変更はほぼなし
// パフォーマンス恩恵は大規模プロジェクトほど顕著

// 例: 大規模プロジェクトのビルド時間比較イメージ
// TS 6.x: ~60秒 → TS 7.0: ~6秒（10倍高速化）

// 型システムは引き続き同等の厳密さで動作
type ApiResponse<T> = {
  data: T;
  status: "ok" | "error";
  timestamp: string;
};

async function fetchUser(id: string): Promise<ApiResponse<{ name: string }>> {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}
```

プログラマティックAPI（`ts.createProgram()` 等）は **TypeScript 7.1 まで安定保証されない** ため、ツール作者・モノレポ管理者は移行時期の調整を推奨する。ビルドツール（Vite・esbuild・webpack）側の対応状況も各プロジェクトで確認が必要だ。

### 重要インフラ狙いの複合攻撃: EYブリーチ＋水道OT侵害の教訓

```text
=== 2026年7月 重要インフラ攻撃 サマリー ===

[インシデント 1] Ernst & Young ITサポートチケット基盤侵害
  期間    : 2026-03-28 〜 2026-04-12
  手口    : 第三者によるサポートチケット基盤への不正アクセス
  流出物  : 顧客の税務書類・投資保有文書
  教訓    : サードパーティ製ITサービス基盤を経由した
            サプライチェーン攻撃は検知難度が高い
            → ITSMツールのアクセスログ監視を強化すること

[インシデント 2] イラン系ハッカーによる米国水道インフラ攻撃
  標的    : 米国内の民間水道・廃水処理施設
  手口    : インターネット露出したOT管理インターフェース

  脅威    : 化学注入制御の改ざん・サービス停止
  推奨策  :
    - インターネット直結OT機器の即時棚卸し
    - VPNまたはゼロトラストゲートウェイへの切り替え
    - 多要素認証（MFA）の全OT管理端末への適用
    - CISA ICS-CERT アドバイザリの定期確認

[Five Eyes 警告（7月発表）]
  内容    : フロンティアAIモデルが数か月以内に
            攻防両面のサイバー能力を「根本的に変容」させる
  対策    :
    - AIが生成するフィッシング・コード・音声の検証プロセス整備
    - ID確認・安全監査の強化
    - AIメディアへのデフォルト透かし（watermarking）の実装検討
```

今週の一連のインシデントが示す共通点は「直接侵害ではなく迂回路を使った攻撃」の増加だ。EYのケースはエンドユーザーではなくサポート基盤を標的にし、水道施設のケースは制御ネットワークの境界を侵食する。さらにFive Eyesが指摘するようにAIが攻撃ツールの自動生成・改良に活用されるようになれば、既存の防御サイクルでは対応が間に合わなくなるリスクが高まる。エージェンティックAIを使ったゼロデイ自動発見は「既存の防御アーキテクチャが設計速度を超えた攻撃速度に直面する」という新しい現実を意味し、インシデント対応計画のアップデートが急務となっている。
