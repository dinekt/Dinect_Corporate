### 1. OpenAI の内部モデルが 80 年来の Erdős 幾何学予想を自律的に反証 — AI が初めて独立した数学的証明を達成

OpenAI は 5/20 に、内部汎用推論モデルが 1946 年に Paul Erdős が提唱した「平面単位距離問題」の中心的予想を自律的に反証したと発表した。この問題は「n 点を平面上に配置したとき、距離 1 となるペアの最大数」を問うもので、約 80 年にわたり正方格子がほぼ最適と信じられてきた。OpenAI のモデルは Golod-Shafarevich 理論・無限クラス体塔などの代数的数論を駆使し、正方格子を多項式的に上回る n^(1+δ)（δ > 0）の構成族を発見した。Princeton 数学者の Will Sawin が δ = 0.014 と精緻化し、フィールズ賞受賞者の Tim Gowers も「AI 数学のマイルストーン」と評した。AI が単独で著名な未解決問題を解いた初の事例として、数学コミュニティへの衝撃は大きい。

## 新技術・新リリース

### Google Managed Agents in Gemini API — エージェントに隔離 Linux 環境を動的プロビジョニング

Google I/O 2026 で発表された **Managed Agents** は、Gemini API 上でエージェントワークフローを構築する際に、コード実行・Web ブラウジング・ファイル管理を安全に行える隔離サンドボックスを自動プロビジョニングするサービスだ。内部的には **Antigravity** と呼ばれる Gemini 3.5 Flash ベースのエージェントがサンドボックスを駆動する。

```python
import google.generativeai as genai

# Managed Agents を使ったエージェント起動例（概念コード）
genai.configure(api_key="YOUR_API_KEY")

model = genai.GenerativeModel(
    model_name="gemini-3.5-flash",
    tools=["code_execution", "web_search", "file_management"],
)

# エージェントに隔離サンドボックスで複数ステップタスクを委譲
response = model.generate_content(
    "以下のリポジトリをクローンして依存関係を解析し、脆弱なパッケージを列挙せよ: "
    "https://github.com/example/project",
    generation_config={"agent_mode": "managed"},
)

print(response.text)
```

従来のエージェントフレームワーク（LangChain、AutoGen 等）では開発者がサンドボックス環境を自前で用意する必要があったが、Managed Agents はその複雑さをサービス側に吸収し、セキュリティと再現性を高める設計となっている。エージェントが生成したコードはホスト環境から完全に分離されるため、意図しないシステム変更のリスクが低減される。

## セキュリティ

### Laravel-Lang 供給チェーン攻撃 — 影響確認と緊急対処手順

```bash
# 1. composer.lock で影響パッケージを確認
grep -E "laravel-lang/(lang|http-statuses|attributes|actions)" composer.lock

# 影響バージョン（2026-05-22 以降に公開された全タグが対象）
# 安全なバージョンへの固定（Packagist の公式回復後）
composer require laravel-lang/lang:@stable --update-with-all-dependencies

# 2. 環境変数・クレデンシャルのローテーション（最優先）
# AWS
aws iam list-access-keys --user-name <user>
aws iam delete-access-key --access-key-id <old-key>
aws iam create-access-key --user-name <user>

# GCP サービスアカウントキーのローテーション
gcloud iam service-accounts keys list --iam-account=<sa>@<project>.iam.gserviceaccount.com
gcloud iam service-accounts keys delete <key-id> --iam-account=<sa>@<project>.iam.gserviceaccount.com

# 3. Docker / Kubernetes 認証情報の無効化
kubectl get secrets --all-namespaces | grep docker
kubectl delete secret <secret-name> -n <namespace>
# 新しい imagePullSecret を再発行して Pod に適用

# 4. SSH 鍵のローテーション
# GitHub: Settings → SSH and GPG keys → 旧鍵を削除、新鍵を追加
# ~/.ssh/ 内の秘密鍵を再生成
ssh-keygen -t ed25519 -C "your_email@example.com"

# 5. ブラウザ保存パスワードの一括変更を検討
# 特に Chrome / Firefox の saved passwords は平文抽出対象となるため要注意

# 6. CI/CD トークン（GitHub Actions, CircleCI 等）の無効化と再発行
# GitHub: Settings → Developer settings → Personal access tokens → Revoke all
```

攻撃を受けたホストは composer install / update を実行しただけで感染する仕組みであるため、CI/CD パイプラインで影響バージョンを使用した環境は全て侵害済みとみなし、シークレットのフルローテーションが必要だ。

**出典**: [Supply Chain Attack Targets Laravel-Lang Packages — Aikido](https://www.aikido.dev/blog/supply-chain-attack-targets-laravel-lang-packages-with-credential-stealer) / [Hackers Compromised 233 Versions of Laravel-Lang Packages — CyberSecurityNews](https://cybersecuritynews.com/laravel-lang-packages-compromised/) / [Laravel-Lang Compromise — Socket.dev](https://socket.dev/blog/laravel-lang-compromise)

### Cisco Secure Workload CVE-2026-20223（CVSS 10.0） — 未認証 REST API アクセスが可能

Cisco Secure Workload（旧 Tetration）に CVSS **10.0** の脆弱性 CVE-2026-20223 が報告された。REST API エンドポイントへの検証・認証が不十分であることが原因で、ネットワーク到達可能な攻撃者が認証なしで任意の API 操作を実行できる。マイクロセグメンテーション・ゼロトラストポリシーの管理基盤として使われる製品だけに、侵害された場合のインフラ全体への影響が大きい。Cisco からセキュリティアドバイザリが公開されており、修正バージョンへの移行が推奨される。
