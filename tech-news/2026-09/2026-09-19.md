## 開発環境の最新アップデート

### 1. Claude Platform、Chromeセッションも監査対象へ

**区分：公式更新**。Anthropicは9月18日、Compliance APIのローカルセッション用エンドポイントがClaude in Chromeのセッション記録も返せるようになったと発表した。Claude Enterprise組織向けベータで、既存のCompliance Access Keyと`read:compliance_user_data`スコープを使う。コーディングエージェントの操作面がターミナルやIDEからブラウザへ広がるほど、どの面で何を実行したかを同じ監査系へ集める設計が重要になる。本記事では実環境でのAPI応答までは試していない。

**出典**: [Anthropic — Claude Platform release notes](https://platform.claude.com/docs/en/release-notes/overview)

### 2. Visual Studio 2026、BYOK対応Agent Modeをプレビュー提供

**区分：公式更新**。MicrosoftのVisual Studio 2026 September Updateでは、Bring Your Own Key（BYOK）で複数のモデル提供元を接続できるAgent Modeがプレビュー提供されている。公式ノートではMicrosoft Foundry、OpenAI、Anthropic、Ollamaなどが対応先として挙げられ、モデルによって一部機能に対応しない場合は明示される。ハーネス側がモデル差を吸収しきれないケースを黙って失敗させず、能力差として扱う点は環境設計の参考になる。9月15日公開の18.10.1では別途、ワークフローデザイナーとコード生成の不具合も修正された。

**出典**: [Microsoft Learn — Visual Studio 2026 release notes](https://learn.microsoft.com/en-us/visualstudio/releases/2026/release-notes)

## 今日の実践Tips

### AGENTS.mdに検証手順と完了条件をまとめる

**区分：公式推奨を土台にした編集部の提案**

#### 目的

エージェントが毎回リポジトリを探索し直したり、誤ったビルド順序で失敗したりするのを減らす。期待を抽象的な文章ではなく、実行可能なコマンド、完了条件、禁止境界として渡す。

#### 対象・前提

Codexで`AGENTS.md`を使うリポジトリと、Claude Codeでも同じ指示資産を共有したいチームを想定する。ビルド、lint、テスト、CIの正しい順序を一度は人間が確認できることが前提だ。

Codexは作業前に`AGENTS.md`を読み、ルートから現在ディレクトリへ向かって指示を重ねる。Claude Codeはv2.1.277以降、条件を満たす環境で`AGENTS.md`を直接読めるが、`CLAUDE.md`が存在する場合の既定動作や、Bedrock等で利用できない場合があるため、読み込み条件を確認する必要がある。

#### 手順

以下は、例示した`npm` scriptsが`package.json`に定義されているNode.jsプロジェクトを前提とした設定例である。実際の導入では、リポジトリで利用しているパッケージマネージャーとscriptsを確認して置き換える。

```markdown
# AGENTS.md

## Repository map
- `src/`: application code
- `tests/`: unit and integration tests
- `.github/workflows/ci.yml`: required CI checks

## Setup and validation
- `npm ci`
- `npm run lint`
- `npm test`
- `npm run build`

## Completion criteria
- 変更に対応するテストを追加または更新する
- プロジェクトで定めた検証コマンドの結果を報告する
- 実行していない確認を「成功」と書かない

## Boundaries
- 本番依存関係の追加は事前確認する
- `.env*`、資格情報、生成済み成果物をコミットしない
```

コマンドの実行順序はプロジェクト依存であり、この例の順番が常に正しいわけではない。依存関係のインストール、生成処理、lint、テスト、ビルドの前提関係を確認して、実際に成功した順序を記載する。サービス固有のコマンドや権限制約は配下へ分離する。Codex向けの一時上書きには`AGENTS.override.md`を使える。Claude Codeと共用する場合は優先順位が完全には同じでないため、Project instructions設定を確認し、必要なら`CLAUDE.md`から明示的に取り込む。

#### 確認方法

1. 新しいセッションで、読み込んだ指示元と検証手順を列挙させる。
2. 小さな変更を与え、プロジェクトで定めた順序どおりにコマンドが実行・報告されるかを見る。
3. CI結果と報告を照合し、ローカル成功だけで完了扱いになっていないか確認する。
4. モノレポでは別ディレクトリから起動し、階層ルールが意図どおり変わるか確認する。

この例は記事作成環境で実リポジトリへ導入していないため、動作確認済みのテンプレートではない。

#### 注意点

- 指示ファイルは権限制御の代わりにならない。sandboxや`permissions.deny`のような強制層と分ける。
- lintの書式規則など機械判定できるものはCIへ寄せる。
- 実在しないコマンドを書かない。GitHubの公式ガイドも、手順を実行して検証し、失敗や前提条件を記録するよう勧めている。
