### 1. IBM Think 2026 — watsonx Orchestrate 次世代マルチエージェント制御基盤を発表、企業 AI の「量産フェーズ」へ

IBM が 5 月 5〜6 日に開催した年次カンファレンス **Think 2026** で、エンタープライズ AI 戦略の大幅刷新を発表した。目玉は次世代 **IBM watsonx Orchestrate**（プライベートプレビュー）で、複数ベンダーの AI エージェントを単一ポリシーモデル下で統合管理する「マルチエージェント制御プレーン」として位置付けられる。同時に発表された **IBM Bob** は、セキュリティとコスト制御を組み込みで持つエージェント開発パートナーで、一般提供（GA）が開始された。データ基盤面では Confluent 買収で得た Kafka / Flink ベースのリアルタイムストリーミングを **watsonx.data** に統合し、エージェントが常に最新データで推論できる環境を整える。また **IBM Concert**（インテリジェント IT 運用）と **IBM Sovereign Core**（主権・ガバナンス基盤）も合わせて発表され、AI のパイロット段階から本番スケールへの移行を一気通貫で支援する「AI オペレーティングモデル」のブループリントが示された。開発者にとっては、複数の AI プロバイダーのエージェントを統一 API で扱える抽象レイヤーが整備されることで、ベンダーロックインを避けながらエージェントを組み合わせるアーキテクチャが現実的な選択肢となりつつある。

### 2. Palo Alto Networks PAN-OS に CVSS 9.3 のバッファオーバーフロー（CVE-2026-0300）— 未認証 RCE がゼロデイで野生悪用中、パッチは 5/13 以降

Palo Alto Networks が 5 月 6 日、PAN-OS の **User-ID 認証ポータル（Captive Portal）** サービスにバッファオーバーフロー脆弱性 **CVE-2026-0300** が存在し、すでに限定的な実環境悪用（ゼロデイ）が確認されていると警告した。CVSS スコアはインターネット露出構成で **9.3**（Critical）、内部制限構成でも 8.7 と高く、未認証の攻撃者が特別に細工したパケットを送信するだけで **root 権限での任意コード実行**が可能になる。影響範囲は **PA-Series・VM-Series ファイアウォール**に限定され、Prisma Access・Cloud NGFW・Panorama は対象外。パッチのリリースは **5 月 13 日**が予定されており、それまでの間は User-ID 認証ポータルへのアクセスを信頼済みゾーンのみに制限するか、不要であれば完全無効化することが推奨される。過去の PAN-OS 系ゼロデイ（CVE-2024-3400 等）では公開直後から自動化された大規模スキャンが始まった経緯があり、今回も迅速な緩和策の適用が求められる。

### Mojo 1.0 へのカウントダウン — Modular Platform 26.2 で FLUX.2 画像生成 4x 高速化、コンパイラ OSS 公開も確定

Modular が **Modular Platform 26.2** をリリースし、AI 向けシステムプログラミング言語 **Mojo** の 1.0 到達に向けた整備が着実に進んでいることを示した。主な更新点として、FLUX.2 画像生成モデルで従来比 **4 倍以上**の速度向上、NVIDIA B300・Jetson Thor・DGX Spark および AMD RDNA コンシューマ GPU への対応拡張、さらに Mojo コンパイラの **OSS（オープンソース）公開**が正式に約束された。言語機能面では、線形型（linear types）のファーストクラスサポート、関数が raise する例外型をコンパイル時に特定できる型付きエラー、リフレクションを用いた `Hashable` / `Writable` / `Equatable` トレイトの自動導出など、Rust ライクな安全性を Python の文法で実現しようとする方向性が鮮明になった。Mojo の特徴は Python との文法的互換性を維持しつつ MLIR コンパイル基盤を通じて GPU まで一貫してコンパイルできる点で、AI 推論・学習のパフォーマンスクリティカルな層を Python から置き換える現実的な候補として注目度が増している。

```python
# Mojo: 型付きエラーの例（Python には存在しない静的型付きエラー処理）
fn parse_int(s: String) raises[ValueError] -> Int:
    """文字列を整数に変換。変換不能なら ValueError を raise する。"""
    if s.empty():
        raise ValueError("空文字列は変換できません")
    return Int(s)

fn safe_parse(s: String) -> Int:
    try:
        return parse_int(s)
    except e: ValueError:
        # コンパイラが ValueError のみをここでキャッチすることを保証
        print("変換失敗:", e)
        return 0

fn main():
    print(safe_parse("42"))   # → 42
    print(safe_parse("abc"))  # → 変換失敗: ... → 0
```

## セキュリティ

### CVE-2026-0300（PAN-OS）— ゼロデイ対応チェックリスト

パッチが 5 月 13 日まで提供されない状況での最低限の緩和策をまとめる。

**即時確認・対処事項:**
- PAN-OS の **User-ID 認証ポータル（Captive Portal）** がインターネット側に公開されているか確認
- 公開されている場合は直ちに**信頼済みゾーン（内部 IP）のみに制限**するか、使用していなければ**完全無効化**
- PA-Series / VM-Series のバージョンを特定し、Palo Alto Networks の公式セキュリティアドバイザリを購読して 5/13 のパッチリリースを待機
- ネットワーク境界の IDS / IPS ログを強化し、Captive Portal への不審なリクエストを監視

**5 月 13 日以降:**
- 提供されたパッチを最優先で適用（過去の PAN-OS 系脆弱性では公開後 24 時間以内に自動化スキャンが始まった実績あり）
- Prisma Access・Cloud NGFW・Panorama は今回の CVE の対象外だが、関連する認証フローの設定を再確認することを推奨

### cPanel CVE-2026-41940 — 4 万 4000 件の IP が侵害・悪用開始

cPanel / WHM の認証バイパス脆弱性 **CVE-2026-41940** が 4 月 30 日時点で少なくとも **44,000 件の IP アドレス**を侵害し、スキャン・ブルートフォース攻撃の踏み台として悪用されていることが判明した。この脆弱性は遠隔の攻撃者がコントロールパネルへの認証を回避して昇格した権限を得られるもので、共有ホスティング環境では他テナントのデータへの影響も懸念される。cPanel / WHM を利用している場合は速やかに最新版へのアップグレードと、管理画面へのアクセス元 IP 制限を実施することが強く推奨される。
