## 注目技術と実践ベストプラクティス

### AI訓練の利用方針をパス単位でコード化し、CIで検証する

#### 目的

IETFのInternet-Draftは、`robots.txt` の既存文法に `__usage_ai-training` というポリシートークンを加え、サイト全体またはパス単位で生成AI訓練への意思を表す方法を提案しています。複数のAI事業者が対応を表明したため、公開コンテンツと訓練対象外コンテンツを同じサイトで運用する組織にとって、設定の一貫性を保ちやすい点に実務上の価値があります。今回は、公開用プレスキットだけ訓練利用を許可し、それ以外は拒否する方針を設定ファイルと自動テストで照合します。

#### 対象・前提

対象は、自社で `robots.txt` を配信でき、コンテンツ利用方針を法務・広報・開発で合意できるWebサイトです。例はPython 3.11以降の標準ライブラリだけで動作し、IETF提案のパス最長一致を検査します。IETF文書は2026年10月時点でInternet-Draftであり最終標準ではなく、OpenAI、Google、Microsoftの対応時期も異なるため、既存の事業者別トークンを直ちに削除しないことが前提です。

#### 手順

一般化した構成例として、クロール自体は許可しつつ、生成AI訓練は原則拒否し、`/press-kit/` だけ許可します。訓練利用のポリシートークンと通常のクローラールールは別グループに置きます。

```text
User-agent: *
Allow: /

User-agent: __usage_ai-training
Disallow: /
Allow: /press-kit/
```

次のPython 3.11コードは、対象グループだけを読み取り、パス最長一致で期待する方針になっているかを検証する最小実装例です。CIでは実際に配信する `robots.txt` を入力に置き換え、公開前に実行します。

```python
from urllib.parse import urlsplit

TOKEN = "__usage_ai-training"

def read_policy(text: str):
    groups, agents, rules = [], [], []

    def flush():
        nonlocal agents, rules
        if agents:
            groups.append((agents, rules))
        agents, rules = [], []

    for raw in text.splitlines():
        line = raw.split("#", 1)[0].strip()
        if not line or ":" not in line:
            continue
        key, value = (part.strip() for part in line.split(":", 1))
        key = key.casefold()
        if key == "user-agent":
            if rules:
                flush()
            agents.append(value.casefold())
        elif key in {"allow", "disallow"} and agents:
            rules.append((key == "allow", value))
    flush()

    selected = [rule for names, rs in groups if TOKEN in names for rule in rs]
    return any(TOKEN in names for names, _ in groups), selected

def training_allowed(text: str, url: str):
    present, rules = read_policy(text)
    if not present:
        return None  # 共通トークンによる意思表示なし
    path = urlsplit(url).path or "/"
    matched = [(len(prefix), allow) for allow, prefix in rules
               if prefix and path.startswith(prefix)]
    return max(matched, default=(0, True), key=lambda item: (item[0], item[1]))[1]

robots = """User-agent: *
Allow: /

User-agent: __usage_ai-training
Disallow: /
Allow: /press-kit/
"""

expected = {
    "https://example.com/": False,
    "https://example.com/articles/report.html": False,
    "https://example.com/press-kit/logo.svg": True,
}
for url, want in expected.items():
    actual = training_allowed(robots, url)
    assert actual is want, (url, actual, want)
    print(url, "allow" if actual else "disallow")
```

公式資料に基づく推奨は、共通トークンを事業者別設定と併用し、訓練とグラウンディングを別の意思決定として扱うことです。一般化した構成例のように例外パスを最小化してテストへ固定すると、公開範囲の変更で意図せず訓練許可が広がる事故を検知できます。一方、例外を細かく増やすほど保守コストが上がるため、コンテンツ分類が安定しているサイトで特に有効です。

#### 確認方法

上記コードはPython 3.11で実行し、ルートと記事が `disallow`、プレスキットが `allow` と表示され、すべてのアサーションを通過することを確認済みです。実サイトでは、CIの結果に加えて配信URLの `robots.txt` を取得し、CDNキャッシュ後も同じ内容か、想定外の `Allow` がないかを確認します。各AI事業者が方針を受理したか、訓練データから除外したかはこのテストでは確認できず、本稿でも事業者側の動作検証は未実行です。

#### 注意点

このポリシートークンは訓練利用の意思表示であり、クロールを止める指令ではありません。取得そのものを制限する場合は対象クローラーの製品トークンを別途設定し、認証やアクセス制御が必要な情報は `robots.txt` に頼らず非公開にします。また、訓練を拒否しても検索掲載やグラウンディングが自動的に拒否されるわけではなく、Microsoftは両者を独立設定とし、Googleも `Google-Extended` の明示設定を並行して扱います。Internet-Draftの変更、各社の実装時期、再クロールの遅延、個別契約による優先条件を継続監視する必要があります。
