## 注目技術と実践ベストプラクティス

### 画像文書を構造化JSONへ変換するVLMを、業務テストセットで選定する

#### 目的

視覚言語モデル（VLM）は、領収書や請求書の画像を直接読み、項目をJSONへ変換する文書処理に利用できます。OCR、座標処理、項目推定を別々に組む構成を簡素化できる可能性がありますが、公開ベンチマークの順位だけでは、自社の帳票、言語、画質、欠損項目に対する適合性は分かりません。そこで、モデルの新しさではなく、業務上の失敗コストに沿った非公開テストで採否を決める方法を扱います。

#### 対象・前提

対象は、帳票画像から定型項目を抽出し、人が承認して会計・購買システムへ登録する業務です。実装例では、2026年10月15日公開の `nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-BF16` とPythonのTransformersパイプラインを想定します。公式モデルカードはBF16版の基準構成に4基のH100または2基のGB200を挙げており、より小さい量子化版や外部推論サービスを使う場合は別の候補として評価します。機密文書を扱うため、入力画像、推論ログ、生成結果の保存先とアクセス権を先に決め、モデルライセンスと依存コードも確認します。

#### 手順

まず、業務データを取引先、帳票様式、言語、画質、期間で分け、開発用と最終評価用を分離します。NISTのAITEが非公開データを隔離環境で評価して学習・テスト汚染を抑える考え方を採用しているため、最終評価用の正解データは調整担当者からも隠します。

次は一般化した構成例です。入力を領収書画像、出力を `merchant`、`transaction_date`、`total`、`currency`、`tax`、`needs_review` のJSONに固定し、欠落値を推測させず `null` にします。仮想例の入力が「ACME STORE、2026/10/15、合計 12,300円、税 1,118円」と読める画像なら、期待出力は次のとおりです。

```json
{
  "merchant": "ACME STORE",
  "transaction_date": "2026-10-15",
  "total": 12300,
  "currency": "JPY",
  "tax": 1118,
  "needs_review": false
}
```

最小の実装例では、公式モデルカードにある `image-text-to-text` パイプラインを使い、JSON以外を返さないこと、読めない値は `null` にすること、金額と日付を正規化することをプロンプトへ明記します。次のコードは構成を示すもので、画像URL、認証、GPU割り当て、出力形式は環境に合わせて変更します。

```python
from transformers import pipeline
import json

MODEL = "nvidia/NVIDIA-Nemotron-3.5-Super-VL-120B-A12B-BF16"
pipe = pipeline("image-text-to-text", model=MODEL,
                trust_remote_code=True, device_map="auto")
messages = [{"role": "user", "content": [
    {"type": "image", "url": "https://internal.example/receipts/123.png"},
    {"type": "text", "text": """領収書を読み、merchant, transaction_date,
total, currency, tax, needs_reviewだけを持つJSONを返してください。
日付はYYYY-MM-DD、金額は整数、読めない値は推測せずnull、
JSON以外は出力しないでください。"""}
]}]
result = pipe(text=messages, max_new_tokens=256)
payload = result[0]["generated_text"][-1]["content"]
record = json.loads(payload)
```

生成後はJSON Schemaで型と必須キーを検証し、金額の合計整合、日付範囲、通貨コードを決定的なルールで再確認します。検証に失敗した文書と高額取引は自動再試行で確定させず、人の確認待ちへ送ります。

#### 確認方法

期待結果は、最終評価セットで有効なJSONが返り、正解とのフィールド単位完全一致、金額・日付の正規化後一致、欠落項目を `null` にできた割合が事前基準を満たすことです。加えて、無効JSON率、人手確認率、1文書当たりの待ち時間、GPUメモリ、処理コストを記録し、既存のOCR＋ルール方式および小型VLMと同じデータで比較します。量子化、プロンプト、推論エンジンを変えた場合は別構成として再評価し、代表的な誤り画像を残して回帰テストに加えます。本記事のコードとモデル推論は未実行であり、NVIDIAやNISTの公開資料を自社環境で再検証した結果ではありません。

#### 注意点

帳票内の文字列は信頼できない入力であり、プロンプト命令のような文言やQRコードをモデルの操作指示として扱わせない分離が必要です。VLMは、低解像度、手書き、縦書き、複数通貨、合計と小計の混同で誤るため、JSONが構文上正しくても自動承認の根拠にはできません。フル精度モデルは大きなGPU構成を要し、量子化版はコストを下げられる一方で帳票精度が変わる可能性があります。個人情報や決済情報を含む画像は最小限の保存期間とし、ログのマスキング、暗号化、権限分離を行います。
