## 注目技術と実践ベストプラクティス

### モデルAPIの大量抽出を多層シグナルで検知し、段階的に制限する

#### 目的

モデル蒸留自体は正当な圧縮手法にも使われますが、提供者の許可なく大量の応答や保護された推論を集める抽出攻撃は、APIの知的財産、利用規約、安全対策を回避する経路になります。Anthropicが公表した対策は、推論を持ち出しにくくする設計、リクエスト単位の分類、反復するアカウントの制限を重ねる防御です。ここではその考え方を一般化し、単発の誤検知で即時停止せず、組織単位の反復パターンを加味して`allow`、`review`、`block`へ振り分ける最小のポリシー層を作ります。

#### 対象・前提

対象は、独自モデルや高価な推論モデルを外部へ提供し、APIゲートウェイで組織ID、アカウントID、時刻、匿名化した接続元、抽出検知器のスコアを取得できるサービスです。以下はPython 3.12の標準ライブラリだけを使う仮想例で、上流の分類器が0から1の`extraction_score`を返す前提です。しきい値と10分の窓は説明用の値であり、Anthropicの非公開実装や公式推奨値を再現するものではありません。本番では、利用規約、正当な一括処理、研究用途、法人契約、地域のプライバシー規制に合わせて、保存項目と判定基準を定めます。

#### 手順

まずリクエスト単位の高信頼スコアを即時遮断し、中程度のスコアや、同一組織で複数アカウント・接続元に分散した反復を人の確認へ送ります。次の一般化した構成例は、分類器そのものではなく、その出力と時間窓の集約を扱う実装例です。

```python
from collections import defaultdict, deque
from dataclasses import dataclass


@dataclass(frozen=True)
class Event:
    ts: float
    org_id: str
    account_id: str
    ip_hash: str
    extraction_score: float


class ExtractionGate:
    def __init__(self, window_seconds: int = 600):
        self.window_seconds = window_seconds
        self.events = defaultdict(deque)

    def decide(self, event: Event) -> str:
        history = self.events[event.org_id]
        cutoff = event.ts - self.window_seconds
        while history and history[0].ts < cutoff:
            history.popleft()
        history.append(event)

        if event.extraction_score >= 0.90:
            return "block"

        suspicious = [e for e in history if e.extraction_score >= 0.35]
        accounts = {e.account_id for e in suspicious}
        sources = {e.ip_hash for e in suspicious}
        if (
            event.extraction_score >= 0.60
            or len(suspicious) >= 3
            or len(accounts) >= 3
            or len(sources) >= 3
        ):
            return "review"
        return "allow"


gate = ExtractionGate()
assert gate.decide(Event(0, "org-a", "acct-1", "src-a", 0.10)) == "allow"
assert gate.decide(Event(10, "org-b", "acct-1", "src-a", 0.40)) == "allow"
assert gate.decide(Event(20, "org-b", "acct-2", "src-b", 0.40)) == "allow"
assert gate.decide(Event(30, "org-b", "acct-3", "src-c", 0.40)) == "review"
assert gate.decide(Event(40, "org-c", "acct-9", "src-z", 0.95)) == "block"
```

接続元は生のIPアドレスではなく、短期間でローテーションするソルトを使ったハッシュなど、相関に必要な最小情報へ変換します。導入時は判定だけを記録するシャドーモードから始め、正常なバッチ処理と既知の抽出テストをラベル付きデータにして誤検知と見逃しを測ります。十分な証拠がないイベントは`review`または一時的な速度制限にとどめ、高信頼の単発検知や確認済みの反復だけを遮断することで、正当な大量利用を止める損失との均衡を取ります。

#### 確認方法

掲載コードはPython 3.12で実行し、通常利用が`allow`、3アカウント・3接続元へ分散した低〜中スコアの反復が`review`、高スコアの単発要求が`block`になることをassertで確認します。本番前には、時間帯、契約プラン、バッチサイズ、言語、地域を含む正常トラフィックを層別化し、偽陽性率、再審査で解除された割合、遮断までの時間、抽出可能だった出力量を測ります。しきい値を変えるたびに同じ固定評価セットで比較し、攻撃テスト用データは学習用データと分けます。実API、実利用者データ、上流分類器、分散ストレージ、速度制限との結合試験は未実行です。

#### 注意点

キーワードや単一IPだけの規則は、言い換えや代理ネットワークで回避されやすく、研究者、評価会社、大規模顧客を誤って止める危険があります。組織をまたぐ照合は防御力を上げますが、ログの共有範囲、保存期間、目的外利用を最小化し、アクセス制御と削除手続きを設ける必要があります。Anthropic自身も、分類器が正当な要求を誤って遮断する場合、連携変更が必要になる場合、遮断済み要求にも料金が発生する場合をトレードオフとして挙げています。また、攻撃者が複数のクラウドや推論事業者へ分散すると単一ゲートウェイでは全体像を得られないため、契約上許される範囲で不正アカウントの確認手順と事業者間の通報経路を整えます。
