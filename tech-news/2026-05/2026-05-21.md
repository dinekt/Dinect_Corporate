### 2. Anthropic API 新機能（5 月）

**Cache Diagnostics パブリックベータ（5/13 リリース）:**

プロンプトキャッシュのミス原因を API レベルで診断できる新機能。`diagnostics.previous_message_id` を渡すと `cache_miss_reason` が返り、前回ターンからどこでキャッシュプレフィックスが diverge したかを特定できる。

```python
import anthropic

client = anthropic.Anthropic()

# 1ターン目
resp1 = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    system=[{"type": "text", "text": "あなたは文書処理の専門家です。", "cache_control": {"type": "ephemeral"}}],
    messages=[{"role": "user", "content": "PDFを要約してください"}],
    extra_headers={"anthropic-beta": "cache-diagnosis-2026-04-07"},
)

# 2ターン目: 前回の message_id を渡す
resp2 = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    system=[{"type": "text", "text": "あなたは文書処理の専門家です。", "cache_control": {"type": "ephemeral"}}],
    messages=[
        {"role": "user", "content": "PDFを要約してください"},
        {"role": "assistant", "content": resp1.content},
        {"role": "user", "content": "詳しく説明してください"},
    ],
    diagnostics={"previous_message_id": resp1.id},  # ← 診断キー
    extra_headers={"anthropic-beta": "cache-diagnosis-2026-04-07"},
)

# cache_miss_reason でミス箇所を特定
if hasattr(resp2, "diagnostics") and resp2.diagnostics:
    print("Cache miss reason:", resp2.diagnostics.cache_miss_reason)
    # 例: "system_prompt_changed" / "tool_definition_changed" など
```

Python SDK 0.102.0（5/13）で正式サポート。ツール定義の変更がキャッシュを破壊する最多パターンであることが判明している（ツール定義はキャッシュプレフィックスの一部）。

**Managed Agents API（4/8 GA → 5/19 に Self-hosted Sandbox・MCP Tunnel 追加）:**

Anthropic 管理のインフラでエージェントを実行するホスト型 API。自前でエージェントループを実装する必要がない。全エンドポイントに `managed-agents-2026-04-01` ベータヘッダーが必要。

```python
import anthropic

client = anthropic.Anthropic()

# エージェント定義（1 度作れば ID で再利用）
agent = client.beta.agents.create(
    model="claude-opus-4-7",
    name="doc-processor",
    system_prompt="PDF文書を処理し、構造化データを抽出する専門エージェント。",
    tools=[{"type": "bash"}, {"type": "file_read"}, {"type": "file_write"}],
    betas=["managed-agents-2026-04-01"],
)

# セッション起動（非同期・長時間実行）
session = client.beta.agents.sessions.create(
    agent_id=agent.id,
    betas=["managed-agents-2026-04-01"],
)

# イベント送信＆ SSE ストリーミング
for event in client.beta.agents.sessions.send_event_stream(
    session_id=session.id,
    event={"type": "user", "content": "invoice.pdf を処理してください"},
    betas=["managed-agents-2026-04-01"],
):
    print(event)
```

5/19 追加: **Self-hosted Sandbox**（コンプライアンス・データレジデンシー要件対応）、**MCP Tunnel** でプライベートネットワーク内の MCP サーバーに接続可能（後述）。

**MCP トンネル（Research Preview、5/19 リリース）:**

プライベートネットワーク内の MCP サーバーに、インバウンドポート開放なしで接続できる機能。Cloudflare 経由のアウトバウンド接続のみで動作。

```bash
# Docker Compose による最速セットアップ（クイックスタート）
# 事前: Claude Console でトンネルを作成して TOKEN を取得

cat > docker-compose.yml << 'EOF'
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    command: tunnel --no-autoupdate run --token ${TUNNEL_TOKEN}
    environment:
      - TUNNEL_TOKEN=${TUNNEL_TOKEN}

  proxy:
    image: ghcr.io/anthropics/mcp-tunnel-proxy:latest
    environment:
      - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
      - TUNNEL_DOMAIN=${TUNNEL_DOMAIN}
    volumes:
      - ./proxy-config.yaml:/etc/proxy/config.yaml

  my-mcp-server:
    image: my-org/my-mcp-server:latest
    # プライベートネットワーク内で動作
EOF

docker compose up -d
```

```python
# Messages API からトンネル経由 MCP を使用
response = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=1000,
    messages=[{"role": "user", "content": "社内DBを検索して"}],
    mcp_servers=[
        {
            "type": "url",
            "url": "https://mydb.YOUR_TUNNEL_DOMAIN/mcp",  # トンネル経由
            "name": "internal-db",
        }
    ],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "internal-db"}],
    betas=["mcp-client-2025-11-20"],
)
```

セキュリティ: 3 層構造（mTLS + 内部 TLS + OAuth）。Cloudflare はペイロードを読めない。

**2026 年の重要な知見（スタンフォード研究）:**
- LLM 生成のコンテキストファイルはタスク成功率を約 3% **低下** させる
- 人間が書いたコンテキストファイルは成功率を約 4% 向上させるが、推論コストを 20%+ 増加させる
- 結論: CLAUDE.md は簡潔に保ち、必要なコンテキストのみ記述する

### 5. 実践的 Tips（見落とされがちな機能）

**Claude Code の隠れた便利機能:**

```bash
# /loop: テスト→修正→テストを自動サイクル（手動確認なし）
/loop pytest tests/ --tb=short

# /ultrareview: エンタープライズ級セキュリティ＋スケーラビリティ監査
/ultrareview src/

# Extended Thinking トリガーフレーズ（どれも同等に機能）
"think step by step"
"think harder"
"ultrathink"

# `d` キー（モデルピッカー内）: デフォルトモデルを永続変更
/model → d キー → claude-sonnet-4-6 を選択

# terminalSequence フック: デスクトップ通知・ウィンドウタイトル・ベルを発火
# hooks.json で terminalSequence フィールドを設定
{
  "hooks": {
    "on_complete": {
      "terminalSequence": "\033]9;Task completed\007"  # デスクトップ通知
    }
  }
}
```

**プロンプトキャッシュの鉄則（Anthropic エンジニアリングブログより）:**

- Claude Code チームはキャッシュヒット率の 2 ポイント低下を「本番インシデント」として扱う
- キャッシュを壊す最多原因: **会話途中でのツール定義変更**（ツールはキャッシュプレフィックスに含まれる）
- static なコンテキスト（システムプロンプト・アーキテクチャ・API 仕様）を最上部に配置する
- `automatic caching` で `cache_control` の手動管理が不要に（2/19 GA）
- `thinking.display: "omitted"` で思考ブロックをストリームから除外（高速化、課金は変わらない）

**CLAUDE.md のトークンコスト意識:**

```
5,000 トークンの CLAUDE.md = 全ターン・全セッションで毎回 5,000 トークン消費
→ CLAUDE.md は必要最小限に。詳細情報は外部 DB や SKILL.md に分離するのが最適
```
