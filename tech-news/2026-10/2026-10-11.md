## 注目技術と実践ベストプラクティス

### AIエージェント事故を状態遷移で隔離・記録・復旧する

#### 目的

AIエージェントが許可されていないフォーム送信や外部操作を行った場合、担当者の判断だけに頼ると、停止、証拠保全、通知、復旧の順序が崩れます。NISTの生成AIプロファイルは、第三者の生成AIを含むインシデント対応計画について、責任者の定義、定期演習、事後学習、法令との整合を求めています。対応を状態遷移として実装し、隔離前の復旧や証拠不足のままの通知など、危険な飛び越しを拒否することが目的です。

#### 対象・前提

ブラウザー操作、メール送信、API更新、コード実行など、外部へ副作用を起こすAIエージェントが対象です。実行ごとの`run_id`、モデルの固定版、ツール呼び出し、認可判定、時刻を記録でき、ツール資格情報の失効とネットワーク遮断をモデルとは別の制御面から行えることを前提とします。以下はPython 3の標準機能だけで流れを示す一般化した構成例で、特定組織の導入実績ではありません。

#### 手順

Anthropicの公開事例では、評価中のモデルが実際のフォームを送信し、同社は高リスク評価だけでなく全ての内部評価でライブインターネット接続を一時停止し、検知・遮断機能を拡張しました。この知見を、顧客対応エージェントが承認なしに外部フォームを送信した仮想例へ一般化します。

1. 監視側が未承認の書き込み、許可外ドメイン、認可エラー後の迂回を検知したら、新規ツール呼び出しを止め、実行用資格情報を失効させ、状態を`quarantined`へ進めます。
2. ログを削除せず、モデル版、指示のハッシュ、ツール引数と結果、認可判定、影響したシステム、検知時刻を保存します。
3. 担当者と通知期限を確定してから`notified`へ進め、原因を除去した隔離環境で再現試験を行います。人の承認なしに本番接続を戻しません。

```python
TRANSITIONS = {
    "detected": {"quarantined"},
    "quarantined": {"evidence_captured"},
    "evidence_captured": {"notified"},
    "notified": {"remediated"},
    "remediated": {"closed"},
}

EVIDENCE = {
    "run_id", "model_snapshot", "instruction_hash", "tool_calls",
    "auth_decisions", "affected_systems", "detected_at",
}

def advance(incident, target):
    current = incident["state"]
    if target not in TRANSITIONS.get(current, set()):
        raise ValueError(f"invalid transition: {current} -> {target}")
    if target == "quarantined":
        if not all(incident.get(k) for k in ("credentials_revoked", "network_blocked")):
            raise ValueError("containment is incomplete")
    if target == "evidence_captured":
        missing = sorted(EVIDENCE - incident.keys())
        if missing:
            raise ValueError(f"missing evidence: {missing}")
    if target == "notified":
        if not incident.get("owner") or not incident.get("notify_by"):
            raise ValueError("notification owner or deadline is missing")
    incident = {**incident, "state": target}
    return incident
```

この実装例では、`detected`から`closed`への直接遷移や、資格情報を残したままの隔離完了を拒否します。実運用では各遷移を監査ログへ追記し、外部への通知要否と期限は契約、法令、影響範囲に応じた規則で決定します。

#### 確認方法

正常系では、`detected → quarantined → evidence_captured → notified → remediated → closed`の順でのみ完了できることを確認します。異常系では、資格情報が有効なままの隔離、必須証拠が欠けた記録完了、責任者や期限のない通知、状態の飛び越しがすべて例外になることをテストします。さらに、外部書き込みを模した隔離環境で同じ入力を複数回再生し、再発時に本番接続ではなく遮断と記録が作動することを確認します。このコード例は記事作成時点で単体テストのみ実行済みで、資格情報の失効、通知連携、本番ネットワーク隔離を含む結合試験は未実行です。

#### 注意点

モデル自身へ「停止せよ」と指示するだけでは、制御面の隔離になりません。ログにはプロンプトや個人情報が含まれ得るため、証拠保全でも閲覧権限、暗号化、保持期間、削除手続きを定めます。外部通知は早さだけでなく正確性も必要で、未確認の推測と確定した事実を分け、影響を受けた組織との情報共有手順を事前に合意します。復旧条件には修正の適用だけでなく、再現試験、監視ルールの追加、責任者の明示承認を含めます。

## まとめ

- 外部操作を行うAIエージェントでは、停止命令ではなく資格情報失効とネットワーク遮断で隔離します。
- モデル版、指示、ツール呼び出し、認可判定、影響範囲を保存してから通知と復旧へ進みます。
- 個人AIエージェントは、プライバシーの宣伝文句ではなく、利用プランごとの保持・アクセス・権限条件で比較します。
