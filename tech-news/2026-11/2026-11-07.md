## 注目技術と実践ベストプラクティス

### 金融データに基づくAI回答を「根拠行・鮮度・完全性」で照合する

#### 目的

読み取り専用の金融コネクターは、誤送金などの操作リスクを抑えながら支出分析を支援できますが、回答の正しさまで保証するものではありません。残高の遅延、同じ口座の重複接続、未接続口座、保留中取引、分類違いが重なると、自然な文章でも集計結果は誤り得ます。そこで、AIへ渡す前に取引を決定的な処理で集計し、回答と一緒に根拠行、データ時点、除外理由、対象口座を残す方法を採ります。

#### 対象・前提

予算確認、経費の傾向把握、月次レポートの下書きなど、最終判断を人が行える用途に適します。Claude Personal Financeを直接使う場合は、2026年11月7日時点で米国のPro・Max・Ultra向けベータで、Plaid接続は読み取り専用です。以下の一般化した実装例は特定製品の接続機能を再現するものではなく、Python 3.11以降の標準ライブラリだけで匿名化済みCSVを検算する構成です。口座番号、氏名、店舗の自由記述など、検算に不要な情報は入力前に削除します。

#### 手順

一般化した実装例として、11月1〜5日の食費を集計します。入力CSV `transactions.csv` は次の合成データで、`t002`の重複行と保留中の`t004`を意図的に含めています。

```csv
transaction_id,posted_at,account_id,amount,category,status
t001,2026-11-02,checking,-18.40,food,posted
t002,2026-11-03,card,-32.10,food,posted
t003,2026-11-04,card,-12.00,transport,posted
t004,2026-11-05,card,-9.90,food,pending
t002,2026-11-03,card,-32.10,food,posted
```

次のPythonは、取引IDと口座IDの組み合わせで重複を除き、確定済みの食費だけを`Decimal`で合計し、AIが引用できる証跡をJSONで出力します。実運用では、取引IDが口座内で一意かをデータ提供元の仕様で確認し、違う場合は一意キーを変更します。

```python
import csv
import json
from datetime import date
from decimal import Decimal

start = date.fromisoformat("2026-11-01")
end = date.fromisoformat("2026-11-05")
seen = set()
included = []
excluded = {"duplicate": 0, "pending": 0, "other": 0}

with open("transactions.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        key = (row["account_id"], row["transaction_id"])
        if key in seen:
            excluded["duplicate"] += 1
            continue
        seen.add(key)
        posted_at = date.fromisoformat(row["posted_at"])
        if row["status"] != "posted":
            excluded["pending"] += 1
        elif not (start <= posted_at <= end) or row["category"] != "food":
            excluded["other"] += 1
        else:
            included.append(row)

total = sum((abs(Decimal(r["amount"])) for r in included), Decimal("0"))
evidence = {
    "period": [start.isoformat(), end.isoformat()],
    "total": format(total, ".2f"),
    "currency": "USD",
    "source_ids": [r["transaction_id"] for r in included],
    "accounts": sorted({r["account_id"] for r in included}),
    "latest_posted_at": max(r["posted_at"] for r in included),
    "excluded": excluded,
}
print(json.dumps(evidence, ensure_ascii=False, indent=2))
```

この例の出力では合計が`50.50`、根拠が`t001`と`t002`、根拠行の最新確定日が`2026-11-03`、除外は重複1件・保留1件・その他1件になります。AIにはこのJSONだけを渡し、「数値には`source_ids`と`latest_posted_at`を添え、対象口座が完全か不明なら断定しない。投資判断や資金移動を提案しない」と指示します。これにより、文章生成と計算を分離し、計算の再現性と回答の読みやすさを両立できます。

#### 確認方法

上の合成CSVとコードはPython 3.11で実行確認済みで、`50.50`と各除外件数が期待どおりになることを確認しました。実データ、Plaid接続、Claude Personal Financeとの統合は未実行です。実運用では、対象期間の元明細と`source_ids`を突き合わせ、全口座が接続済みか、重複ログインがないか、保留中取引を除外してよいかを人が確認します。回帰テストには、重複、未接続口座を示すメタデータ、日付境界、返金、通貨混在、保留から確定への遷移を含め、数値だけでなく根拠IDと除外理由も比較します。

#### 注意点

読み取り専用でも、取引履歴は機微情報であり、共有リンク、成果物、会話履歴から漏れる可能性があります。Claudeの公式ヘルプでは、接続解除後も過去の会話や成果物、共有リンクは自動削除されないため、不要な履歴と共有物は別途削除する必要があります。また、残高が1〜2日遅れる、同一口座の複数ログインで二重計上される、アクセスできない金融機関が予算から抜けるといった制約があるため、「利用可能残高」や「余剰資金」を単一回答で確定しません。投資・融資・税務など高影響の判断では、AI出力を助言とみなさず、元明細と資格を持つ専門家の確認を優先します。

## まとめ

- 金融データをAIへ渡す前に、重複除去と確定取引の集計を決定的な処理で行い、根拠ID・データ時点・除外理由を回答に添えます。
- 読み取り専用接続でも共有物と履歴の漏えい対策は必要であり、元明細との照合を行える業務に限定して試します。
- 動画や音声AIの新機能は、短い下書きと部分修正、割り込み後の指示追跡といった検証可能な単位から導入します。
