### 2. EU AI Act高リスク規定が8月2日から施行 — チャットボットのAI明示・ディープフェイクラベルが世界標準に波及

欧州委員会のAIオフィスは2026年8月2日をもってEU AI Actの透明性義務（Article 50）と一般目的AI（GPAI）モデルの規制を正式に発効・施行した。これによりEUでサービスを提供するすべての事業者は、チャットボットや音声エージェントがユーザーと対話する際に「自分はAIである」と最初に開示しなければならない。ディープフェイクや機械生成コンテンツにはEUが定める標準規格に準拠した機械可読な電子透かし（ウォーターマーク）の付与が義務付けられ、これを検出するAPIの整備も事業者側に求められる。罰則は違反の種類によって最大**€1,500万または全世界年間売上の3%**（いずれか高い方）で、GDPR同水準の実効性を持つ。高リスクAI（雇用・与信・医療・法執行分野など）については、EU議会が2026年7月27日に発効した「Digital Omnibus（規制2026/1744号）」により適合性評価の期限が**2027年12月2日まで延長**されたものの、チャットボットの透明性義務は猶予なく即時適用である。日本・韓国・ブラジルなどAI規制の立法を進める国がEU標準を参照しており、ウォーターマーク実装の技術要件が実質的なグローバルデファクト化する可能性が高い。

### 3. DeadLockランサムウェア、Polygonブロックチェーンで分散型C2を構築 — インフラ摘発を無効化する新設計

Microsoftセキュリティチームは2026年8月10日、**DeadLock**と名付けられたランサムウェアグループの技術分析を公開した。最大の特徴は、被害者との通信に**Polygonブロックチェーンのスマートコントラクト**を活用してC2（コマンド&コントロール）アドレスを動的に取得する設計にある。従来のランサムウェアはC2サーバーがDNS/IPで特定されると法執行機関によるテイクダウンで機能停止するが、DeadLockは被害者端末上のクライアントがPolygonのコントラクトを参照して現在の通信先を取得するため、攻撃者がスマートコントラクトのパラメータを更新するだけでインフラを即座に切り替えられる。被害者との匿名通信には分散型メッセージングネットワーク**Session**を使用し、データリーク・脅迫サイトのホスティングも分散型ストレージに移行していることが確認された。ランサムウェア本体はRustで実装されており、Windows Defenderの無効化・バックアップの削除・イベントログのクリアを暗号化前に実行する。2026年7月時点でDeadLockのリークサイトには**80以上の組織**（主に欧州のIT・製造・輸送・ホスピタリティ業）が掲載されており、ReliaQuestの四半期レポートはこのブロックチェーンC2手法が2026年内に他グループへ広がると中程度の確信で予測している。

### EU AI Act Article 50 対応：チャットボットのコンプライアンス実装パターン

EU AI Act Article 50が施行されたことで、EUユーザー向けにチャットボットを提供する開発者はシステムの起動時にAI開示を行う実装が義務付けられた。以下は対応パターンの概念例だ。

```python
# EU AI Act Article 50 — チャットボット透明性対応の実装概念例
from dataclasses import dataclass
from enum import Enum

class UserRegion(Enum):
    EU = "eu"
    OTHER = "other"

@dataclass
class ChatSession:
    user_region: UserRegion
    disclosed: bool = False

def get_opening_message(session: ChatSession) -> str:
    """
    EU AI Act Article 50: EUユーザーへのAI開示（セッション開始時に必須）
    非EUでも透明性のベストプラクティスとして推奨される
    """
    disclosure = (
        "[AI通知] このチャットはAIによって自動応答されています。"
        "人間のオペレーターではありません。 "
        "| [AI Notice] You are interacting with an automated AI system, not a human.\n\n"
    )
    session.disclosed = True
    if session.user_region == UserRegion.EU:
        return disclosure + "ご質問をどうぞ。"
    # EU外でもオプション開示（GDPR的ベストプラクティス）
    return "ご質問をどうぞ。"


# ディープフェイク・AI生成コンテンツへのウォーターマーク付与（概念）
import struct

WATERMARK_MAGIC = b"C2PA"  # Coalition for Content Provenance and Authenticity

def embed_ai_content_watermark(image_bytes: bytes, model_id: str) -> bytes:
    """
    EU AI Act / C2PA準拠: AI生成画像に機械可読なメタデータを付与
    実際の実装はC2PAライブラリ (python-c2pa) を使用する
    """
    manifest_json = (
        f'{{"dc:format":"image/jpeg","ai_generated":true,"model":"{model_id}"}}'
    ).encode()
    # C2PAマニフェスト相当のバイト列を先頭に挿入（実装概念）
    header = WATERMARK_MAGIC + struct.pack(">I", len(manifest_json)) + manifest_json
    return header + image_bytes


# 高リスクAIシステムのリスク管理ログ（Article 9対応、2027/12まで猶予あり）
def log_ai_decision(decision: dict, user_id: str, model_version: str) -> None:
    """
    高リスクAI（雇用・与信・法執行等）はArticle 9のリスク管理記録が必須
    適合性評価期限: 2027-12-02（Digital Omnibus延長後）
    """
    audit_entry = {
        "timestamp": "...",  # UTC ISO8601
        "user_id_hash": hash(user_id),  # 個人情報を直接保存しない
        "model_version": model_version,
        "decision_outcome": decision.get("result"),
        "confidence": decision.get("confidence"),
        "human_review_required": decision.get("confidence", 1.0) < 0.80,
    }
    # audit_log.append(audit_entry)  # 監査ログストアへ保存
```

EU圏外の事業者であっても、EUユーザーにサービスを提供する場合は域外適用が生じる点に注意が必要だ。C2PA（Coalition for Content Provenance and Authenticity）準拠のウォーターマーク実装は、Adobe・Microsoftも支持する業界標準であり、EUの技術規格との親和性が高い。Article 50への対応は「ユーザーに不便を与えない範囲でAI開示をUIに組み込む設計」が認められており、モーダルでの事前同意よりも会話ヘッダや常時表示のバッジ等が実装例として挙げられる。

### DeadLockランサムウェア詳細：ブロックチェーンC2が従来の封じ込め戦術を無効化する理由

DeadLockが採用するPolygon + Sessionのハイブリッドアーキテクチャは、従来の法執行機関による「インフラテイクダウン」戦術に対して構造的な耐性を持つ。

```text
=== DeadLockランサムウェア 攻撃フロー（2026年8月 Microsoft分析より）===

[フェーズ1: 侵入・偵察]
  初期アクセス  : VPN脆弱性 / RDP総当たり / フィッシング
  横展開       : Living-off-the-land (LOLbins) で検出回避
  情報窃取     : 機密文書・認証情報を外部ストレージへ転送（二重恐喝準備）

[フェーズ2: 暗号化前の防御無効化]
  1. Windows Defender / AV をサービス停止 or 設定改ざんで無効化
  2. Volume Shadow Copies (VSS) を削除 → ローカルバックアップ復元を阻止
  3. Windows Event Log サービスを停止 → フォレンジック証跡を消去

[フェーズ3: 暗号化]
  エンクリプター: Rust製バイナリ（高速・クロスプラットフォーム対応）
  暗号方式     : ChaCha20 (対称) + X25519 (鍵交換) の組み合わせ
  対象        : ネットワーク共有・ローカルドライブを優先順位付きで暗号化

[フェーズ4: 分散型C2 — 従来のテイクダウン戦術が効かない理由]

  従来型ランサムウェア:
    被害者 → HTTPリクエスト → C2サーバー(固定IP/ドメイン)
              ↑ ここをシンクホール / DNSブロック / サーバー押収で無効化

  DeadLock (ブロックチェーンC2):
    被害者クライアント
      → Polygon RPC (公開ノード, ブロック不可)
        → スマートコントラクト参照 → 現在のプロキシアドレス取得
          → Sessionネットワーク (P2P暗号化通信) → 攻撃者
    攻撃者がコントラクトのパラメータを更新するだけでインフラ切り替え完了

[防御側の対応指針]
  検出ルール例 (Sigma形式コンセプト):
    - Windowsイベント: ServiceStop (EventID 7036) で "WinDefend" の停止
    - vssadmin.exe / wmic shadowcopy delete コマンドの実行
    - 外部への大量データ転送 (>100MB/hour to non-business IPs)
    - Polygon RPC エンドポイント (rpc.ankr.com/polygon 等) への不審な接続

  ネットワーク緩和:
    - ランサムウェア実行前の大量外部転送を止めるDLP/EGRESルールが最重要
    - ブロックチェーン系RPCエンドポイントへのアウトバウンドを業務上不要なら制限
    - EDRによる「暗号ランサム的ファイル変更パターン」の振る舞い検知を有効化
```

DeadLockがRustで実装されている点も注目に値する。Rustのメモリ安全性はセキュリティソフトウェアだけでなく攻撃的なマルウェアの開発にも活用されており、クラッシュしにくい安定した暗号化エンジンの実現に貢献している。法執行機関がブロックチェーンC2を持つグループのインフラを封じ込めるには、スマートコントラクトのデプロイアカウントの特定と資産凍結など、従来のTTPs（戦術・技術・手順）と異なるアプローチが必要になる。
