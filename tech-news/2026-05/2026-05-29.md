### 3. Subquadratic が SubQ を公開 — Transformer 非依存・12M トークン・SSA アーキテクチャで「コンテキスト単価 1/300」を主張

Miami 発スタートアップ **Subquadratic** が 2026-05-05 にリリースした **SubQ** は、商用 LLM として初となる **Transformer 以外のアーキテクチャ**（Subquadratic Sparse Attention / SSA）を採用し、**12M トークン**のコンテキストウィンドウを提供する。従来の Transformer 系モデルでは Attention の計算コストが O(n²) であるため長大なコンテキストの処理コストは二乗で膨らむが、SSA はこれをサブ二乗に抑えることで、1M トークン時に FlashAttention 比 **52 倍の効率**を謳う。コーディング性能は「Claude Opus 相当で約 1/20 のコスト」とされており、RULER ベンチマークでは 128K コンテキストで 95% の精度を記録した。$29M のシード調達（バリュエーション約 $500M）も注目を集めているが、査読論文や OSS 公開は未着手であり、独立した再現検証が困難な状態が続いている点には業界から懸念の声も上がっている。

## 新技術・新リリース

### SubQ — Transformer 非依存 LLM の仕組みと長大コンテキストの実用イメージ

SubQ は SSA（Subquadratic Sparse Attention）により、通常の Transformer が直面するコンテキスト拡大に伴う計算コスト爆発を回避する。以下は長大なコンテキストを活用するシナリオのイメージコードだ（SubQ API は preview 段階であり、インターフェースは変動する可能性がある）。

```python
# SubQ API — 超長大コンテキストでのドキュメント解析イメージ
import subquadratic  # pip install subquadratic-sdk（preview）

client = subquadratic.Client(api_key="YOUR_API_KEY")

# 12M トークン対応モデルに巨大なコードベース全体を渡す例
with open("entire_codebase.txt") as f:
    codebase = f.read()  # 数百万トークン規模も可

response = client.messages.create(
    model="subq-1m-preview",  # 研究用 12M variant も存在
    max_tokens=4096,
    messages=[{
        "role": "user",
        "content": f"以下のコードベース全体を解析し、セキュリティ上の問題点を列挙せよ。\n\n{codebase}"
    }]
)
print(response.content)
```

```python
# 比較: Transformer 系モデルのコンテキスト長とコストの関係（概念）
# n トークン → コスト ∝ n²（通常 Transformer）
# n トークン → コスト ∝ n^α（α<2, SSA）
# 1M token 処理:  Transformer ≈ 10^12 ops / SSA ≈ 10^10 ops（52倍差）

def estimate_cost_ratio(n_tokens: int, transformer_cost_per_million: float) -> dict:
    """コンテキスト長に応じたコスト比の概算（SubQ 公称値より）"""
    transformer_cost = transformer_cost_per_million * (n_tokens / 1_000_000) ** 2
    ssa_cost = transformer_cost_per_million * (n_tokens / 1_000_000) ** 1.3  # 概算
    return {
        "n_tokens": n_tokens,
        "transformer_relative": transformer_cost,
        "ssa_relative": ssa_cost,
        "speedup": transformer_cost / ssa_cost,
    }

print(estimate_cost_ratio(1_000_000, 1.0))
# → {'speedup': ~52.0} （SubQ の主張値に近似）
```

独立した再現実験はまだ行われておらず、公称値の妥当性はコミュニティで議論中だ。査読論文の公開が検証の鍵となる。

## セキュリティ

### サプライチェーン攻撃 3 件の緊急対応手順

```bash
# --- DAEMON Tools Lite (CVE-2026-8398) ---
# 感染バージョン: 11.2.0 以前（2026-04-08〜05-05 に公式サイトから配布）
# 修正バージョン: 11.2.1 以降または 12.6 以降

# バージョン確認（Windows PowerShell）
Get-WmiObject Win32_Product | Where-Object { $_.Name -like "*DAEMON*" } | Select-Object Name, Version

# 対応: アンインストールまたは 11.2.1+ へアップグレード
# winget upgrade DISC-Soft.DaemonToolsLite

# --- TanStack npm (CVE-2026-45321) ---
# 汚染バージョン: 2026-05-11 19:20〜19:26 UTC に公開された 84 バージョン
# @tanstack/* 全パッケージの lockfile を確認

# npm audit で汚染バージョンの検出
npm audit --audit-level=critical

# lockfile で汚染された特定バージョンを探す（例: @tanstack/react-query）
grep -A2 "@tanstack/react-query" package-lock.json | grep '"version"'

# 安全な最新バージョンへ更新
npm update @tanstack/react-query @tanstack/query-core @tanstack/router

# --- Nx Console VS Code 拡張 (CVE-2026-48027) ---
# 汚染バージョン: 18.95.0（2026-05-19 に 36 分間公開）
# 認証情報窃取: 1Password・npm token・GitHub token・AWS credentials

# 現在インストールバージョンの確認
code --list-extensions --show-versions | grep nrwl.angular-console

# 18.95.0 がインストールされていた場合は認証情報をローテーション
# GitHub token
gh auth refresh

# AWS credentials（影響範囲を確認後）
aws iam delete-access-key --access-key-id OLD_KEY_ID
aws iam create-access-key --user-name YOUR_USER
```

いずれも CI/CD パイプラインを通じた下流への波及が確認されており、影響期間中にビルドを実行した場合はアーティファクトの完全性検証が推奨される。TeamPCP は Aqua Trivy・Bitwarden CLI に続く3件目の攻撃であり、CI/CD 環境の信頼チェーン全体を見直すタイミングだ。
