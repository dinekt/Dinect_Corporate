### 1. SpaceXAI（旧xAI）、Grok 4.6 をリリース — 1.5兆パラメータ・500Kコンテキスト、GPT-5.6 Sol と同スコアでフロンティアモデルに躍進

Elon Musk傘下のxAIは先月SpaceXに買収されて**SpaceXAI**と改称し、2026年8月12日に新フラッグシップモデル**Grok 4.6**を公開した。最大の特徴はパラメータ数**1.5兆**と**コンテキスト長500K**で、長時間稼働するAIエージェントタスク・コーディング・マルチステップ知識作業に最適化されている。ベンチマークでは**Artificial Analysis Intelligence Index**で61点を記録し、OpenAIのGPT-5.6 Sol Maxと並ぶスコアを達成。Anthropic Fable 5の一部タスクを上回るとSpaceXAIは主張している。技術的にはSFT（教師あり微調整）とRL（強化学習）を大幅に強化したAI生成データセットで追加学習しており、ビジュアル・インタラクティブプロジェクトの初手生成品質と、長時間実行時の自己テスト・フィードバックループが改善された。モデルは**テキスト＋画像入力・テキスト出力**のマルチモーダル構成で、知識カットオフは2026年2月1日。APIは入力$2/Mトークン・出力$6/Mトークン（高速版は倍額）で、Grok Build、Cursor、Cloudflare、OpenRouter、Vercelを通じて利用可能。ローンチウィーク中はGrok Build・Cursor加入者に通常の2倍の利用枠が提供される。

### 2. Microsoft 8月 Patch Tuesday — 398件のCVEを修正、ワーム可能な Windows DNS RCE（CVE-2026-62878、CVSS 9.8）と実悪用ゼロデイが含まれる

Microsoftは2026年8月の月例セキュリティ更新（Patch Tuesday）で**398件のCVE**を修正した。うち62件がCritical、357件がImportantに分類される。最大の注目点は**CVE-2026-62878**（Windows DNS Server Remote Code Execution Vulnerability）で、CVSSスコア9.8の最高水準。スタックベースのバッファオーバーフローにより、**認証なし・ユーザー操作なし**でリモートから特権コードが実行可能であることに加え、Zero Day Initiative（ZDI）が**ワーム可能（wormable）**と評価した。つまり、一度悪用が始まると脆弱なDNSサーバー間を自己伝播するポテンシャルを持つ。影響範囲はWindows Server 2012〜2025の複数バージョンおよびDNSコンポーネントを持つWindows 10系統に及ぶ。もう1件、**Windowsドライバのゼロデイ**が既に実際の攻撃で悪用中と報告されており、即時パッチ適用が強く推奨される。また今月は**CVE-2026-62911**（Microsoft Exchange Server特権昇格、認証バイパスによるメールボックス乗っ取り）と**CVE-2026-59310**（VMware vCenter Server任意コード実行）が同時期に公開されており、三つの重大脆弱性が重なるタイミングとなっている。

### 3. MetaがオープンソースAI「Muse Glimmer」（30B）をApache 2.0で公開 — 24GB VRAMで動作するローカルAIエージェント

Meta傘下のMeta Superintelligence Labs（MSL）は2026年8月10日、**Muse Glimmer**を**Apache 2.0ライセンス**のオープンウェイトモデルとしてHugging Faceで公開した。305億パラメータの密なマルチモーダルモデルで、テキスト・画像の混在入力に対応し、100言語以上をサポート、コンテキスト長131,072トークンを持つ。最大の特徴はオフライン・ローカル実行への最適化で、4bit量子化を適用することでモデルのVRAM消費を55GBから**18〜20GBまで圧縮**し、単一の24〜32GB VRAMのコンシューマーGPU・PC・Mac上でKVキャッシュ・知覚エンコーダ・投機的デコーダを含む全コンポーネントが稼働する。コーディング・スケジュール管理・ファイル整理・関数呼び出し・LLM-as-a-judge評価などのエージェント用途を主眼として訓練されており、失敗したツール呼び出しを自律的にリトライする**自律失敗回復機能**を備える。知識カットオフは2026年1月4日。llama.cpp・MLX・ExecuTorchの最適化統合も近日リリース予定とされており、ローカルAIの普及を加速させる可能性がある。

## セキュリティ

### CVE-2026-62878：Windowsのワーム可能なDNS RCEの仕組みと即時対応指針

今月のPatch Tuesdayで最も緊急性が高い**CVE-2026-62878**（CVSS 9.8）を詳しく掘り下げる。この脆弱性はWindows DNSサービスのスタックベースバッファオーバーフローが原因で、攻撃者は**特別に細工したパケット1つ**をDNSポート（UDP/TCP 53）に送信するだけで、認証なし・ユーザー操作なしに高権限コードを実行できる。ZDIが「ワーム可能」と評価した根拠は「脆弱なDNSサーバーに到達できれば連鎖感染が技術的に可能」という構造にある。

```text
=== CVE-2026-62878 攻撃フロー概要 ===

[攻撃者]
  |
  | UDP/TCP 53 へ細工パケット（認証不要）
  v
[Windows DNS Server（パッチ未適用）]
  スタックバッファオーバーフロー発生
  → リターンアドレス改ざん
  → SYSTEM権限でシェルコード実行
  → ワーム的な横展開が可能

=== 優先パッチ対象 ===
  Windows Server 2012 R2 〜 Windows Server 2025
  ※インターネット公開・DMZ配置のDNSサーバーが最高リスク

=== 暫定緩和策（パッチ適用まで）===
  1. インターネット直接公開のDNSサーバーへのアクセスをACLで限定
  2. DNSをDMZ以外の内部セグメントに隔離
  3. ファイアウォールでポート53への不審なソース制限
  4. Windows Defenderの最新定義ファイル適用（振る舞い検知補完）

=== 同時公開・注意要件のCVE（8月 Patch Tuesday）===
  CVE-2026-62911 : Exchange Server EoP / 認証バイパスでメールボックス全乗っ取り
  CVE-2026-59310 : VMware vCenter Server RCE / ネットワークアクセスで任意コード実行
  ※ Windowsドライバゼロデイ（番号非公開）: 既に実攻撃で悪用中 → 最優先パッチ
```

セキュリティ担当者へのアクション指針：インターネット公開 DNS サーバーには今週中のパッチ適用が事実上必須。Exchange Server は CVE-2026-62911 で全ユーザーのメールボックスが危険にさらされる可能性があり、こちらも最優先で対処が求められる。VMware vCenter は昨年来の脆弱性続出を受けて「vCenter は信頼境界外に絶対に公開しない」という設計原則の再徹底を勧告する声もセキュリティコミュニティで高まっている。
