### 1. Apple、ブラジル競争規制当局との合意でサードパーティアプリストアを全世界展開へ — iOS 26.5で実装予定・iOS 26.6 Beta も同日公開

Appleはブラジルの競争規制当局 **CADE（Conselho Administrativo de Defesa Econômica）** との合意に基づき、第三者アプリストアからのアプリインストールを EU・日本に続いてグローバルに解禁する方針を明らかにした。実装は **iOS 26.5** で行われ、ユーザーは正式なサードパーティアプリストアを通じてアプリをダウンロード・インストールできるようになる。この動きはAppleが各国規制当局の圧力に対して個別対応から統一グローバルポリシーへ転換しつつあることを示しており、**「ウォールドガーデン」モデルの構造的な緩和**として業界内外で注目されている。同日、Apple は **iOS 26.6・iPadOS 26.6・macOS 26.6・tvOS 26.6・visionOS 26.6・watchOS 26.6** の Beta をデベロッパー向けに公開しており、秋の正式リリースに向けた最終サイクルに入った。また App Store のオーストラリア・ベトナム向け年齢レーティング更新（6月18日〜）も並行して展開中であり、各国の規制要件に応じた段階的なプラットフォーム適応が加速している。

### 2. Shai-Hulud サプライチェーン攻撃が新変種「Miasma」「Hades」で拡大 — npm・PyPI・GitHub Actions・VS Code拡張を横断し累計473パッケージ感染

npm と PyPI を標的とした自己伝播型ワーム **Shai-Hulud（TeamPCP作）** が、6月以降に「**Miasma: The Spreading Blight**」「**Hades – The End for the Damned**」という新変種へ進化し被害を急拡大させている。6月1日以降の感染数は **累計473パッケージアーティファクト（npm + PyPI）** に上り、過去最大のサプライチェーン侵害キャンペーンの一つとなった。Miasma は主に npm（Red Hat クラウドサービス系パッケージを含む）を標的とし、Hades は PyPI に特化しながら **バイオインフォマティクスおよびMCP（Model Context Protocol）開発者向けパッケージ**を悪意のある亜種に差し替える。さらに Hades には **AI コーディングアシスタントへのプロンプトインジェクション機能**が追加されており、GitHub Copilot や Claude Code などの AI 補助ツールを通じて感染が気づかれないまま伝播する新手法が確認されている。また **GitHub ActionsワークフローとVS Code拡張**も感染対象に加わり、CI/CDパイプライン全体が標的となっている。初期侵害は開発者・クラウドのクレデンシャル窃取から始まり、窃取した権限で正規パッケージの新バージョンを毒入りで公開するという形で自己伝播する。SLSA Build Level 3 の来歴証明を突破した初のサプライチェーン攻撃としても記録されており、プロセス整合性チェックだけでは不十分であることが証明された形だ。

### 3. Claude Fable 5、米政府との6日間交渉を経て6/18に復旧 — AI規制をめぐるAnthropicと政府の対立が「前例」として残した問題

6月9日に公開され、6月12日に米政府の国家安全保障権限に基づく指令によって全世界停止となっていた **Claude Fable 5（および Mythos 5）** が、6月18日にAnthropicによってアクセス再開された。停止のきっかけは6月10日に「Pliny the Liberator」がXで公開したジェイルブレイク手法であり、政府は外国人向けアクセスの全面停止を指令した。Anthropicは「狭く非普遍的なジェイルブレイクの可能性という口頭証拠だけで商用モデルを回収する根拠にはならない」と公式に反論しながらも、全顧客（外国人に限らず）へのアクセスを停止するという前例のない対応を取った。今回の事件が残した問題は3点ある：**① AIモデルが輸出規制対象として扱われた初のケース**、**② ジェイルブレイクの公開が政府介入のトリガーとなった連鎖**、**③ 企業が政府指令を不服としながらも従わざるを得ない AI ガバナンスの曖昧な権限構造**。フロンティアモデルの公開・停止に関して連邦政府がどこまで介入できるかの法的枠組みが存在しない中、Great American AI Act（6/4討議草案）との兼ね合いも含め、今後の規制立法の焦点となる。

### Python 3.15 フィーチャーフリーズ完了・Rust for CPython PEP が正式起草フェーズへ — CPythonのビルドシステム変革が始まる

6月9日に **Python 3.15.0b2** がリリースされ、フィーチャーフリーズ（機能追加の停止）が完了した。次のプレリリースは6月23日予定の 3.15.0b3 で、正式リリースは2026年10月を予定している。3.15 の主要機能はすでに確定しており、**`t-string`（テンプレート文字列リテラル）の安定化**・**`locals()` の動作の仕様明確化**・**`asyncio` のパフォーマンス改善**などが含まれる。

一方、より長期的な視点で注目されるのが **Rust for CPython PEP** の動向だ。Guido van Rossum（Python の創始者）がドラフト承認を表明しており、PEP は 2026年6〜7月の正式起草フェーズに入った。Python 3.15（2026年10月）ではビルド時に Rust が未インストールの場合に警告を出す程度の「任意の統合」から始め、**Python 3.16（2027年）のビルドシステムに Rust が本格統合**される見通しだ。

```python
# Python 3.15 新機能: t-string (Template String Literal)
# f-string とは異なり、即座に文字列に評価されず
# テンプレートオブジェクトとして扱えるため、
# SQLインジェクション対策などでの安全な文字列生成に有用

from string.templatelib import Template

def safe_query(table: str, user_id: int) -> str:
    # t"..." はテンプレートオブジェクトを返す
    tmpl: Template = t"SELECT * FROM {table} WHERE id = {user_id}"
    # テンプレートの値をエスケープしてから文字列化
    return "".join(
        escape(part) if isinstance(part, str) else str(part)
        for part in tmpl.args
    )

# f-string の即時評価と違い、t-string はインジェクション対策のための
# 中間処理ステップを挟む余地を作るのが設計の肝
```

Python コミュニティでは「CPython のビルドシステムへの Rust 導入は、将来的な安全なシステムプログラミング部品の段階的な置き換えへの布石」として評価されており、C 拡張一辺倒だったエコシステムが転換期を迎えている。

### Shai-Hulud / Miasma / Hades サプライチェーン攻撃 — 開発者が取るべき即時対策

```bash
# === Shai-Hulud 系サプライチェーン攻撃 対策チェックリスト (2026-06-19) ===

# ---- [1] 依存パッケージのロックファイル検証 ----
# npm: package-lock.json / yarn.lock のインテグリティハッシュを確認
npm audit --audit-level=critical
# または特定パッケージの整合性チェック
npm ls --depth=0 | grep -E "(tanstack|openai|mistral|uipath|opensearch)"

# ---- [2] PyPI 環境の .pth ファイルバックドア検査 ----
# Miasma/Hades は site-packages に悪意ある .pth ファイルを埋め込む
# ドロッパーが Python 起動時に自動実行されるため、.pth の内容確認が必須
python -c "import site; print(site.getsitepackages())"
# 上記ディレクトリ内の .pth を全件確認
find $(python -c "import site; print(' '.join(site.getsitepackages()))") \
  -name "*.pth" -exec cat {} \; 2>/dev/null | grep -v "^/"

# ---- [3] GitHub Actions ワークフロー整合性確認 ----
# .github/workflows/ 内の uses: を第三者アクションへのピン留めにする
# 例: uses: actions/checkout@v4 → uses: actions/checkout@<SHA>
grep -r "uses:" .github/workflows/ | grep -v "@[a-f0-9]\{40\}"
# SHA ピン留めされていない外部アクションを警告として列挙

# ---- [4] クレデンシャルの即時ローテーション確認 ----
# Shai-Hulud は窃取したクレデンシャルで正規パッケージの新バージョンを公開する
# npm token, PyPI token, AWS/GCP/Azure 認証情報を定期ローテーション
# 今回の被害が報告されているスコープ:
# npm: TanStack, Red Hat Cloud Services 系パッケージ
# PyPI: MistralAI, UiPath, OpenSearch, バイオインフォマティクス系（scikit-bio 等）

# ---- [5] SLSA 証明だけでは不十分 — Sigstore によるアーティファクト署名を追加確認 ----
# Hades は SLSA BL3 証明済みパッケージを侵害することに成功しており、
# 証明の有無だけでなく署名元の信頼チェーン検証が必要
cosign verify-attestation --type slsaprovenance <package-artifact>

echo "=== Shai-Hulud 系攻撃 現状サマリー ==="
echo "6/1 以降の感染数: 累計 473 パッケージアーティファクト (npm + PyPI)"
echo "新変種: Miasma (npm 中心) / Hades (PyPI + MCP ターゲット)"
echo "追加標的: GitHub Actions ワークフロー / VS Code 拡張 / RubyGems"
echo "特記事項: AI コーディングアシスタントへのプロンプトインジェクション機能を確認"
```

Hades 変種が **MCP（Model Context Protocol）開発者向けパッケージ**を標的にしている点は特に警戒が必要だ。MCPサーバーは多くの場合ローカル権限で動作するため、感染した MCP パッケージは開発者のシステム全体へのアクセスを得る可能性がある。また **AI コーディングアシスタントへのプロンプトインジェクション**により、感染パッケージが開発者の気付かないうちにコードレビューをすり抜ける可能性も指摘されている。依存パッケージの定期的なハッシュ検証と、CI/CDにおける自動的な不審 `.pth` ファイル検査の組み込みが推奨される。
