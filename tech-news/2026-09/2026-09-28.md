## 注目技術と実践ベストプラクティス

### RAGの回答に「たどれる引用」を残す

#### 目的

検索拡張生成（RAG）の回答では、リンクを添えるだけでなく、どの文書のどの部分が各主張を支えているかを後から確認できる設計が重要です。回答と根拠の対応を保存しておくと、利用者が内容を確かめやすくなり、誤った検索結果や古い規程を参照した場合の調査にも使えます。Azure AI Searchの公式資料でも、文書名・ページ番号・チャンクIDなどの引用フィールドが推奨され、取得結果には参照ID、文書キー、根拠データなどを含められます。

#### 対象・前提

社内規程、製品マニュアル、FAQなど、回答の出所を示す必要があるRAGシステムが対象です。具体例はAzure AI Searchのagentic retrievalを前提とし、一般提供の`2026-04-01` APIと、引用URLなどを含む`2026-08-01-preview` APIの違いに注意します。プレビュー機能はサービスレベル契約の対象外で、本番利用が推奨されないと公式資料に明記されているため、採用時は安定版で取得できる参照情報を基準に設計します。

#### 手順

まず、検索インデックスに本文だけでなく、文書の版、タイトル、ページ番号、チャンクIDを保持します。次に、検索結果から回答を生成するとき、回答本文と参照IDを分離せず、同じ記録として保存します。以下は旅費規程への質問を想定した一般化した構成例であり、実在組織のデータや実行結果ではありません。

```json
{
  "question": "国内出張の宿泊費上限は？",
  "answer": "宿泊費の上限は職位と地域区分で異なります。[0]",
  "citations": [
    {
      "ref_id": "0",
      "doc_key": "travel-policy-v3",
      "title": "旅費規程 第3版",
      "page": 12,
      "chunk_id": "travel-12-2"
    }
  ]
}
```

引用を表示する際は、`ref_id`から取得応答の参照情報へ対応付け、タイトル、版、ページを利用者に示します。公式資料に基づく推奨は、検索可能かつ取得可能な本文フィールドを用意し、文書名・ページ・チャンクIDなどの引用フィールドを持たせることです。一般化した構成例では、回答の保存時にも文書の版を残し、後日インデックスが更新されても当時の根拠を識別できるようにしています。

#### 確認方法

少なくとも「根拠が一つの質問」「複数文書をまたぐ質問」「該当情報がない質問」「権限のない文書に関する質問」「旧版と新版で答えが異なる質問」を用意します。各回答について、引用先の本文が主張を実際に支えているか、ページとチャンクが再取得できるか、権限外や旧版の文書が混ざっていないかを人が確認します。根拠がない場合に推測で答えず、回答不能として処理できることも合格条件にします。この記事の構成例は未実行であり、API呼び出しや回答精度の測定は行っていません。

#### 注意点

引用が付いていても、その箇所が回答を支持しているとは限らないため、リンクの有無だけを品質指標にしないでください。Azure AI Searchの`citationUrl`はプレビュー機能で、応答に含まれない場合があり、参照時には検索サービスへの認証と適切な権限が必要です。文書レベルのアクセス制御を使う場合は、引用先を取得するときも同じ利用者権限を適用し、引用表示から機密情報が漏れないようにします。文書の差し替えや削除に備え、版や文書キーを監査ログに残す一方、保存期間と個人情報の扱いは組織の規程に合わせます。

- 導入前に、根拠なし・権限外・新旧版が競合する質問を含む確認セットで引用の妥当性を点検します。
