## 新技術・新リリース

### Python 3.14 t-strings（PEP 750）— 型安全な文字列テンプレートの実装例

t-strings は f-strings の `f""` プレフィックスを `t""` に変えるだけで使え、実行前にテンプレートオブジェクトとして評価される。SQL・HTML などのコンテキスト別エスケープを言語レベルで安全に扱えるのが最大の利点だ。

```python
# Python 3.14+ (PEP 750: t-strings)
from string.templatelib import Template

def safe_html(template: Template) -> str:
    """テンプレートの補間値を自動 HTML エスケープする"""
    from html import escape
    parts = []
    for item in template:
        if isinstance(item, str):
            parts.append(item)
        else:
            # Interpolation オブジェクト: .value に生の値が入る
            parts.append(escape(str(item.value)))
    return "".join(parts)

user_input = '<script>alert("xss")</script>'
title = "My Page"

# t-strings は Template オブジェクトを返す（即座に文字列化しない）
tmpl = t"<h1>{title}</h1><p>{user_input}</p>"
print(safe_html(tmpl))
# → <h1>My Page</h1><p>&lt;script&gt;alert(&quot;xss&quot;)&lt;/script&gt;</p>

# フリースレッド Python (PEP 779) — GIL なし並列処理
import threading

def cpu_bound_task(n: int) -> int:
    return sum(i * i for i in range(n))

# Python 3.14 の free-threaded モードでは真の並列実行が成立する
threads = [threading.Thread(target=cpu_bound_task, args=(10_000_000,)) for _ in range(4)]
for t in threads:
    t.start()
for t in threads:
    t.join()
```

### CVE-2026-31431 "Copy Fail" — Linux カーネル暗号サブシステムの特権昇格が野放し悪用中

```bash
# 1. カーネルバージョン確認（脆弱バージョン: 6.18.21 以下）
uname -r

# 2. AF_ALG (algif_aead) モジュールのロード状態確認
lsmod | grep algif_aead
# モジュールがロード済み且つカーネルが未パッチなら要対応

# 3. 影響を受けるディストリビューション（2017 年以降のほぼ全系統）
# Ubuntu 20.04/22.04/24.04, RHEL 8/9, Amazon Linux 2/2023,
# Debian 11/12, Alpine 3.x など

# 4. パッチ済みカーネルへの更新（Debian/Ubuntu 系）
sudo apt update && sudo apt dist-upgrade
# RHEL/CentOS 系
sudo dnf update kernel
# Amazon Linux 2023
sudo dnf update kernel

# 5. 即時緩和策（アップグレード不可の場合）
# algif_aead モジュールをブラックリスト化して無効化
echo "blacklist algif_aead" | sudo tee /etc/modprobe.d/disable-algif-aead.conf
sudo update-initramfs -u  # Debian/Ubuntu
# ※ この緩和策は AEAD 暗号を使用する一部アプリケーションに影響する場合がある
```

CVE-2026-31431（別名 "Copy Fail"）は Linux カーネルの **AF_ALG インターフェースの `algif_aead` モジュール**に存在するロジック欠陥で、インプレース操作中のメモリ処理が不正となる。CVSS 7.8（高）、攻撃ベクタはローカル・低権限・ユーザー操作不要という条件で、「4 バイトをページキャッシュに書き込むだけで root を取れる」と複数の PoC が実証している。2017 年以降にリリースされたほぼ全ての Linux ディストリビューション（Ubuntu・RHEL・Amazon Linux など）が対象で、数百万規模の Kubernetes クラスターにも影響する。CISA は 5 月 1 日に KEV 追加、連邦機関への対応期限を 5 月 15 日に設定した（民間は引き続き緊急対応が推奨）。修正済みカーネルバージョンは **6.18.22・6.19.12・7.0** 以降。

**出典**: [CISA says 'Copy Fail' flaw now exploited to root Linux systems — BleepingComputer](https://www.bleepingcomputer.com/news/security/cisa-says-copy-fail-flaw-now-exploited-to-root-linux-systems/) / [CVE-2026-31431: Copy Fail — Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/05/01/cve-2026-31431-copy-fail-vulnerability-enables-linux-root-privilege-escalation/) / [Nine-year-old Linux kernel flaw — Help Net Security](https://www.helpnetsecurity.com/2026/04/30/copyfail-linux-lpe-vulnerability-cve-2026-31431/)

### EU AI Act 透明性ルールが 8 月施行 — AI 利用企業は今すぐドキュメント整備を

EU AI Act の**透明性義務（第 50 条系）** が 2026 年 8 月に発効する。チャットボット・ディープフェイク・感情認識システムなどを公開・利用する事業者は、AI であることの開示・生成コンテンツへのウォーターマーク付与・人物なりすましの禁止が義務化される。高リスク AI（採用・信用スコアリング・医療等）には既にコンプライアンス準備期間が進行中だが、EU 内でサービスを提供する日本企業を含む域外事業者も対象となる点に注意が必要だ。UK ICO は採用 AI に関する報告書を発表し「AI 支援プロセスへの意味ある人間の関与」を雇用主に求めている。AI Act 違反は最大 **3,000 万ユーロまたは全世界売上高の 6%** の制裁金が科されるため、8 月までにリスク分類・ドキュメント・説明可能性の整備を完了させることが急務だ。
