### 1. MetaがMuse Glimmer（30Bパラメータ）をApache 2.0でOSS公開 — 24GB VRAMの家庭用GPUで動くローカルAIエージェント

Meta Superintelligence Labs（MSL）は2026年8月10日、**Muse Glimmer**をApache 2.0ライセンスのもとHugging Faceで公開した。30Bパラメータの高密度マルチモーダルモデルで、4ビット量子化を適用することでメモリ使用量を55 GBから18〜20 GBへ圧縮し、コンシューマー向けの24 GB VRAMを持つ単一GPUで動作する。性能面ではSWE-Bench Proスコアが51.2を記録し、Gemma4-31B（36.9）およびQwen3.6-27B（50.2）を上回った。マルチターンのリクエスト処理、精確なツール呼び出し、長期にわたる多ステップ計画の実行のほか、ツール呼び出し失敗からの自動リカバリや専用パーセプションエンコーダによる画像理解も可能だ。フラッグシップモデルMuse Sparkからロジット蒸留で訓練されており、MetaはこのオープンウェイトリリースをOpenAI・Anthropicなど独占型AIへの対抗軸として位置づけている。AMDのRyzen AI Max搭載PC・Radeon GPUでの動作も正式にサポートされ、ローカルで完結するプライバシー保護型AIエージェントの実用化を大きく前進させる一手となった。

### 2. EU AI法（AI Act）透明性規則が8月2日より施行 — 「AIです」の明示が義務に、違反は最大€15M

欧州委員会のAIオフィスは2026年8月2日、**EU AI法（AI Act）**における透明性規則の施行を正式に開始した。チャットボットなどの対話型AIはユーザーに対して「AI と対話していること」を明示する義務を負い、ディープフェイクにはラベル付けが、AI生成コンテンツには機械可読マークの埋め込みが求められる。感情認識・生体認証カテゴリー分類・公共の関心事項に関するAI生成テキストについても透明性規制の対象となる。ガイドラインは7月20日に欧州委員会が採択しており、180以上の組織がAI生成コンテンツの透明性に関する実践規範（Code of Practice）に署名している。違反した場合の罰則は最大€1,500万、または世界年間売上高の3%のいずれか高い方で、国家市場監視当局・欧州AIオフィス・欧州データ保護監督官が監督を担当する。実装した透明性の仕組みはチャットボット・UX・コンテンツパイプライン各レイヤーに跨るため、企業のコンプライアンス対応はシステムアーキテクチャ全体の見直しを要求している。

### 3. SCTPhantom（CVE-2026-64564）— 18年間潜伏したLinuxカーネルSCTP脆弱性が公開、ローカルrootおよびコンテナ脱出が可能

2026年8月4日、Linuxカーネルチームは**CVE-2026-64564**（通称: SCTPhantom）を正式公開した。Stream Control Transmission Protocol（SCTP）の動的アドレス再設定機能に存在するuse-after-free脆弱性で、起源は2007年12月にLinux 2.6.25へ組み込まれたコードにあり、約18年間誰にも発見されなかった。ローカルの攻撃者が本脆弱性を悪用すると、特権昇格によるroot権限取得と、特定の設定下ではコンテナからホストへの脱出が可能となる。根本原因はアドレス検証のロジックにあり、DEL-IP削除操作でカーネルがパケットの送信元アドレスで検証を行う一方、実際のネットワーク経路（トランスポート）選択には別のキャッシュポインタが用いられるという不一致だ。悪用にはローカルアクセスとSCTPの到達可能性が必要であるため、リモートからの直接悪用は困難だが、マルチテナント環境やコンテナオーケストレーション環境では脅威レベルが高い。修正済みバージョンは6.6.148・6.12.101・6.18.42・7.1.6で、プライベート開示は7月12日から始まっていた。

### Meta Muse Glimmer の4ビット量子化アーキテクチャ：単一コンシューマーGPU対応の仕組み

Muse Glimmerが24 GB VRAMに収まる理由は、モデルウェイトを4ビットに量子化しつつKVキャッシュ・パーセプションエンコーダ・スペキュレーティブデコードドラフターを全て同一GPUメモリ上で管理する設計にある。

```text
=== Muse Glimmer メモリレイアウト（24GB VRAM 構成例）===

[モデルウェイト] 30B × 4-bit量子化
  ├─ 元サイズ: ~55 GB (bfloat16)
  └─ 量子化後: 18〜20 GB (4-bit + スケール係数)

[推論コンポーネント] 合計 ~4 GB
  ├─ KVキャッシュ (コンテキスト長依存)
  ├─ パーセプションエンコーダ (画像/マルチモーダル)
  └─ スペキュレーティブデコードドラフター (高速化用小型モデル)

[合計目安] 22〜24 GB → 24GB または 32GB VRAM GPU で動作

[対応ハードウェア例]
  NVIDIA: RTX 4090 (24GB), RTX 5080 (16GB+*)
  AMD:    Radeon RX 9070 XT, Ryzen AI Max搭載PC
  Apple:  M4 Max (Mac Studio/MacBook Pro 搭載 36GB/48GB統合メモリ)

[ライセンス] Apache 2.0 — 商用利用・改変・再配布が自由
[配布先]    Hugging Face (meta-superintelligence-labs/Muse-Glimmer-30B)

[SWE-Bench Pro スコア比較]
  Muse Glimmer 30B : 51.2
  Gemma4-31B       : 36.9
  Qwen3.6-27B      : 50.2
```

フラッグシップモデルからロジット蒸留することで「大型モデルの出力分布」を小型モデルが再現しており、単純な知識蒸留よりもエージェントタスクに特化した能力転移が実現されている。ツール呼び出し失敗時の自動リカバリ機能は、定型的なコーディングエージェントではなくロバストな自律エージェントとして設計されていることを示しており、クラウドAPIへの依存を排除したオンプレミス・エアギャップ環境でのAI活用という新たなユースケースを開く。

**出典**: [Muse Glimmer Deep Dive — Essa Mamdani](https://essamamdani.com/blog/muse-glimmer-30b-local-agent-model-deep-dive-2026) / [Run Meta Muse Glimmer on AMD — AMD Developer Blog](https://www.amd.com/en/blogs/2026/run-meta-muse-glimmer-30b-on-amd-ryzen-ai-max-and-radeon-gpus.html)

## セキュリティ

### SCTPhantom 緊急対応ガイドと Coldcard ファームウェア脆弱性による $70M Bitcoin 流出

SCTPhantomとColdcard問題の両者に共通するのは「既存コードへの長期潜伏」と「発覚後の急速な被害拡大」だ。

```text
=== 2026年8月10日 重要セキュリティ対応チェックリスト ===

[CVE-2026-64564 — SCTPhantom（Linuxカーネル SCTP UAF）]
  発見:         2007年12月のLinux 2.6.25コードが起源 → 約18年潜伏
  影響:         ローカル特権昇格（→ root）+ コンテナ脱出
  悪用条件:     ローカルアクセス + SCTPプロトコルが到達可能な環境
  修正バージョン: 6.6.148 / 6.12.101 / 6.18.42 / 7.1.6
  確認コマンド:
    uname -r                    # 現在のカーネルバージョン確認
    grep SCTP /boot/config-$(uname -r)  # SCTP有効か確認
    # CONFIG_IP_SCTP=m や =y の場合は要アップデート
  緩和策（カーネル更新が困難な場合）:
    modprobe -r sctp            # SCTPモジュールをアンロード（要再起動後無効化）
    echo 'install sctp /bin/true' >> /etc/modprobe.d/disable-sctp.conf
  高リスク環境: マルチテナントKubernetes、コンテナホスト、共有Linuxサーバー

[Coldcard ファームウェア脆弱性 — $70M Bitcoin 流出]
  概要:         2021年3月のファームウェア更新でHW-RNGの代わりにソフトウェア
                PRNGがシード生成に使われるバグが混入（2021年〜現在まで潜伏）
  被害:         1,196アドレスが41分で drain、被害総額 $70.2M+（現在も上昇中）
  影響ユーザー: 2021年3月以降のColdcardファームウェアでシードを生成し、
                さいころエントロピー・パスフレーズ・マルチシグを使用していない場合
  推奨対応:     被害を受けた可能性があるウォレットのBTCを新規生成ウォレットへ
                直ちに移動すること（公式手順を参照）

[その他の週内パッチ（優先度: 高）]
  HashiCorp Terraform MCP Server : CVE発表、最新版へのアップデート推奨
  Veeam Service Provider Console : 複数の脆弱性（1件はCVSS 10.0）、即時パッチ適用
  Django セキュリティリリース     : OSS フレームワーク利用者は pip upgrade django 実行
```

Coldcardのケースは「ハードウェアウォレット＝安全」という前提が崩れることを示している。ソフトウェアPRNGの出力は攻撃者がオフラインで候補シードを生成しブロックチェーン上で照合できるため、物理的な盗難がなくても暗号資産が消える。SCTPhantomは悪用にローカルアクセスが必要であるため野生での大規模攻撃のリスクは限定的だが、マルチテナント環境ではコンテナ内の攻撃者がホストrootを奪える点に注意が必要だ。
