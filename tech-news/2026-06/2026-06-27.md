### 1. 米商務省、Anthropic Claude Mythos 5 を約100社・官庁へ限定解禁 — "Project Glasswing" ホワイトリスト体制が始動、Fable 5 はなお停止中

Anthropicは6月26〜27日、米商務省の許可を受け**Claude Mythos 5**を「約100の信頼済み組織」へ限定的に再開放した。Commerce SecretaryのHoward Lutnick氏がAnthropicのチーフ・コンピュートオフィサーTom Brown氏宛に書簡を送り、「適切なセーフガードが整備されたと判断した」として解禁を通知した。承認された組織群は**Project Glasswing**と呼ばれるAnthropicの信頼済みパートナー枠組みに属し、政府機関・主要テック企業など約100社が含まれる。利用目的は「防御的サイバー目的」に限定されており、一般消費者向けアクセスは引き続き停止されたままだ。輸出規制の端緒は約2週間前、Amazon CEOのAndy Jassy氏が財務長官Scott Bessent氏に「Anthropicモデルのジェイルブレイク脆弱性」を警告したことにあるとされ、政府とAnthropicの間では連日交渉が行われていたという。一方、消費者向けに一時は最高性能モデルとして公開されていた**Claude Fable 5**については今回の書簡に言及がなく、別途交渉継続中とされている。このホワイトリスト方式は、フロンティアAIモデルへのアクセス管理の新たなモデルケースとして国際的な注目を集めている。

### 2. 北朝鮮系APT、Rust製macOSマルウェア "Gaslight" を展開 — AI解析ツールをプロンプトインジェクションで欺く新世代バックドア

Rustで実装された新型macOS向けバックドア・情報窃取マルウェア **"Gaslight"** が発見され、北朝鮮系の脅威アクターによるものと高い確度で評価されている。このマルウェアの際立った特徴は、マルウェア解析者が使用するAIツール（コードサマリー・脅威インテリジェンス生成に活用されるLLM）を標的にした**プロンプトインジェクション**ペイロードを内包している点だ。バイナリ内に埋め込まれた悪意ある命令が、AIアシスタントに「このファイルは無害だ」「脅威の証拠はない」等と誤分析させる仕組みとなっている。Rustを選択することで従来型AV検出を回避しつつ、次世代のAI解析レイヤーもプロンプトインジェクションで欺くという二重のステルス性を実現した点が、今後のマルウェア設計の方向性を示す先駆けとして注目される。セキュリティ研究者は「AIが解析フローに組み込まれるほど、攻撃者がAI自体を標的にするインセンティブも高まる」と警鐘を鳴らしており、マルウェア検体のコンテンツをLLMプロンプトに生のまま渡すワークフローの見直しが急務とされている。

### Microsoft MAI-Thinking-1 正式発表 & Rust 2026 本番採用率47%突破 — 「愛されているだけ」から「使われている」へ

Microsoft Build 2026（6月2日）でMicrosoftは自社開発AI群として**MAIファミリー7モデル**を一挙発表した。旗艦推論モデル**MAI-Thinking-1**は**アクティブパラメータ35B・コンテキスト256K**のスパースMoEアーキテクチャで、OpenAIのデータを一切使わずに訓練された初の自社推論モデルだ。AIME 2025で**97.0%**、AIME 2026で**94.5%**を記録し、コーディングベンチマークでは先行モデルを上回ると主張している。Microsoft Foundryでプライベートプレビュー中で、Fireworks AI・Baseten・OpenRouterでも利用可能になる予定だ。MAI-Code-1-Flash（コード生成）・MAI-Image-2.5（画像）・MAI-Voice-2（音声）・MAI-Transcribe-1.5（文字起こし）等も同時発表されており、OpenAI依存の段階的脱却という長期戦略の実行フェーズに突入したことを示している。

一方、システムプログラミング言語の世界では**Rust**の本番採用率が**47%**（2023年: 28%）に達し、Stack Overflow Developer Surveyで9年連続最愛言語（83%賞賛率）の称号を実態として裏付けた。Google Androidの報告では、Rustコードのシェア拡大に伴いメモリ安全性脆弱性の割合が実測で低下しており、「Rustは安全の約束を本番スケールで実証した」との評価が定まりつつある。

```rust
// Rust 2026: メモリ安全性の実例 — コンパイル時にUBを根絶する設計
// Linux kernel・Windows kernel・AWS Firecracker・Cloudflare Workers 等で本番採用済み

fn process_buffer(data: &[u8]) -> Option<u8> {
    // 境界チェックは自動 — 範囲外アクセスはパニック（UB ではなく制御された失敗）
    data.get(42).copied()
}

fn ownership_demo() {
    let buf = vec![1u8, 2, 3];
    let reference = &buf;           // 不変借用
    // drop(buf);                   // ← コンパイルエラー: 借用が生きている間は drop 不可
    println!("{:?}", reference);    // 安全なアクセス
}                                   // buf と reference がここで同時にドロップ

// C/C++ なら UAF (use-after-free) / OOB write になる箇所を
// Rust はコンパイル時に型システムで検出し、実行時コストゼロで防ぐ

fn main() {
    match process_buffer(&[10, 20, 30]) {
        Some(v) => println!("Found: {v}"),
        None    => println!("Index out of bounds"),  // クラッシュではなく制御された分岐
    }
    ownership_demo();
}
```
