### 2. CVE-2026-61511: vBulletinにPre-Auth RCEのPoC公開 — eval()直撃・認証不要で世界中のフォーラムが即日標的に

7月27日、セキュリティ研究者がSSD Secure Disclosureを通じて**CVE-2026-61511**のPoCエクスプロイトコードを公開した。この脆弱性はvBulletin 6.2.1以前に存在するプリオース（認証不要）リモートコード実行（RCE）で、`/includes/vb5/template/runtime.php`内の`vB5_Template_Runtime::runMaths()`メソッドがPHPの`eval()`関数に渡す入力を適切にサニタイズしていないことに起因する。攻撃者はテンプレートタグ`{vb:math}`の処理パスを通じて数値とXOR演算のみでPHPコード（`system()`等）をエンコードし、`ajax/render/pagenav`へのPOSTリクエストでWebサーバー権限のシェルを取得できる。**アカウント・管理権限・他ユーザーの操作一切不要**という最も危険な攻撃条件だ。vBulletinは6月末にパッチを発行し7月1日に修正版6.2.2をリリース済みだが、PoCが公開されたことで未更新のフォーラムサーバーへの自動スキャン・攻撃が急増する見込みだ。世界には数万のvBulletinフォーラムが存在し、旧来の掲示板文化を支えるサーバーが多く未パッチのリスクが高い。管理者はバージョン6.2.2への即時更新と、`runMaths()`コードパスへの外部アクセスログの確認を最優先すべき状況だ。

AI規制・標準化を巡る国際的な駆け引きが最終局面を迎えている。7月17日の上海世界AI会議（WAIC）で、中国の習近平国家主席は**「AIは世界協力の交響曲であるべき」**と演説し、**パキスタンを含む29か国を創設メンバーとする「世界人工知能協力機構（WAICO: World Artificial Intelligence Cooperation Organisation）」の設立**を宣言した。WAICOは中国主導のAI分野初の政府間国際機関で、AI倫理・標準・ガバナンス規範の形成において西側主導の動きに対抗する軸となる。7月6〜7日にジュネーブで開催されたUN主催「グローバルAIガバナンス対話」では、EU・米・中の競合する規制モデルが一堂に会した。EUは権利・リスクベースの規制モデル、米国は革新保護を優先する自主規範、中国はデータ主権を守りながら「包括的協力」を訴えるという三極の立場が鮮明になった。このUN対話から3週間後の**8月2日にEU AI Act（EU AI法）が完全施行**される（残り6日）。高リスクAIへの人間監督義務・生成AIへの透明性開示・違反時最大€1,500万の制裁が実効化するタイミングで、Kimi K3のような中国オープンウェイトモデルが欧州利用者を含む世界規模で普及し始めるという複雑な地政学状況が重なる。誰がAI標準と規制フレームを決めるかという問いは、技術の問題を超えて外交・安全保障の中核テーマになった。

### JDK 28 — JEP 401「値オブジェクト（プレビュー）」とJEP 539「JVM厳格フィールド初期化（プレビュー）」がProposed to Targetに昇格

Javaの次期長期サポート候補**JDK 28**の開発で、2つの重要JEPが「Proposed to Target」に昇格した。**JEP 401（Value Objects - Preview）**はProject Valhallaの中核機能で、オブジェクトのアイデンティティを持たない「値型」クラスを定義できるようにするもの。ヒープアロケーションを避けてスタックやレジスタに展開できるため、数値計算・ゲーム・金融システムなどアロケーション負荷が高い領域でパフォーマンスが大幅に向上する。**JEP 539（Strict Field Initialization in the JVM - Preview）**はJVMレベルでフィールドの「コンストラクタ前に読まれていない」ことを保証することで、デフォルト値（`null` / `0`）が観測されないようにするもの。サブクラスのコンストラクタチェーンで`null`が漏れる古典的バグを型システム上で封じる効果がある。また今四半期からOracle（JDK 25.0.4 / 21.0.12 / 17.0.20 / 11.0.32 / 8u501をリリース済み）は**Critical Patch Updateの配信頻度を四半期から月次に引き上げ**始めており、高優先度の脆弱性を素早くパッチ提供する体制に移行した。これはAI支援コード解析が脆弱性検出を加速したことへの対応でもある。

```java
// JEP 401: Value Objects (Preview) — JDK 28 プレビュー機能のイメージ
// ※ 現時点では Preview のためコンパイルに --enable-preview が必要

// value class は == が参照ではなく内容比較になる (将来的な意味論)
value class Point {
    int x;
    int y;

    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    // アイデンティティを持たないため synchronized は使用不可
    Point translate(int dx, int dy) {
        return new Point(x + dx, y + dy);
    }
}

public class ValueObjectDemo {
    public static void main(String[] args) {
        var p1 = new Point(1, 2);
        var p2 = new Point(1, 2);
        // 値クラス同士の == は内容比較 → true (参照ではなく値の同一性)
        System.out.println(p1 == p2); // → true (従来のクラスは false)

        // スタック展開・インライン化でヒープアロケーションを回避
        var p3 = p1.translate(3, 4);
        System.out.println(p3); // → Point[x=4, y=6]
    }
}
```

```java
// JEP 539: Strict Field Initialization — null漏れを型レベルで封じる
// コンストラクタチェーンでサブクラスが親のオーバーライドメソッドを呼ぶと
// 従来は親フィールドが null のまま読まれるバグが発生していた

class Parent {
    final String name; // strict: コンストラクタ完了前に読み取り不可
    Parent() {
        init(); // ← 従来はここでサブクラスが name を読むと null だった
        this.name = "Parent";
    }
    void init() {} // オーバーライド可能メソッド
}

class Child extends Parent {
    @Override
    void init() {
        // JEP 539 施行後: name へのアクセスはここでコンパイルエラーまたは実行時例外
        // System.out.println(name); // → NG: 初期化前アクセス検出
    }
}
```
