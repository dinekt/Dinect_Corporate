## 注目技術と実践ベストプラクティス

### 依存グラフで長大なコードベースのコンテキストを絞り込む

#### 目的

コードのimport関係をグラフ化し、変更対象から一定距離にある実装だけをAIへ渡すことで、長大なコンテキストの容量を関連性の高い情報へ使う。Kimiは100万トークンで大規模コードベース全体を一度に読み込めるとしているが、容量内に収まることと、変更に必要な情報だけが選ばれていることは別である。依存元と依存先を機械的に抽出すれば、無関係なコードによる注意の分散と送信量を抑えつつ、影響を受ける呼び出し側やテストを候補へ加えられる。

#### 対象・前提

対象は、単一ファイルでは判断できない変更をAIコーディング支援へ渡す中規模以上のリポジトリである。以下の一般化した構成例はPython 3.12の標準ライブラリ`ast`だけを使い、静的な絶対importを持つ4ファイルを対象とする。実環境では、利用言語の構文解析器、ビルドシステム、テスト対応表、所有者情報を組み合わせる必要がある。動的import、リフレクション、生成コード、設定ファイル経由の結合が多いシステムには、この方法だけでは不十分である。

#### 手順

最初に、各ソースを構文解析して「ファイルからファイルへのimport」を辺として保存し、逆向きの辺も作る。次に、変更ファイルから依存先と依存元の両方向を指定ホップ数だけ探索する。得られた集合へ対応テスト、公開API仕様、所有者ルールを追加し、ファイル名と選定理由の一覧を先にAIへ渡す。AIが追加情報を求めた場合だけ範囲を広げ、提案された変更は全テストではなく、まず選定した近傍のテストから実行する。

以下は再現可能な最小例である。`common/audit.py`を変更すると、直接参照する`billing/service.py`と、その呼び出し元`app.py`が2ホップ以内に選ばれ、関係のない`marketing/campaign.py`は除外される。

```python
import ast

sources = {
    "app.py": "from billing.service import charge\ncharge()\n",
    "billing/service.py": "from common.audit import log\ndef charge(): log('paid')\n",
    "common/audit.py": "def log(message): print(message)\n",
    "marketing/campaign.py": "def launch(): return 'ok'\n",
}

module_to_path = {
    path.removesuffix(".py").replace("/", "."): path
    for path in sources
}
forward = {path: set() for path in sources}

for path, source in sources.items():
    tree = ast.parse(source, filename=path)
    for node in ast.walk(tree):
        if isinstance(node, ast.ImportFrom) and node.module in module_to_path:
            forward[path].add(module_to_path[node.module])
        elif isinstance(node, ast.Import):
            for alias in node.names:
                if alias.name in module_to_path:
                    forward[path].add(module_to_path[alias.name])

reverse = {path: set() for path in sources}
for caller, dependencies in forward.items():
    for dependency in dependencies:
        reverse[dependency].add(caller)

def neighborhood(changed, max_hops=2):
    selected = {changed}
    frontier = {changed}
    for _ in range(max_hops):
        frontier = {
            neighbor
            for path in frontier
            for neighbor in forward[path] | reverse[path]
        } - selected
        selected |= frontier
    return sorted(selected)

print(neighborhood("common/audit.py"))
```

入力は4ファイルと変更対象`common/audit.py`で、期待する出力は`['app.py', 'billing/service.py', 'common/audit.py']`である。実際のリポジトリでは、選択集合、除外理由、推定トークン数を記録し、上限を超えた場合はホップ数ではなく、変更シンボルからの到達性やテストの関連度で優先順位を付ける。

#### 確認方法

上のコードは標準Python 3.12で実行し、記載した出力になることを確認する。Kimi K3.1 Proや実在する業務リポジトリでは未実行であり、100万トークン時の品質や費用を検証した結果ではない。本番では、過去の変更を入力にして「実際に修正されたファイルと失敗したテスト」が選択集合へ含まれる再現率を測り、同時に送信トークン数、応答時間、不要ファイル率を比較する。近傍だけで失敗する変更は、動的依存や仕様・設定の辺を追加するための評価ケースとして残す。

#### 注意点

静的importグラフは実行時に選ばれるプラグイン、文字列からのimport、外部サービス契約、データベーススキーマを捉えないため、CIの実行履歴や所有者による確認で補完する。狭く選びすぎると重要な前提を落とし、広げすぎるとトークン費用と待ち時間が増え、無関係な指示や古いコードへ引きずられる。ソース内のコメントや文書は信頼できない入力として扱い、AIに渡した内容から秘密情報を除き、ツール権限は読み取りから始める。AST解析自体も巨大または悪意ある入力で資源を消費し得るため、対象サイズと処理時間を制限し、解析失敗時は自動変更を止める。

**出典**: [Kimi — Kimi Code overview](https://www.kimi.com/code/docs/en/)、[Python Software Foundation — ast — Abstract Syntax Trees](https://docs.python.org/3.12/library/ast.html)

## まとめ

- 大規模コード変更では、変更ファイルから依存元・依存先をたどり、選定理由とともにAIへ渡す。
- 動的依存がある場合は静的グラフだけに頼らず、テスト履歴、仕様、設定、所有者情報で補完する。
- 長大なコンテキストは全投入ではなく、漏れの再現率と送信量を比較しながら段階的に広げる。
